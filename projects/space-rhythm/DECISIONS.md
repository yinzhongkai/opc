# 项目决定

## D-008：Qt 精确版本基线
- 状态：confirmed
- 提出者：build-engineer-windows-qt-01
- 问题与候选方案：在 D-005 已确认从官方源码构建 Qt、D-006 已确认 MSVC 2022 Build Tools x64、D-007 已确认 LGPLv3 路径后，仍需把 Qt 版本精确到 patch。候选为立即锁定当前已发布的 Qt 6.11.2、等待计划中的 6.11.3，或选择后续 LTS 维护主要面向商业许可证客户的 Qt 6.8 LTS。
- 确认人：PROJECT 默认最终确认人，即提出建项请求的本会话用户。
- 结果：第一阶段 Qt SDK 精确锁定为 Qt 6.11.2，使用官方 `qt-everywhere-src-6.11.2.tar.xz` 源码归档；已登记的官方文件大小为 1,019,661,552 字节，SHA-256 为 `6dcfbca271d76a6502741a2c0dc6fc98ef7dd0b7b4cfd0abcebb285a86a26f33`，实际获取后必须重新校验。Qt、应用和同进程原生依赖按 D-006 使用 MSVC 2022 x64，Qt 按 D-007 构建为 shared/dynamic。版本不得自动跟随“最新”；6.11.3 或其他后续版本正式发布后，只能通过新决定、干净重建和回归验证受控替代。
- 确认来源与日期：build-engineer-windows-qt-01 在 A-008 0.2 中提出 Qt 6.11.2 建议后，本会话用户于 2026-09-08 明确回复“确认 Qt 6.11.2”。
- 适用范围与影响：影响 T-012/T-013、Qt 源码与哈希清单、SDK 安装前缀、CMake/CI 工具链元组、缓存键、部署清单和后续升级策略；本决定本身不授权下载安装、修改系统环境、签名或生产发布。
- 替代关系：无；补充 D-005 的源码供应方式、D-006 的编译器路线和 D-007 的许可证路径。
- 记录人及更新日期：build-engineer-windows-qt-01，2026-09-08。

## D-007：Qt 许可证路径
- 状态：confirmed
- 提出者：PROJECT 默认最终确认人，即提出建项请求的本会话用户。
- 问题与候选方案：Qt 源码构建、模块选择、链接方式和发布材料需要在商业许可与开源许可路径之间确定基线；开源路径还必须区分 LGPLv3 可用模块与仅 GPL 提供的模块，并保留最终用户替换 Qt 动态库的能力。
- 确认人：提出本次许可证要求的本会话用户。
- 结果：本项目采用 Qt LGPLv3 路径，Qt SDK 和应用默认使用 shared/dynamic linking；打包时保留 Qt 动态库可替换性，并维护许可证文本、版权声明、Qt 源码取得方式、构建/替换说明、模块与二进制清单。默认不得引入 Qt 的 GPL-only 模块，不得把 Qt 改为静态链接；如后续确有需要，必须先重新进行许可证影响审查并形成新决定。该记录是工程合规基线，不替代正式法律意见或发布前许可证复核。
- 确认来源与日期：本会话用户于 2026-09-08 明确表示“Qt使用许可证LGPLv3”；build-engineer-windows-qt-01 据此记录。
- 适用范围与影响：影响 T-012/T-013、Qt 模块白名单、链接方式、依赖与 SBOM 清单、部署暂存和发布材料；本决定自身不确认 Qt 的确切 patch 版本，该版本已由 D-008 补充确认为 Qt 6.11.2。
- 替代关系：无；补充 D-002/D-005 的 Qt 技术与供应方式基线。
- 记录人及更新日期：build-engineer-windows-qt-01，2026-09-08。

## D-006：Windows 原生编译器工具链
- 状态：confirmed
- 提出者：architect-01
- 问题与候选方案：D-005 要求从源码构建 Qt，但 Qt 源码不包含 C++ 编译器。Qt 6.11 官方支持 Windows x86_64 使用 MSVC 2022 或 MinGW-w64 13.1；当前环境没有已确认可用的 MSVC 工具链，需要决定是安装 MSVC 2022 Build Tools，还是把 Qt、应用和全部原生依赖统一切换为 MinGW-w64 ABI。
- 确认人：PROJECT 默认最终确认人，即提出建项请求的本会话用户。
- 结果：第一阶段采用 MSVC 2022 Build Tools x64 路线。Qt、应用、FFmpeg、OpenCV 及其他进入同一进程的 C/C++ 依赖统一使用 MSVC v143 兼容的 x64 工具链和一致的 MSVC CRT 模型；禁止混用 MSVC 与 MinGW C++ ABI。Windows SDK、MSVC 工具集的完整版本在安装和验证后写入可复现工具链元组，并满足所选 Qt 版本的最低要求。
- 确认来源与日期：本会话用户于 2026-09-08 明确表示“编译器使用 MSVC 2022 Build Tools”；build-engineer-windows-qt-01 据此将 architect-01 于 2026-09-07 提出的候选决定更新为 confirmed。
- 适用范围与影响：影响 Qt 源码构建、vcpkg triplet、第三方二进制可复用性、调试符号、CI 镜像和应用部署；关闭 T-012/T-013 的编译器路线门禁，但不代表已经授权或完成工具安装。本决定自身不确认 Qt 确切版本或 D-003 其余构建组合，其中 Qt 版本已由 D-008 补充确认。
- 替代关系：无；细化 D-003 的 Windows 工具链待确认项。
- 记录人及更新日期：architect-01，2026-09-07；build-engineer-windows-qt-01，2026-09-08 更新确认结果。

## D-005：Windows x64 与 Qt 源码构建基线
- 状态：confirmed
- 提出者：PROJECT 默认最终确认人，即提出建项请求的本会话用户。
- 问题与候选方案：D-004 已限定 Windows，但 CPU 架构和 Qt 获取方式仍未确定。候选为 x64 或 ARM64，以及使用 Qt 预编译包或固定源码自行构建。
- 确认人：提出本次架构与构建要求的本会话用户。
- 结果：第一阶段只生成 Windows x64（`x86_64`）产物，不生成 x86、ARM64 或 ARM64EC 版本；Qt 不使用预编译二进制包，必须从固定版本的官方源码自行配置、编译和安装。Qt 源码、构建目录与安装目录分离，构建配置、工具版本、源码版本/哈希和安装清单必须可追溯。Qt、应用及同进程原生依赖必须采用兼容的编译器和运行时 ABI。
- 确认来源与日期：本会话用户于 2026-09-07 明确表示“Qt 匹配的 MSVC 工具链也没有，需要从零开始编译qt源码，架构就x64”。architect-01 依据其中明确的源码构建和 x64 要求记录；编译器选择随后由 D-006 确认。
- 适用范围与影响：影响 A-004、A-005、Qt 获取与构建流水线、第三方依赖、CI 缓存、调试和部署；本决定自身不确认 Qt 确切版本、许可证路径、Windows 最低版本或最终编译器，其中许可证和编译器已分别由 D-007、D-006 补充确认。

## D-002：界面框架与算法实现语言基线
- 状态：confirmed
- 提出者：PROJECT 默认最终确认人，即提出建项请求的本会话用户。
- 问题与候选方案：A-004 0.1 将 Qt/C++ 作为候选实现栈，但尚未确定界面框架和算法实现语言。用户先明确“界面使用 Qt，算法使用 C/C++”，随后在了解 Qt Widgets 与 Qt Quick/QML 的差异后明确采用 Qt Quick/QML。具体 Qt/C/C++ 版本、编译器和许可证路径仍需后续技术设计和发布约束确认。
- 确认人：提出上述技术方向的本会话用户。

- 替代关系：无。
- 记录人及更新日期：architect-01，2026-09-07。

## D-001：第一阶段目标用户与主验证路径
- 状态：confirmed
- 提出者：product-manager-01
- 问题与候选方案：需要确认第一阶段首先服务谁，以及优先验证哪条价值路径。候选主路径为：A. 音频输入后自动生成可导出视觉视频；B. 视频输入后自动生成卡点节奏音轨；C. 用统一节奏事件时间线做轻量双向闭环，两侧都只覆盖最小能力。结合 A-003 0.1，产品经理将建议细化为“B 为主、A 为辅”：以视频到可编辑节奏音轨作为差异化主流程，同时用同一事件时间线提供少量音频驱动视觉模板；不在第一阶段生成完整歌曲，也不复刻参考软件的专业合成器、效果器和集成矩阵。
- 确认人：PROJECT 默认最终确认人，即提出建项请求的本会话用户。
- 结果：第一阶段聚焦需要快速制作卡点内容的桌面音视频创作者，采用独立桌面应用；以“视频到可编辑节奏音轨”为差异化主流程，以“音频到少量视觉模板”为配套流程，共用节奏事件时间线。第一阶段不生成完整歌曲，不纳入 VST3、Blender/GPLA、专业合成器、复杂效果器或现场演出集成。
- 确认来源与日期：本会话用户于 2026-09-07 在收到上述明确方案后回复“OK，把你生成的内容提交一把”，确认采用该方向并要求提交记录。
- 适用范围与影响：影响 T-002、A-002、后续技术可行性评估、原型范围与验收样例；确认前不视为项目最终范围。
- 替代关系：无。
- 记录人及更新日期：product-manager-01，2026-09-07；同日依据用户明确回复将状态更新为 confirmed。
