## 目标与约束

- 目标：学习 Zephyr RTOS；用真实图书项目验证并持续完善 OPC 写书框架；将学习、实验和修订过程整理为可复核的书籍内容。
- 长期主题边界：以 Zephyr RTOS 为稳定主线，允许后续图书或内容更换、增加芯片与开发板；具体扩展范围需另行确认。
- 首本书：暂定《nRF54L15 与 Zephyr RTOS 实战：从芯片外设到低功耗蓝牙产品》，主要硬件平台为用户已购的 Nordic 官方 nRF54L15 DK。
- 本轮范围：仅创建项目共享文件，登记图书工作方式和成果落点；不创建成员、任务、真实成果、书籍目录或章节。
- 本轮非目标：不生成正文，不声称完成学习或实验，不确定出版、发布时间、篇幅和商业目标。
- 计划交付：逐步形成可学习、可复现、可审校的技术书稿，以及与其分离的实验依据和学习反馈；具体交付格式与验收要求待确认。
- 时间、资源与其他约束：暂无期限或预算；开发主机、板卡修订号、Zephyr/NCS、SDK 和工具链版本待后续实验规划时确认。

未知项保持待确认，已确认的范围变更链接 [DECISIONS.md](DECISIONS.md) 中的决定，不从模板预设业务任务。

## 图书工作方式

- 本项目采用根 [可选图书成果模板](../../templates/book/README.md) 的工作方式，书稿计划放在 `artifacts/book/`；当前尚无有效成员受理成果任务，因此不复制空目录稿、章节或发布物。
- 计划遵循“规划 → 草稿 → 审校 → 试读/学习与实验反馈 → 修订复核 → 成书”的迭代过程；各阶段只有在实际受理后才登记任务和成果。
- 书稿、技术验证证据与用户学习反馈分别记录，不能用预期现象替代实测结果，也不能把 AI 生成内容写成用户亲历。
- 用户逐章通读（[D-008](DECISIONS.md)）：每章完成约定的必要审校与修订、形成明确版本的完整可读稿后，交用户完整读一遍；用户可直接在会话中反馈理解障碍、内容顺序、详略及例子/图示需求，无需正式报告。writer 记录所读版本、实际反馈、处理回复与修订版本，重要改动交用户复读，技术改动按影响由相应成员复核。第 1 章由 [T-006](TASKS.md) 落实。
- 通读与实机学习/实验分别记录，用户不必边读边完成全部实验；未经实际确认不记为通读完成，通读完成不等于实测通过或章节获批。章节定稿仍须满足既定验证与确认条件；具体反馈和验收证据在各章任务内记录。
- 岗位补充知识在实际创建成员时按其岗位与 scope 配置，不因采用模板而预置成员或虚构分工。

- 正式成果位于 `artifacts/`；图书成果按采用的图书模板组织在 `artifacts/book/`，仅在真实任务需要时创建相应文件。
- 用户保证当前仓库每次只有一个会话执行，前一会话完成或停止后再启动下一会话；框架不实现文件锁或自动调度。
- 每份文档默认维护一个当前版本，记录版本及批准依据；历史通过用户维护的 Git 追溯。
- 评审与批准要求在任务中明确。专业交叉评审由现有成员在原会话执行，不默认新建评审会话；用户保证受评版本可读取且不变，本轮全部评审者提交意见后作者再统一修订。采用根 [项目运行协议](../../PROJECT_PROTOCOL.md) 的评审、完成与状态规则。
- 默认在相关任务内记录轻量评审，需独立跟踪或正式报告时再拆分；具体已确认的验收要求不能自行降低。
