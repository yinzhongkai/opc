## 3. 四条工作流的详细工作分解

### 3.1 Windows/Qt 构建工作流：T-011～T-013

1. **T-011 工具链审计与决策输入**
   - 盘点 Windows 版本、CPU/内存/磁盘、`vswhere`、MSVC/Windows SDK、MinGW、CMake、Ninja、Python、Git 与环境变量现状。
   - 用 Qt 官方支持范围、x64 ABI、FFmpeg/依赖兼容、CI 与调试体验比较 MSVC 2022 Build Tools 和 MinGW-w64；给出推荐、风险和缺口，不代替用户确认 D-006。
   - 列出 Qt 确切版本、商业/LGPL 路径、最低 Windows 版本仍需谁确认；禁止在本任务中下载、安装或构建大型依赖。
2. **T-012 可复现 Qt x64 SDK**
   - 在 D-006 及版本/许可输入确认后获取固定官方源码并校验哈希，执行源码/构建/安装隔离的 shadow build。
   - 保存工具链版本、configure 全量参数和摘要、模块白名单、产物/符号/运行库清单与哈希；不使用 `-developer-build` 作为交付 SDK。
   - 构建并运行最小 Qt Quick/QML x64 程序，验证 QML 模块、插件发现、部署暂存和 Debug/Release 运行库一致性。
3. **T-013 应用工程与 CI 骨架**
   - D-006 和 D-003 构建组合确认后，依据 A-005 第 7 节先建立 `src/domain`、`src/media`、`tests` 的纯 C++ 最小目标；T-012 Qt SDK 就绪后再补齐 `src/app`、`src/worker` 和 Qt 目标。
   - 提供开发/CI presets、编译警告、运行库、x64 保护、测试入口、依赖 manifest/baseline；只有 D-003 确认后才冻结 vcpkg 和具体依赖版本。
   - CI 至少完成配置、构建、无 GUI 单测、最小 QML 冒烟和运行时依赖检查；安装器、签名和发布审批另设责任。

### 3.2 C++ 核心/系统工作流：T-014～T-016

1. **T-014 核心契约 0.x**
   - 定义有符号 64 位 `timeNs`、带检查的时间基换算与舍入规则；媒体 PTS 解释仍由 T-017/T-018 负责。
   - 定义 `RhythmEvent`、来源、强度/置信度、锁定/人工编辑、`timelineRevision`、`analysisRevision`、错误 taxonomy 和诊断 ID。
   - 定义命令与事务提交边界、取消/失败语义、DTO/schema 版本规则；产出边界测试向量，不依赖 Qt Quick 或 FFmpeg 类型。
2. **T-015 时间线事务与融合核心**
   - 实现增删移锁、批量偏移、撤销重做、分析结果合并、密度/窗口/种子参数、锁定事件保护和修订冲突拒绝。
   - 相同输入、算法版本、参数与种子产生等价输出；合并只作为单个事务提交，异常/取消不改变当前时间线。
   - 为公共 API、关键不变量和并发边界提供开发自测；测试工程师负责独立契约与集成验证，不替代开发自测。
3. **T-016 Worker/IPC/存储骨架**
   - 定义 `queued/running/cancelling/succeeded/failed/cancelled` 作业状态、幂等请求、进度、取消、超时、诊断与协议版本握手。
   - IPC 只传命令、进度、错误和稀疏 DTO；大帧/PCM 不经 JSON 往返复制。具体 Qt 本地 IPC 实现须受 D-003 确认约束。
   - 实现项目 JSON schema/迁移、原子保存、自动恢复、素材重定位、缓存指纹/配额/清理和临时结果提交；worker 崩溃不得破坏最近成功保存。

### 3.3 FFmpeg 多媒体工作流：T-017～T-019

1. **T-017 媒体契约与样例矩阵**
   - 定义 `MediaInfo`、流选择、旋转/SAR/DAR、帧/PCM 缓冲所有权、背压和生命周期；禁止跨模块暴露未约束的 FFmpeg 裸指针。
   - 定义 `PTS/DTS/time_base -> timeNs`、未知/负时间戳、start time、VFR、seek 对齐、音频采样索引和舍入策略。
   - 建立生成或许可清晰的 CFR、VFR、旋转、可变音频采样率、损坏/缺失流样例清单及期望时间向量。
2. **T-018 探测、解码与代理实现**
   - 使用 FFmpeg C API 和 RAII 封装完成只读探测、解复用、视频/音频解码、格式归一、代理帧/缩略图/波形源数据与定位。
   - 对长素材采用有界队列和缓存策略，不整段载入内存；取消、损坏、不支持、资源不足均返回结构化错误。
   - 在 CFR/VFR/旋转/多流样例上证明 `timeNs` 映射和定位一致，记录 FFmpeg build configuration 与能力矩阵。
3. **T-019 预览同步与导出事务**
   - 建立音频主时钟或明确的主时钟策略、视频帧调度、seek/暂停/恢复、掉帧与漂移诊断；UI 只消费状态和表面，不参与解码循环。
   - 导出开始时冻结 `timelineRevision`、媒体/渲染/音频参数与随机种子；写临时目标，成功后再提交，取消/失败不覆盖既有输出。
   - 在 H.264 后端未决定前使用可插拔编码器边界和已确认测试格式，不把原型编码器当成发布决定；输出音画误差按 A-004 的“一帧”约束验证。

### 3.4 C++/Qt 测试工作流：T-020～T-022

1. **T-020 测试策略与可追踪计划**
   - 将 A-004 TR-A/TR-F/TR-Q 与 G0～G4 映射到单元、契约、集成、Qt/QML、黄金样例、性能、恢复和兼容测试。
   - 规定测试命名、种子/时钟、临时目录、诊断归档、环境信息、跳过规则、样例许可证/来源/哈希和可复现入口。
   - 明确开发人员必须提交模块自测，测试成员独立维护跨模块断言和失败注入；D-003 未确认前只给框架候选接入方案。
2. **T-021 契约测试入口与黄金样例**
   - 建立统一 `ctest` 入口、标签和 headless 配置；测试框架仅在 D-003 确认后落地。
   - 覆盖时间换算边界/溢出、事件事务/锁定/修订、媒体 PTS/VFR/旋转、IPC 状态机、schema 迁移与原子保存。
   - 黄金素材必须生成或许可可核对，并登记生成命令、哈希、期望输出和容差来源；禁止把 `package/` 样本直接作为可分发测试资产。
3. **T-022 集成、故障与质量门禁**
   - 打通 UI 空壳/worker/core/media/storage 的端到端自动化，覆盖取消、worker 崩溃、损坏媒体、缓存损坏、素材丢失、磁盘不足和并发输出冲突。
   - 在确认的基准硬件和素材矩阵上记录时延、吞吐、峰值内存、seek、漂移和恢复数据；未确认阈值不得给出 pass。
   - 汇总 G0～G4 证据、失败项、复现步骤和归属任务；测试结论不等于成果批准或发布授权。
