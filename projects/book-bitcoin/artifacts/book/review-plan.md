## 计划目标与当前条件

沿用书稿现有读者定位，审核全部 13 篇，并让“原理、源码、运行观测”的证据能相互支撑。核心目标是形成可复核、适合目标读者的出版候选稿；成书格式、排版导出和出版渠道尚未确定，本计划不据此预设任务。

当前书稿基线已锁定，本次盘点已覆盖全书。tiger 上可定位 Core v31.0 对应提交 `6574cb40869b96b9ffc79c19dc8f4e467d60f321`，但环境和构建尚未验证。bitcoin-tools 无 Git 元数据，只有四脚本，其中两个与书稿同名；完整参考标签、图稿、版本清单和实验记录仍需落实。

四名成员的职责可覆盖计划协调、已有书稿修订、独立审校和领域证据核查。没有成员获授权承担配套软件开发或服务器实际实验执行。T-006 因此由项目经理组织验证矩阵、收集现有证据和落实执行责任；不能把“技术验证”技能当作新增执行授权。此次 ssh 授权仅用于资料位置查找。

## 执行与记录约定

每次领取任务先按会话协议刷新身份、任务和相关版本。领域结论由 researcher 署名，独立审校由 reviewer 署名，writer 对问题逐项回复；project-manager 不代写他人的 pass、接收或复核结果。

T-007–T-009 内安排 reviewer 复核论述、教学、一致性和验证证据，researcher 复核技术事实与来源。开始每轮时登记受评路径、精确 commit / 可读取内容版本、成员范围与完成条件；所有本轮意见齐备后再修订。复核是各组任务完成条件的一部分，无需为每位评审者重复建任务或递归审校评审报告。

治理文档放在 OPC `artifacts/book/`，正文与直接配套交付物放在已声明的产品工作区。候选服务器资料的位置可记录为输入；导入或创建新配套工作区、开发缺失工具、安装依赖、执行实验和发布需各自具体授权与责任，不因本计划自动生效。

当前开发分支为 `feature/book-bitcoin/t-001-review-planning`。后续分支在任务中列为计划名，尚未创建；必须完成当前轮交付、合入与验证后才启动下一轮开发，沿用用户已确认的线性提交偏好。产品任务合入后由内容负责人提供最终完整 commit，再按协议刷新版本引用。本计划不推送、合并或删除分支。
