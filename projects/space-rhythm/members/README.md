# 项目成员文档

成员名单以 [TEAM.yaml](../TEAM.yaml) 的 members 列表为准；空列表表示尚未创建成员，本说明不维护动态成员表。由框架级 [超级管理员](../../../SUPER_ADMIN.md) 按用户请求创建成员并登记 ID；新会话不能仅凭角色声明自动创建成员。

每名成员只有一份 `<member-id>.yaml` 配置，文件名与内部 id 一致，仅保存 id、role 和 scope。TEAM 不重复这些字段，也不保存平台会话 ID、标题或当前有效会话状态。角色与技能引用共享定义，不复制成每个成员各自维护的提示词；底层字段仍使用 `role`、`knowledge` 和 `roleKnowledge`，逻辑身份到平台会话的映射只由适配层运行时维护。

以下只是格式样例，不是已创建成员：

```yaml
id: project-manager
role: project-manager
scope:
  - 在已确认范围内协调项目计划、依赖和风险
```

按 [配置规范](../../../CONFIG_SCHEMA.md) 完成文件与索引两处写入并校验后，才能报告创建完成。未登记、缺失、重名或路径不匹配的配置不能用于绑定。

用户或超级管理员按 [会话消息协议](../../../SESSION_MESSAGING.md) 创建成员会话后，可发送“你是项目经理，请初始化”。项目与对应角色的在册成员可唯一确定时按 [会话协议](../../../SESSION_PROTOCOL.md) 绑定；有歧义才询问。每个成员同一时间只保留一个当前有效会话，替换前停止旧会话工作。初始化回执会包含实际成员 ID、配置路径、角色和分工；会话标题不代替初始化，成员文档也不提供会话锁。
