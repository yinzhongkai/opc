## 1. 架构结论及边界

采用原生微信小程序，候选编辑、独立等概率抽取和菜单持久化均在当前设备完成。全新状态按D-019一次性建立并加载8项默认菜单；再次启动按稳定身份恢复上次成功使用的菜单当前保存快照，缺失/已删除才依现存内置默认身份、现存同名菜单、原列表首份降级，旧有效空库保持空。对应13项有效需求、13条规则、40项验收；选择记忆不自动保存编辑，不新建或覆盖菜单内容。

## 2. 系统与模块

```mermaid
flowchart LR
    U[用户输入及主动操作] --> UI[主页与菜单弹层]
    UI --> STATE[WorkingSession 工作副本]
    STATE --> POLICY[CandidatePolicy 与 MenuPolicy]
    STATE --> DRAW[DrawEngine]
    DRAW --> RANDOM[本机 RandomPort]
    STATE --> REPO[MenuRepository 串行命令]
    REPO --> STORAGE[当前微信用户的小程序本机存储]
```

| 模块 | 职责及依赖 | 失败处理 |
|---|---|---|
| MainPage / Dialogs | 转盘、名称输入、完整候选列表、保存及菜单管理；派发命令，不直接改存储。 | 提示具体错误，保留输入、工作候选及旧菜单。结果区域仅名称。 |
| WorkingSession | 当前候选、加载菜单 ID、基线版本/内容、dirty、界面阶段和抽取代次。 | 迟到回调不覆盖当前状态；仅明确保存成功才替换保存基线。 |
| CandidatePolicy | trim、非空、同一列表逐字名称去重、24 项上限。 | 不查地图，不要求真实门店、地址或类别；拒绝时不改变已有项。 |
| MenuPolicy | 菜单名 1～20 可见字符、不同菜单名唯一、非空快照、覆盖/另存语义。 | 不截断、隐式覆盖或以固定菜单份数拒绝保存。 |
| MenuRepository / StoragePort | CRUD、不可变快照、容量检查、写入确认及格式验证。 | 不以删除旧菜单腾空间；失败保留编辑态和已提交版本，保存并切换停止。 |
| DrawEngine / RandomPort | 固定候选快照、均匀索引和动画结果分离。 | 熵源失败不出结果；不根据历史调整概率，不写回菜单。 |
| GraphemeSegmenter | 对菜单名称按固定 Unicode 扩展字素簇版本计数。 | 不依赖未经验证的运行时内建能力；分段不可用时不绕过菜单校验。 |
| StartupCoordinator / MenuRepository.ensureDefaultMenu | 一次性初始化已在当前基线存在；T-034需在其后接入第11节现存菜单选择与恢复。 | 保留bootstrap终态，不用重新播种修复旧版启动空候选。 |
| SelectionStore / SelectionCoordinator（待实现） | 同域独立记忆menuId、选择版本与意图；成功加载/关联保存后更新，恢复时只读最新菜单快照。 | 区分菜单与记忆结果；记忆不可用不破坏健康菜单库，结果不明先核验，见第11节。 |

领域规则不依赖界面、网络和存储实现。StoragePort 与 RandomPort 便于后续故障注入；首版没有服务端部署单元或外部餐厅适配器。

## 3. 数据模型与不变量

| 对象 | 字段及含义 | 约束 |
|---|---|---|
| Candidate | candidateId、displayName。ID 为内部生成，用户只填名称。 | displayName 在添加时 trim 且非空；同列表逐字唯一，顺序稳定；0～24 项。 |
| MenuSnapshot | menuId、name、schemaVersion、revision、orderedCandidates、createdAt、updatedAt。 | name trim 后 1～20 个可见字符；不同 menuId 名称唯一；完整保存 1～24 项及顺序。 |
| WorkingSession | candidates、currentMenuId 可空、baselineRevision、baselineCandidates、dirty、phase、generation。 | 不持久化未保存副本或抽取结果。dirty 按有序名称内容与基线比较；内部 ID、动画和抽取不造成内容变更。 |
| DrawResult | drawId、generation、selectedCandidateId、displayName。 | 只属一次抽取；重新编辑候选或开始新抽取时清除旧结果。 |
| StoreRoot / StoredChunk | schemaVersion、storeRevision、索引/内容引用、校验值、最近提交信息。 | 存储格式校验、分块和版本恢复使用；不增加用户输入字段或菜单份数业务限制。 |
| SelectionRecord（待实现） | 第11节独立key ee/selection；schemaVersion、kind、revision、menuId可空、operationId。 | 仅记稳定身份，不存候选/菜单名/未保存内容；缺失正常兼容，损坏单独报告，不重写旧菜单或旧根格式。 |

去重只在同一份当前候选中执行：trim 后字符串逐字相同则拒绝；不同菜单可包含相同候选。不做大小写、全半角、同音或模糊合并，不再有跨来源同名例外。菜单名唯一性与候选名称唯一性分别校验，重命名菜单排除自身 ID。

加载按保存顺序恢复，不重新trim、筛选或生成名称；坏快照不静默修复。现有根/索引/内容schemaVersion=1和已实现的defaultMenuBootstrap及其原回执格式保持，具体合法存量见第11.1节。新选择格式缺失不是损坏，选择key与菜单校验分开；不为选择功能重新初始化、迁移或改写旧菜单内容。

本版不保存位置、地址、门店来源/标识、许可、搜索状态、电话或历史抽取记录。菜单存储域按当前微信用户与小程序隔离；换微信用户不能被描述为同一存储域。正常关闭后可加载是目标，主动清除及平台清理后的找回不在承诺范围。

## 4. 输入与菜单接口

### 4.1 候选命令

| 命令 | 输入/成功结果 | 拒绝或异常 |
|---|---|---|
| addCandidate | 原始名称 → trim 后的名称及新 candidateId，追加末尾。 | 空白、同列表重名或已有 24 项时拒绝，原候选和旧菜单不变；不要求对应地图门店。 |
| removeCandidate | candidateId → 仅删除该当前项。 | 允许删除最后一项；不自动覆盖已保存菜单。未知 ID 不误删其他项。 |

名称没有 20 字符业务上限。官方 input 默认 maxlength=140，因此候选输入须显式取消该默认限制；菜单名称也先接收完整输入再按字素计数，不用控件 maxlength=20 冒充可见字符规则。[S-03](https://developers.weixin.qq.com/miniprogram/dev/component/input.html) 超长内容引起的平台资源/写入失败须明确反馈，不截断后假称原样保存；实际极端长度可用性待验证。

### 4.2 菜单仓储契约

所有菜单写操作通过同一串行队列执行，唯一性检查和 store revision 核对属于同一命令。每次操作固定 operationId、目标 ID 和 expectedRevision；新建/覆盖还保留完整有序候选快照。相同完整意图回放持久回执，不新增记录或回退当前工作态；复用 ID 但更改命令、参数或版本拒绝。公开入口须先查回执，再判断目标当前是否存在；001/002已独立复测关闭，见第9节。

本表保留菜单阶段接口；低层repository.list/load只读，不因测试/检查读取而记住选择。面向用户的成功加载、保存、切换由第11节协调器追加独立记忆阶段，分别报告两个结果，不把记忆失败当作菜单保存失败重做。

| 命令 | 成功语义 | 前置及失败语义 |
|---|---|---|
| listMenus | 返回 ID、名称、revision、候选数。 | 只读本机；读取失败不能被当作空库并覆盖原数据。 |
| loadMenu | 校验并完整恢复选定 ID 的名称和顺序，设定基线、dirty=false。 | 切换前处理未保存改动；读取失败保留原工作副本和当前关联。 |
| createMenu | 以新 ID 保存非空完整候选并关联新基线。 | 校验菜单名及唯一性、候选 1～24 项；不因第 21 份或其他固定份数拒绝。 |
| overwriteMenu | 用户明确覆盖指定 ID、版本成功后更新该记录与基线。 | 不能按重名推断目标；空候选、版本或空间失败保留全部旧记录与工作副本。 |
| renameMenu | 仅更改目标菜单名。 | 与新建相同的名称校验，排除自身 ID；自身原名无变化成功；不改候选内容和其他菜单。 |
| deleteMenu | 明确确认后仅删目标保存记录。 | 取消或写入失败全不变；若删当前菜单，保留当前完整候选，清 currentMenuId/基线，标未保存。再次保存须新 ID，不能复活已删关联。 |

菜单名使用 trim 后的原字符串比较，不自动标准化为另一名称。长度按 Unicode 扩展字素簇计数，采用 [UAX #29 修订 49](https://www.unicode.org/reports/tr29/tr29-49.html) 的固定分段口径；汉字、ASCII、组合字符与合法 ZWJ emoji 分别按规则验证。20 字符不约束候选名称。实现已锁定 Unicode 18.0.0/UAX #29 rev49，使用本地属性表及等值 JS 表；独立853条语料与目标基础库/用户手机证据分别见第9节。

切换时 dirty=true 提供保存并切换、放弃并切换、取消。保存并切换在命名、非空、写入和回读确认全部成功后才加载目标；保存尚未确认的任一步失败均保持当前编辑态和菜单关联，不清 dirty、不加载目标；结果不明先核验。若源保存已经确认而目标读取失败，保留当前已保存副本和新基线，不把它误报为未保存，也不切到不可读目标。已知未提交失败后，用户仍可另选取消或明确放弃。无关联的未保存副本须先另存命名。

删除当前菜单时，无论有无修改、是否最后一份，均保留当前候选为未保存副本；若候选已删空，继续保留 0 项并按空保存规则拒绝保存。退出前未保存不要求下次恢复。删除/重命名其他菜单不改变当前候选或其保存内容。

### 4.3 本机持久化与空间失败

官方文档支持本机键值读写，并说明同一微信用户、同一小程序的存储域上限；setStorage 给出普通存储单 key 1MB、总计 10MB，以及用户删除或系统空间清理的边界。[S-01](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/storage.html)、[S-02](https://developers.weixin.qq.com/miniprogram/dev/api/storage/wx.setStorage.html) 这些是平台上限，不是本项目已测可用容量或永久留存保证。

采用不可变内容块与固定大小提交根的设计，避免把全部菜单打包到单个 key 而提前触及单 key 限制。序列化后按字节分块，初始建议每块不超过 128 KiB 的原始字节，再编码为存储值，核对含元信息后的实际长度；索引同样可分块。当前实现默认128 KiB，按编码后的实际块大小检查，链式内容及索引可分块。它是内部参数，不是名称或菜单份数上限。容量预估及实际写入错误均检查；没有自动回退旧根，历史回执及孤块的容量成本见第9节。

写入流程：读取并校验当前根及 revision → 校验命令与容量 → 向新 key 写入候选副本/索引并回读校验 → 更新提交根并回读 → 才向界面报告成功和替换基线。新块全部确认前不替换可见根，不覆盖旧块，不先删除旧菜单腾空间。空间不足或准备阶段失败时，旧提交与当前编辑态保持不变；未提交块后续可清理，但不删除任何仍被有效根引用的内容。重命名、删除同样经此流程确认，不能仅改列表显示。

官方键值 API 没有在已读文档中承诺跨 key 事务或断电原子性；当前实现与分阶段故障证据支持该应用恢复协议，仍不提供平台未承诺的物理原子性。提交根回调异常但回读为新版本时须按实际提交结果恢复，不能同时宣称保存失败且旧记录必然未变；无法判定时保留编辑态、阻止继续写入/切换，提示保存状态需核验。故障注入须分别验证准备阶段空间不足、根提交异常与进程中断，不能用准备阶段测试代替整个持久性保证。损坏/未知格式时不自动清空数据库，也不悄悄恢复为已确认删除前的列表。

getStorageInfo 可提供存储使用情况；仅作为预估，实际写入仍可能失败。[S-05](https://developers.weixin.qq.com/miniprogram/dev/api/storage/wx.getStorageInfo.html) 首版不主动启用加密存储或新建云服务；如后续增加此能力，需重新核对容量、依赖和需求。正常关闭再开及离线已有用户手机自测反馈；失败恢复有独立L层及真实wx上的注入证据，不能据此称实体满配额或断电已测。

## 5. 等概率抽取与状态控制

draw(candidateSnapshot, randomPort) 返回一次固定结果。0 项提示先输入且不产生结果，1 项直接显示唯一名称。N≥2 时，每次均从快照独立选择索引，不根据历史排除上次结果、调整权重或轮换。

RandomPort 已采用官方 wx.getRandomValues：文档标注基础库 2.15.0 起支持，返回指定字节数的随机内容。[S-04](https://developers.weixin.qq.com/miniprogram/dev/api/device/crypto/wx.getRandomValues.html) 每次取得 4 字节并按固定字节序解释成无符号 32 位整数 x，令 B=floor(2^32/N)×N；x<B 时返回 x mod N，否则重新取样。每个余数有相同数量的可接受输入，避免直接取模偏差。设置有限熵源重试预算，失败报错，不用动画角度或未经核对的替代算法产生结果。

2.15.0 只是旧官方说明中的 API 起点；当前已验证基础库锁定3.17.4，工具2.02.2608080/WebView，不宣称已测试较低版本。实现按大端读取4字节，拒绝预算32次；跨执行域宿主 ArrayBuffer 转为本域 Uint8Array，保留严格类型/长度校验，001已独立复测关闭。先选结果，再确定动画终点；动画帧数、时间和历史结果不影响选择。动画结束只提交一次 drawId；再次抽取必须新建 drawId。后台/页面销毁会使 generation 失效，迟到回调不能显示旧结果或改菜单。

候选增删、菜单切换及写入在抽取期间暂不可提交；菜单写入期间也串行化相互冲突的操作，界面保持内容可见并禁用重复动作。抽取中断恢复可操作状态，不自动保存。抽中结果区域仅完整名称，按钮为再抽一次、关闭，不增加地址、距离或来源说明。

```mermaid
    RestoringSelection --> Ready: 现存快照已加载 或合法空库
    RestoringSelection --> StartupError: 读取异常或结果不明
    Bootstrapping --> StartupError: 读取失败或结果不明
    StartupError --> Bootstrapping: 显式安全核验重试
    Ready --> Drawing: N大于等于2
    Drawing --> Result: 固定结果及动画完成
    Drawing --> Ready: 失败或中断
    Ready --> Result: N等于1
    Result --> Drawing: 再抽一次且N大于等于2
    Result --> Ready: 关闭或编辑
    Ready --> SavePrompt: 有未保存改动时切换
    SavePrompt --> Saving: 保存并切换
    Saving --> Ready: 保存确认后加载目标
    Saving --> SavePrompt: 保存失败 保留当前内容
    SavePrompt --> Ready: 放弃后加载或取消
```

状态图为目标契约；选择恢复及独立记忆阶段待T-034实现。记忆明确写失败可进入Ready并单独警示，结果不明先核验。N=0不重新播种，N=1仍返回唯一名称；失败不丢工作态，同页后台返回不重新恢复。

| 错误类别 | 可恢复行为 |
|---|---|
| EMPTY_CANDIDATES / INVALID_CANDIDATE_NAME / DUPLICATE_CANDIDATE / CAPACITY_FULL | 提示先添加、检查名称或先删除；原候选和已保存记录不变。 |
| INVALID_MENU_NAME / DUPLICATE_MENU_NAME / EMPTY_MENU | 保留输入、编辑态及旧记录；不截断、不继续保存并切换。 |
| STORAGE_FULL / WRITE_FAILED / REVISION_CONFLICT | 不报已保存，不清 dirty，不自动删旧菜单；按实际提交结果判断可安全重试的命令。 |
| STORAGE_UNCERTAIN / STORAGE_CORRUPT / UNSUPPORTED_SCHEMA | 保留当前内容，停止可能覆盖原数据的操作并说明读取/保存状态；不当成空库。 |
| RANDOM_UNAVAILABLE / PLATFORM_UNSUPPORTED | 不产生抽取结果，恢复按钮；说明当前平台能力未满足。 |

| LEGACY_EXISTING | 无新标记的已知v1合法根，完整验证后含一份或多份菜单（含任何同名菜单）。 | 直接settled，不写标记、不增菜单；原名称/内容/顺序/ID/版本及原有加载行为不变。 |
| LEGACY_EMPTY | 无新标记的已知v1合法根，菜单为0；包含revision=0/index=null的旧genesis，或revision≥1的有效空索引（可能含删除/失败历史回执）。 | 按已使用的空库处理，settled且不写入、不自动加载；不能证明首次就不播种。旧失败首次保存留下的genesis也如此，不追溯补默认菜单。 |
| PENDING | 合法根含本节已知策略的pending元数据，revision=0/index=null；恢复意图身份完整，可有此前未提交的本域块。 | 显式核验后仅续接原意图，不创建另一份意图；pending不是已保存菜单，不对用户报成功。 |
| INITIALIZED | 合法根含已知策略的complete元数据，revision≥1；完整索引及当前快照验证成功。 | settled，禁止再创建或强制加载原始8项，即使默认菜单改名、改内容或已删除/空库。 |
| UNAVAILABLE | key列表/任一必需读取失败、缺根残块、损坏/校验不符、未知schema/策略/标记状态或不可能组合。 | StartupError；保留全部原字节和可用编辑态。READ_FAILED/STORAGE_CORRUPT/UNSUPPORTED_SCHEMA按实际来源提示；结果不明用STORAGE_UNCERTAIN，均不进入FRESH或自动修复/清库。 |

缺失判定不可吞掉StoragePort.info/read的错误。pending仅允许出现在本节新建的revision=0根；complete仅允许出现在revision≥1根。菜单非空却pending、标记缺ID/字段类型错误等是损坏；已知字段中的未知版本/策略是未支持格式。任何用户持久记录存在时均不得覆盖为genesis。没有标记的普通合法根永远走legacy分支，不能根据名称“默认菜单”或内容恰好8项反推初始化身份。

### 10.3 持久意图、一次提交与幂等

`defaultMenuBootstrap`逻辑字段为`{version:1, policyId:'d019-v1', state:'pending'|'complete', operationId, menuId}`；operationId固定保留为`bootstrap-default-menu-v1`，menuId在首次准备时用现有ID工厂生成并写入pending，重试从pending取回，不重新生成菜单身份。标记不是用户菜单，也不计入24项或菜单份数。固定种子名称/顺序是该策略不可变参数，初始化命令不接受UI传入的覆盖名称/候选；保留operationId供此命令专用，普通CRUD不得使用该ID伪造初始化回执。

1. 启动协调器在空且无关联、无dirty的WorkingSession上调用初始化；同域只用一个repository。coalesce重复onLoad/重试调用并进入既有队列，开始分类到提交/核验完成前锁住冲突操作。普通手动写入若先发生，后续初始化只能按legacy处理，不得覆盖已有内容。当前页面已有编辑态时不执行延迟自动初始化，返回BUSY/UNSAVED_CHANGES并保留副本，不悄悄另存或替换。
2. FRESH先完成容量预估、意图ID校验；再次核对根仍缺失和本域key列表未出现使用痕迹，再写带pending的genesis并回读确认。这一准备根不含菜单，不代表初始化完成。genesis回调失败也必须核对实际根：读回同pending则继续；明确仍缺失且未写任何块则是未提交；无法判定则冻结并等待核验。不得先调用会生成无标记旧genesis的普通createMenu。
3. 按既有复制写入协议为固定8项准备不可变内容块，逐块回读；写新索引，其菜单列表仅一份已固定menuId的完整默认快照，并保存该初始化operationId的持久回执。签名区分初始化类型、policyId、原pending根/版本和固定名称/顺序，防止与普通create混用；candidateId可在准备时生成，但未提交块不可被列表加载。
4. 再查容量和原根原文，发生变化则REVISION_CONFLICT并重新分类，不能把新根覆盖掉。把指向完整新索引的revision=1根与同意图的state=complete元数据**一次根切换**提交；逐根及可达内容核验后才返回成功。因此complete、默认记录和初始化回执同时可见，不单独提前写“完成”布尔位，也不先暴露菜单再补标记。
5. pending期间普通create/overwrite/rename/delete必须拒绝为BUSY（初始化未完成），即使一次明确准备失败后也不能绕过初始化入口写成revision≥1的pending根；由显式核验/续接先解除。complete后的所有CRUD都保留根元数据及索引初始化回执，不因为默认menuId不存在、菜单数0或候选改动清除终态；其根revision继续按既有规则递增。删除菜单只改变索引，不能移除根或重置为新genesis。旧无标记根在普通写入后也保持可识别的合法根；本轮不自动迁移或清理活块、回执。
6. 初始化命令先看当前根终态/当前记录，再处理回执。相同原意图重试只验证既有结果，不重建、不把历史snapshot加载到当前Session；用户后续修改或删除后，旧回执仅证明原初始化曾完成。operationId/策略/目标/原参数不符报REVISION_CONFLICT，不借“重试”更换内容。root.guard只是单写入者协议的冲突检查，不承诺多进程CAS或平台物理断电事务。

### 11.2 独立选择记录与兼容分类

选择记录放同一WxStorage物理前缀`eating-everyday:v1:`内的逻辑key **ee/selection**，与菜单根/内容分开，用原pack/unpack校验封装：`{schemaVersion:1,kind:'menu-selection',revision,baseRevision,menuId,operationId}`。revision为正安全整数，baseRevision=revision-1；menuId为非空稳定ID字符串或显式null。ID可能因菜单删除而悬空，存在性另查，不能将这种合法记录当格式损坏；新写非空目标时才要求目标仍存在。operationId为本次选择意图的非空唯一ID，不能复用bootstrap保留ID。它不保存菜单名、候选、dirty、抽取结果或回执旧快照。缺失按选择版本0处理；null表示已明确清除选择，不删除本域使用痕迹。只保留最后一条选择意图，不随操作次数累积选择历史。

采用独立key是为了菜单已保存/加载后记忆明确失败时能分别反馈；不用改写菜单来补选择，不以单个根内字段把选择坏值和整个菜单库的健康状态混为一谈。需要在所有本域key识别入口（尤其`_bootstrapState`）**只增加ee/selection这一已知key**，其余未知key继续保护；不能放宽为任意key都忽略，也不能把新增选择key当作旧库损坏。原菜单读路径和选择读路径分开校验。

| 存储/选择情况 | 分类及允许行为 |
|---|---|
| 本域全部key明确缺失 | 先执行原FRESH一次性初始化，确认完整菜单落盘/加载后再记选择；不可先写selection造成“只有选择、没有根”的伪新库。 |
| 合法旧库或已初始化库，selection明确不存在/null | 正常兼容输入，非损坏。菜单非空走11.3降级；合法空库保持空。旧genesis可有未提交孤块，沿用现有合法读取条件，不重新播种。 |
| 有已知格式的有效选择ID | 通过完整菜单库验证后判断ID是否存在；存在则读当前保存快照，已明确删除则降级。仅重命名不导致ID失效。 |
| selection坏校验/坏字段/未知版本，或其读取失败 | 仅选择不可用，保留原字节并提示，不当作缺失、不自动降级或覆盖坏记录；菜单库完整可靠可读时可手动明确加载/保存菜单，并单独提示选择无法留存。T-033不授权自动删除/修复未知格式。 |
| 菜单根/索引/任一必需内容读取异常，或初始化pending/结果不明 | 先按原恢复协议处理，不静默跳过坏菜单改选；选择正常也不能替代完整菜单核验，不新建默认记录“修好”旧库。 |
| 无根但仍有selection、孤块或其他本域key | 不是FRESH，保留所有字节并报菜单库不可用；只有明确全部清除后本域全空才按首次处理。 |

同名新菜单的不同menuId不是旧身份；仅因名称相同不修复旧选择ID。未知选择格式不阻断已经独立验证为健康的菜单读取，但不得假称自动恢复或选择写入成功。旧3800e6d启动器会拒绝未知额外key，降级写入兼容未验证且不在本轮自动支持范围，不能承诺旧版本读写本次新记忆。

### 11.3 启动选择、快照应用与升级

新使用会话的启动顺序：原初始化/恢复达到可读终态 → 同队列读取完整菜单库和选择状态 → 决定ID → 重新核对并加载当前保存快照 → 应用候选/基线 → 必要时记住该ID。所有选择只引用现存记录，不调用create/overwrite；菜单列表沿用索引/现有UI显示顺序，不额外按名称、日期或ID排序。

1. 可确认全新状态仍只播种一次；初始化完成后即走普通成功加载/记忆流程。已完成初始化后的恢复也从当前菜单读取，不使用bootstrap历史snapshot覆盖用户修改。
2. 有效选择ID仍存在，优先加载该ID当前保存的名称/完整候选/顺序；不依赖保存时revision或旧名称来选择，但加载后的baselineRevision必须等于这次真实快照revision。
3. 只有选择明确缺失/null或ID已确认不存在，才依次选择：仍存在的`inspect().bootstrap.menuId`（须已知complete，包括已改名者）→ 名称trim后逐字为“默认菜单”的现存菜单（可为用户内容）→ 原菜单列表首份。缺失bootstrap元数据是合法旧库，跳过内置ID步骤，不推断或补造身份；原初始化ID已删也只跳过，不从回执复活。
4. 合法已使用空库保持空候选/无关联；失效选择可单独清为null，已经缺失/null无需写入。清选择失败须提示但不能改变“空库不播种”的判断。存在其他菜单时降级加载成功后记住新ID，不要求先清旧ID再二次写入。
5. 一旦任一必需菜单或选择读取/格式不可靠，不把它当作ID缺失继续降级；库健康而选择单独不可用时进入明确手动模式。用户手动选择成功可使用现存快照，选择读取/格式未恢复前不盲写覆盖它，显示选择未记住。

快照应用必须在同一会话仍有效、待加载选择仍是本次目标且没有新编辑/关联变化时，一次性更新candidates/currentMenuId/baselineRevision/baselineCandidates，dirty=false，清旧结果并重新绘制；失败不先清空副本。目标在判定后被删/版本变更，重新核验库并按同一规则重算，不拿旧snapshot应用；读取错误不能当作目标已删。有限冲突重算仍失败则提示重试，不无限轮询。记忆已是同ID且格式有效时无需再写一次；兼容选择必须真正留存，不能只改当前页面。

### 11.4 选择提交、幂等与核验

一个存储域共享一个repository/SelectionStore写入序列；选择读写、菜单写及选择前的身份核验使用同一串行协调，不在已持有队列时再等待公开排队接口造成自锁。不增加跨进程锁，不把root.guard/选择guard说成多写入者CAS。

每个选择意图固定`{operationId,targetMenuId或null,expectedSelectionRevision,expectedRaw}`。执行时先核验菜单库和当前关联授权，确认非空目标仍存在；在同队列读取选择raw，格式可读且版本/原文符合预期才能写。新revision=baseRevision+1；再次读raw作guard后写入完整pack记录，回读完全等于拟写值并校验才记为remembered。不能把读取错误降级为缺失后写版本1；已存在坏值/未知版本不覆盖。版本耗尽只让记忆阶段明确失败，不回滚已保存菜单。

| 结果 | 处理与对外语义 |
|---|---|
| 写前校验/容量明确失败，或写错误后确认仍为旧raw且无残留写入 | selection=failed；菜单阶段结果保留，当前内容仍可使用，提示“菜单已加载/保存，启动选择未能记住”。不报整个保存失败、不重新执行create/overwrite。 |
| 回调报错但读回完整拟写记录 | 按实际remembered处理，至多一次选择版本推进；不能同时报未记住又盲重试。 |
| 写后读失败、读回未知值、超时尚有底层写入可能 | selection=uncertain，保留原意图并关闭可能改变持久状态/恢复目标的入口，先核验；菜单已确认保存仍保持成功事实。 |
| 重试读回相同operationId、目标、baseRevision及结果revision | 已提交回放，仅返回已确认状态，不写新版本，也不加载任何菜单快照。复用ID但参数不符为冲突。 |
| 当前记录已是更高版本/另一新意图 | 旧请求已过期，不能覆盖或补写旧目标；只返回superseded/冲突，由当前有效目标决定后续。不维护旧选择历史来重放副作用。 |

`recoverSelection(intent)`先确认没有仍可能落盘的旧写：原write已settled、平台有序屏障确认，或读回本唯一operationId的完整拟写记录且Port可保证单次调用至多一次写效果，均可作为依据；不要求已落盘而丢失的成功回调必须再次到达。再验证实际记录：拟写值=committed；确认旧写已结束且仍为原值=not_committed；确认旧写不会再落盘且已有更高有效新意图=superseded；坏值/读错仍不解除不明。不能只凭一次旧值或更高值放行仍可能迟到落盘的写。核验本身不写、不加载；确认未提交且意图仍属于当前关联才显式重试原意图，或对最新目标新建意图。一个不明选择写未解除时，不排入新的菜单保存/删除/切换或选择写与其争用；允许查看/保留本地候选，任何安全本地编辑都不得被恢复回调改写。

缺失选择时的重试仍保留原operationId及参数；新用户选择成功即使省略同ID重复IO，也推进内存选择权威代次，淘汰旧补记。ID变更或删除时旧意图失效；同ID的新编辑不需要另存，记忆补写可以仍指同ID，但绝不回放保存/加载或改候选、基线、dirty。失败提示和记忆状态更新也须核对意图/代次，不能让旧失败覆盖新一次成功提示。

### 11.5 与保存、切换、重命名和删除的一致性

菜单提交与记忆提交是两个可观察阶段，不声称跨key原子性；通过稳定ID和后续存在性校验避免悬空选择复活记录。菜单根/索引/快照和原回执不因补记而改写。面向UI的结果应分开表达，例如`{menu:{status,menuId,revision},selection:{status,operationId},state}`；保持低层菜单返回兼容，在协调层扩展，不用一个泛化异常抹掉已确认成功。

| 操作 | 菜单/当前工作态与选择阶段的顺序 |
|---|---|
| 启动/手动加载/放弃并切B | 完整加载B并关联后才记B；load失败/取消不写B，保留A/dirty。记忆明确失败时B可继续使用，旧可确认记忆仍为下次依据，并单独提示。 |
| 新建/另存/覆盖 | 菜单确认成功、当前关联/保存基线已更新后记当前ID。另存N记N、覆盖M记M；记忆失败只补记，不重做保存或改菜单revision。普通读取、输入、删除候选、抽取不产生选择写。 |
| 保存A并切B | 先保存A确认并记A，再加载B成功后记B；A保存失败/空保存不读B、不改选择。A已保存但B读失败，保留A的新基线和副本，记忆应为A。若A记忆明确失败，保留部分成功提示；可继续尝试B加载，最终B记忆成功可取代此次中间失败。若B也未成功记住，不能承诺下次恢复A/B；用最后可确认记录。任一步结果不明先核验，不继续后续改变恢复目标的阶段。 |
| 重命名当前/其他菜单 | 不改变身份或制造新选择事件；当前ID仍用其最新名称。改另一份不把选择切过去，不以改名操作掩盖此前记忆失败。 |
| 删除当前或被记忆目标 | 先确认菜单删除，再仅在当前持久记忆目标等于被删ID时清为null（单独记忆意图）。删除当前按旧契约解除关联/保留本次未保存副本，不立即自动加载另一菜单覆盖副本；下次启动再降级。清选择明确失败仍保留删除成功，旧ID下次因确认不存在而失效，不复活。 |
| 删除非目标/取消/菜单明确未提交 | 非目标不改记忆；取消/明确未提交不清选择或谎称删除成功。删除当前A但持久记忆仍是B（先前A未记住）时保留B，不能无条件清掉有效B。 |
| 历史菜单幂等回放 | replayed=true不构成新的当前关联事件，不能因旧create/overwrite回执成功就把选择倒退到旧ID。菜单结果不明恢复先核对实际提交和当前上下文；只有未被新会话/关联或编辑超越的原操作可完成相应状态衔接，不无条件调用旧_apply回放历史snapshot。 |

已经保存成功不因记忆失败要求用户再点一次“保存”；提供记忆专用重试。菜单阶段明确失败与选择阶段失败要用不同提示及日志阶段，例如selection.read、selection.guard/write/readback/recover。选择未知格式/持续读失败时，健康菜单可手动继续，正常菜单操作和记忆不可用分别报告；不得为了消除警示清用户数据。菜单自身不明则仍遵循原仓储冻结与核验。

### 11.6 生命周期、顺序与接口边界

区分三类代次：新会话/页面实例sessionEpoch；成功关联或删除造成的choiceEpoch；候选编辑/异步绘制使用的editGeneration。菜单选择结果应用须同时核对相关代次及目标；选择记忆回调从不调用loadMenu/_baseline。单纯onHide的抽取失效不能当作“用户换了菜单”，也不能把已提交菜单撤销。

同一页面onHide/onShow、弹层关闭、列表刷新只刷新可安全展示的信息并保留Session；不重新start、不创建空Session、不自动保存/加载。启动在后台尚未应用时不能过早settled并放行空转盘：返回前台后在仍无编辑/关联的新会话内续接，重读当前快照，再应用并记忆，不重复播种。onUnload后旧实例不得setData、重新关联或安排旧目标的新补记；已发出的持久写可按真实结果结束，但必须在共享序列核验后才让新会话读取/写入，新会话或新成功选择优先。不能通过超时释放队列后让旧物理写覆盖新选择。

以下为待实现的逻辑接口，可等义命名但须在T-034产品说明中列出实际入口和返回；检查工具/测试调用底层只读菜单API不产生“上次使用”。

| 入口 | 必需语义 |
|---|---|
| SelectionStore.read() | missing/known(value)/unavailable(error)分开；有校验的null是known已清除。只读，不吞错或自动修复。 |
| rememberSelection(menuId,intent) / clearSelection(deletedId,intent) | 共享序列中校验目标存在/确已删除、原raw和版本；幂等返回remembered/unchanged/failed/uncertain/superseded。clear不误清其他ID。 |
| recoverSelection(intent) / retrySelection(currentContext) | 核验原意图真实落盘/无残留写；仅补当前仍适用的记忆，不保存/加载、重置副本或重放历史回执。 |
| StartupCoordinator.start/retry | coalesce，同一新会话只有一个恢复链；初始化→选择→真实快照应用→必要记忆，合法空库settled；读取错误保留重试或手动模式，选择明确写失败可就绪并警示。 |
| 用户菜单操作协调层 | 成功菜单结果与记忆结果分开，保持busy直到本轮必要步骤完成；selection=uncertain与repository.uncertain共同约束持久操作，selection=unavailable不误报整个菜单库损坏。 |
| inspect/测试观察 | 可观察selectionStatus/revision/当前权威意图、menu阶段、session/choice代次，不在用户界面展示存储key/回执等实现细节；不记录凭据或私有配置。 |
