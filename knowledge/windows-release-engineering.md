# Windows 发布与供应链工程

用于把已验证的 Windows x64 应用构建转成可安装、可追溯、可恢复的发布候选。具体安装器、签名主体、证书、渠道、最低 Windows 版本和发布时间由项目决定提供。

## 发布输入与冻结

发布候选必须引用源代码提交、构建预设、工具链元组、Qt 与第三方依赖清单、测试结果和已确认产品版本。只从受控构建产物建立部署暂存，不从开发机任意目录捡取 DLL 或插件。

输入缺少版本、哈希、许可证、架构、运行库或测试证据时停止候选冻结并记录责任人。发布工程不通过复制系统 DLL、关闭校验或修改测试预期绕过问题。

## 部署与安装事务

应用、Qt、插件、编解码与运行库部署到应用私有布局，明确搜索路径和模块白名单。安装、升级、修复和卸载规定用户项目、设置、缓存、临时文件及日志的保留或清理边界；失败要能回滚或保持上一成功版本可用。

在干净、受支持的 Windows x64 环境验证安装、首次启动、打开项目、核心工作流、卸载和重装。最低系统版本未确认时只能报告已测环境，不能宣告完整兼容。

## 许可证、SBOM 与签名

维护每项依赖的名称、版本、来源、哈希、许可证、链接方式和随包文件，生成可追溯 SBOM 与许可证材料。对动态链接、源码取得方式和用户替换要求按项目许可证基线准备文档，但工程清单不替代法律意见。

签名流程隔离凭据与普通构建，日志不输出密钥或令牌。只有明确授权的主体和环境可以执行签名；未签名候选与正式签名产物必须清楚区分，签名成功也不等于批准发布。

## 验证与交付

验证产物哈希、签名状态、运行时依赖、安装事务、权限、回滚、磁盘不足和被占用文件等路径。交付部署脚本、安装器配置、SBOM、许可证包、签名流程说明、干净环境记录和已知限制，由测试和最终确认流程决定是否可发布。
