# 项目决定

## D-006：Windows 原生编译器工具链
- 状态：proposed
- 提出者：architect-01
- 问题与候选方案：D-005 要求从源码构建 Qt，但 Qt 源码不包含 C++ 编译器。Qt 6.11 官方支持 Windows x86_64 使用 MSVC 2022 或 MinGW-w64 13.1；当前环境没有已确认可用的 MSVC 工具链，需要决定是安装 MSVC 2022 Build Tools，还是把 Qt、应用和全部原生依赖统一切换为 MinGW-w64 ABI。
- 确认人：PROJECT 默认最终确认人，即提出建项请求的本会话用户。
- 结果：尚未确认。architect-01 推荐安装 MSVC 2022 Build Tools、x64 C++ 工具和匹配的 Windows SDK，再以同一工具集从源码构建 Qt 及本项目；若 MSVC 明确不可安装，则选择 Qt 所支持的 MinGW-w64 版本，并使用同一 MinGW 工具链重编 Qt、应用、FFmpeg、OpenCV 及其他进入同一进程的 C/C++ 依赖。禁止混用 MSVC 与 MinGW C++ ABI。
- 确认来源与日期：尚无；本记录由 architect-01 于 2026-09-07 依据用户说明当前没有匹配的 MSVC 工具链、需要从源码编译 Qt，以及 Qt 官方 Windows 源码构建要求提出，等待用户确认。
- 适用范围与影响：影响 Qt 源码构建、vcpkg triplet、第三方二进制可复用性、调试符号、CI 镜像和应用部署；未确认前可以准备源码与构建说明，但不能启动可复现的 Qt 正式构建或冻结原生依赖。
- 替代关系：无；细化 D-003 的 Windows 工具链待确认项。
- 记录人及更新日期：architect-01，2026-09-07。

## D-005：Windows x64 与 Qt 源码构建基线
- 状态：confirmed
- 提出者：PROJECT 默认最终确认人，即提出建项请求的本会话用户。
- 问题与候选方案：D-004 已限定 Windows，但 CPU 架构和 Qt 获取方式仍未确定。候选为 x64 或 ARM64，以及使用 Qt 预编译包或固定源码自行构建。
- 确认人：提出本次架构与构建要求的本会话用户。
- 结果：第一阶段只生成 Windows x64（`x86_64`）产物，不生成 x86、ARM64 或 ARM64EC 版本；Qt 不使用预编译二进制包，必须从固定版本的官方源码自行配置、编译和安装。Qt 源码、构建目录与安装目录分离，构建配置、工具版本、源码版本/哈希和安装清单必须可追溯。Qt、应用及同进程原生依赖必须采用兼容的编译器和运行时 ABI。
- 确认来源与日期：本会话用户于 2026-09-07 明确表示“Qt 匹配的 MSVC 工具链也没有，需要从零开始编译qt源码，架构就x64”。architect-01 依据其中明确的源码构建和 x64 要求记录；编译器选择另见 D-006 proposed。
- 适用范围与影响：影响 A-004、A-005、Qt 获取与构建流水线、第三方依赖、CI 缓存、调试和部署；不确认 Qt 确切版本、许可证路径、Windows 最低版本或最终编译器。
- 替代关系：补充 D-004 的 CPU 架构与 Qt 供应方式，不替代 D-001～D-004。
- 记录人及更新日期：architect-01，2026-09-07。

## D-002：界面框架与算法实现语言基线
- 状态：confirmed
- 提出者：PROJECT 默认最终确认人，即提出建项请求的本会话用户。
- 问题与候选方案：A-004 0.1 将 Qt/C++ 作为候选实现栈，但尚未确定界面框架和算法实现语言。用户先明确“界面使用 Qt，算法使用 C/C++”，随后在了解 Qt Widgets 与 Qt Quick/QML 的差异后明确采用 Qt Quick/QML。具体 Qt/C/C++ 版本、编译器和许可证路径仍需后续技术设计和发布约束确认。
- 确认人：提出上述技术方向的本会话用户。
- 结果：本项目第一阶段界面层采用 Qt Quick/QML，QML 负责视图、布局、状态绑定和交互，Qt/C++ 适配层负责 ViewModel、模型和应用服务；算法核心采用 C/C++，公共契约不暴露 QML 或 Qt UI 类型。长时解码、分析和导出置于后台 worker。不得把媒体分析、DSP 或大数组处理移入 QML/JavaScript。
- 确认来源与日期：本会话用户于 2026-09-07 明确表示“我的想法界面使用qt，算法使用c/c++来实现”；在收到 Qt Widgets 与 Qt Quick/QML 的区别及选型理由后进一步回复“OK，我理解了那就使用Qt Quick/QML”，确认界面形态。architect-01 依据两次直接技术方向记录。
- 适用范围与影响：影响 A-004、A-005、后续原型、代码目录、构建系统、模块依赖和测试边界；不批准尚未确定的第三方库版本、许可证方案或生产部署，目标平台另按 D-004 执行。
- 替代关系：无。
- 记录人及更新日期：architect-01，2026-09-07。

## D-001：第一阶段目标用户与主验证路径
- 状态：confirmed
- 提出者：product-manager-01
- 问题与候选方案：需要确认第一阶段首先服务谁，以及优先验证哪条价值路径。候选主路径为：A. 音频输入后自动生成可导出视觉视频；B. 视频输入后自动生成卡点节奏音轨；C. 用统一节奏事件时间线做轻量双向闭环，两侧都只覆盖最小能力。结合 A-003 0.1，产品经理将建议细化为“B 为主、A 为辅”：以视频到可编辑节奏音轨作为差异化主流程，同时用同一事件时间线提供少量音频驱动视觉模板；不在第一阶段生成完整歌曲，也不复刻参考软件的专业合成器、效果器和集成矩阵。
- 确认人：PROJECT 默认最终确认人，即提出建项请求的本会话用户。
- 结果：第一阶段聚焦需要快速制作卡点内容的桌面音视频创作者，采用独立桌面应用；以“视频到可编辑节奏音轨”为差异化主流程，以“音频到少量视觉模板”为配套流程，共用节奏事件时间线。第一阶段不生成完整歌曲，不纳入 VST3、Blender/GPLA、专业合成器、复杂效果器或现场演出集成。
- 确认来源与日期：本会话用户于 2026-09-07 在收到上述明确方案后回复“OK，把你生成的内容提交一把”，确认采用该方向并要求提交记录。
- 适用范围与影响：影响 T-002、A-002、后续技术可行性评估、原型范围与验收样例；确认前不视为项目最终范围。
- 替代关系：无。
- 记录人及更新日期：product-manager-01，2026-09-07；同日依据用户明确回复将状态更新为 confirmed。
