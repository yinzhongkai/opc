# 个人记账应用

## 目标

开发支持收支记录、分类、统计和数据导出的个人记账应用。本目录是组织方式示例，尚未开始实际开发。

## 示例范围与待确认输入

第一阶段暂按 Web 应用安排前后端分工，覆盖记录收入支出、分类管理、按时间与分类统计、导出数据。真实银行接入、投资交易、税务申报和生产发布暂不纳入示例计划。

这些是模板假设，目标用户、平台与范围仍需用户确认。技术栈、数据存储、身份验证方式、隐私要求、运行与部署环境尚未决定；不得把模板分工当作已经通过技术选型。

## 交付物与位置

- 需求、验收标准、架构与接口契约：artifacts/。
- 软件实现：项目下 src/frontend/ 与 src/backend/，待开发任务启动时创建。
- 单元测试与构建配置：遵循确认后的工程结构。
- 测试报告、运行说明与评审：artifacts/。

## 协作边界

前后端以架构师形成的接口契约协作。前端成员维护界面与前端测试，后端成员维护服务端并协调集成运行；接口变化先交架构师确认并通知关联成员。项目经理协调依赖，测试与独立评审分别由对应成员会话完成。

验收标准由产品需求任务形成并确认后作为后续工作的依据。

## 岗位与知识组合

项目经理采用通用 project-manager 岗位，并补充软件研发基础。frontend-dev-01 与 backend-dev-01 均采用 developer 岗位，共享软件工程、前端开发和后端开发知识，通过成员 scope 分别负责界面和服务端；同岗位不等于任务可互相接管。
