# Qt Quick/QML 界面设计与工程

用于把桌面创作工具的用户流程实现为 Qt Quick/QML 界面。具体 Qt 版本、组件风格、产品流程和验收要求由项目决定提供；本知识不把候选设计自动视为产品批准。

## 先定义用户流程和状态

从导入素材、分析、编辑、试听、保存和导出等关键路径建立信息架构、线框图和界面状态表。明确空闲、加载、处理中、可取消、失败、恢复和只读状态，以及每个操作对当前项目是否安全。视觉规范至少覆盖颜色、排版、间距、焦点、选中、禁用、错误和高 DPI 缩放。

先用 mock service 和稳定 DTO 验证工作流，不让后端尚未完成阻止页面与交互开发。原型与正式组件区分，临时数据不得静默进入产品逻辑。

## QML 与 C++ 边界

QML 负责布局、状态绑定、交互和轻量动画；C++ ViewModel、`QAbstractItemModel` 或等价适配负责领域数据、命令和服务调用。不要在 QML/JavaScript 中执行媒体解码、FFT、光流、逐像素或逐采样循环，也不要把 worker 或媒体层裸指针暴露给 QML。

跨边界对象明确所有权、线程、可空状态和错误语义。耗时调用异步执行，返回可取消作业句柄、进度和结构化错误；界面线程不阻塞等待 worker。

## 编辑器与高密度数据

时间线缩放、滚动、吸附、拖动、锁定、批量偏移、播放头和快捷键必须复用核心时间与命令契约。一次用户动作对应可预测的事务和撤销单元；显示用浮点坐标不能回写成持久化时间真值。

普通控件使用 QML 组件，高密度波形、频谱和大量事件交给批量绘制接口，不创建“一点一个 QML Item”。低层场景图实现由图形责任人维护，UI 只使用版本化渲染输入和交互命中接口。

## 可用性与验证

覆盖键盘导航、焦点、常见快捷键、高 DPI、不同窗口大小、长文本和可访问名称。错误信息包含失败阶段、项目是否安全、可执行恢复动作和诊断 ID。

测试分层覆盖 ViewModel 单元测试、模型契约、Qt Quick 组件测试和关键用户路径集成测试。视觉快照只用于发现差异，不能替代交互、状态和可访问性断言。

## 交付

交付交互稿、组件和状态规范、QML/C++ 边界、实际运行记录、测试及未覆盖项。涉及产品流程变更交产品负责人，涉及核心语义、媒体时间或渲染接口变化交对应责任人。
