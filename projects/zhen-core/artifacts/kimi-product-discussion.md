## 1. 逐轮讨论

### PM-01：提出四种属性

用户原话：

> 我想做一款名叫"振核"的产品，其主要包含以下4种属性。
>
> 1. 实用属性：有类似"番茄钟"定时的功能
> 2. 装饰属性：可以做为一个桌面摆件起到装饰作用
> 3. 娱乐属性：在酒吧、迪厅等场景，通过"振核"能让大家接收到统一的信号，从而随着信号一起摇摆
> 4. 收藏属性：基于区块链技术，来保证每个振核都是独一无二的产品

Kimi 生成《振核产品概念方案》，用振动串起场景，建议番茄钟保证高频使用、摆件增加曝光、酒吧互动制造峰值体验、收藏支撑稀缺溢价。建议先进入效率人群，再通过酒吧联名扩展，最后沉淀收藏人群。初稿还引入 NFC、基站和 NFT／数字藏品思路；NFT 方向随后被用户明确排除。

### PM-02：解释触觉创意原点

> 为什么会有这个想法，以酒吧的场景为例，基本就是声音加灯光，即听觉加视觉，而振核是在听觉视觉之外的感觉，让人们可以跟着震动的感觉来摇摆

Kimi 将该洞察概括为“第三感”，补入概念方案。它强调全场同步、广播通信、群体节奏和触觉体验，也建议番茄钟以振动提醒。关于人体感知、群体同步、延迟阈值等论述只是该对话中的解释，本记录不视其为研究证据。

### PM-03：仅振动输出与振动语言

> 是的，只考虑振动这一种触感，其他的功能通通不要。另外甚至可以把振动编排成一种"语言"，这样就能传递更丰富的信息了

Kimi 按此去掉屏幕、灯光与扬声器，将装饰价值转向工业设计。它提出四个编码维度：时长、节奏间隔、强度、质感；分直觉层和约定语义层；建议控制词汇量，并新增人际振动消息、DJ 触觉编排、独特振动签名和语言包订阅等用途。宽频马达是 Kimi 为“质感”提出的技术建议，新增功能不等于用户逐项批准。

### PM-04：明确不做 NFT

> 只是昨用区块链技术，不搞NFT

保留原话中的笔误，按语境理解为只使用区块链技术。Kimi 将方案改为区块链存证：出厂信息和签名哈希形成记录；不发行 NFT 或代币，不做二级交易；实物转手后追加流转登记，避免采用钱包、代币转移等表述。它同时调整了商业模式和路线图。对话中的“合规优势”与“无法伪造”不能代替法律或安全评估。

### PM-05：确认 Kimi 的产品经理角色

> 忘记说了，你的角色是产品经理

Kimi 认为已有方案偏创意企划，建议补充 MVP 定义、用户故事、P0/P1/P2、验收标准、竞品定位、指标体系和风险预案；建议先从 MVP 定义和用户故事开始。

### PM-06：继续整理 PRD

> 按你的建议来

Kimi 生成《振核 PRD V0.1：MVP 定义与用户故事》，状态写为“待评审”。其建议将 P0 收敛为番茄钟、手势、App 配置和 OTA，将语言中心、消息与链上存证放到 P1，将场域同步放到 P2 独立项目。用户同意继续整理文档，不等于 PRD 中随后出现的具体数字、功能划分和里程碑已全部批准。

## 2. 最终产品概念方案内容整理

页面文档标题为《振核（ZHEN CORE）产品概念方案》。下列内容属于 Kimi 的概念稿建议。

### 2.1 定位与语言

- 定位为仅以振动输出的实体硬件，承载计时、美学、场域共鸣与实物收藏。
- 装饰依赖造型、材质和工艺；振动既承担提醒与节拍，也可承担消息和身份体验。
- 语言维度：长短、间隔疏密、轻重，以及“嗡／咔”等质感。
- 直觉层通过快慢、强弱、渐强等表达感受；语义层用少量约定短句表达休息、集合等消息。
- 人际消息、DJ 触觉演说和每台设备的签名短句是稿中扩展用途。

### 2.2 硬件、应用与基站建议

| 部分 | 概念稿内容 |
|---|---|
| 外形 | 球体／多面体，约 6–8cm，磁吸底座；限定材质可包括金属、树脂、涂层 |
| 硬件 | 宽频线性马达、蓝牙 5.x、IMU、NFC、USB-C；无屏幕、灯光和扬声器 |
| 输入 | 旋转、拍击、握持等手势及 App |
| App | 计时设置与统计、语言编排与教学、好友消息、附近派对频道、编号与存证查看、流转登记 |
| 场域基站 | 接 DJ 编排，偏向私有 2.4GHz 广播；也提出手机临时主持家庭派对 |
| 其他 | 概念稿还写过日历联动、互动“人浪”和磁吸无线充电底座 |

这些建议未全部与用户的单充电口、立方体交互以及架构候选方案对齐。

### 2.3 存证、用户与商业

- 存证稿建议将编号、材质、批次、签名哈希、首次激活等信息写入联盟链，NFC 对应记录，实物转手追加登记。
- 不做 NFT、代币或二级交易；溢价来源建议为限定材质、编号、联名和签名体验。
- 目标人群建议包括效率办公／学生、夜店电音爱好者、收藏者、情侣／密友。
- 商业建议包括基础与限定硬件、B 端基站和租赁／联名、存证服务，以及语言包、消息和统计等 App 增值订阅。
- 风险包括多属性分散、场域延迟、马达供应与质感、夜店受众范围、语言学习成本和用户对上链的误解。
- 概念稿同时残留“二级市场想象空间”等与“不做二级交易”不一致的叙述；保留为待清理差异，不采纳为项目方向。

### 2.4 概念稿路线图

| 阶段 | Kimi 建议 |
|---|---|
| 0–6 个月 | 番茄钟摆件、直觉层振动语言、基础 App、小批量验证 |
| 6–12 个月 | 语义层与人际消息、联盟链存证、签名和限定款 |
| 12–18 个月 | 场域基站与 3–5 家酒吧试点 |
| 18 个月后 | IP 联名、音乐节、海外版本 |

这里是相对周期建议，没有用户确认的项目起始日或交付承诺。

## 3. PRD V0.1 内容整理

原文标题：《振核 PRD V0.1：MVP 定义与用户故事》。原文状态：待评审。以下保留该草稿的范围、用户故事和数字，供后续讨论，不表示采用这些验收标准。

### 3.1 MVP 假设

| 假设 | 验证建议 | 原稿通过标准 |
|---|---|---|
| H1：振动番茄钟有仪式感、用户会持续使用 | 种子用户试用 4 周 | 4 周留存 ≥30%，周均会话 ≥5 次 |
| H2：纯造型摆件有购买吸引力 | 众筹／预售页 A/B 测试 | 转化率不低于同类硬件均值；原稿未定义具体对标基线 |
| H3：马达触感足以支撑语言直觉层 | 与手机振动进行盲测 | 偏好率 ≥70% |

原稿写明任一假设不通过就复盘，不直接进入下一阶段。

### 3.2 功能优先级

| 级别 | 原稿范围 |
|---|---|
| P0 | 本机番茄钟；开始／结束／休息默认振动；拍击／旋转手势；App 设置、短句体验、统计；蓝牙与 OTA |
| P1 | 语言中心与自定义短句；人际消息；NFC 防伪、联盟链存证、振动签名 |
| P2 | 独立 To B 场域基站、DJ 编排、全场同步；限定款和联名运营 |

原稿排除屏幕、灯光、扬声器、语音助手、通知推送、健康监测、NFT、代币和二级交易；首阶段也不包含多设备组网。这里的 P2 划分尚未与架构稿统一。

### 3.3 全部用户故事（要点）

| 原编号 | 用户与目标 |
|---|---|
| US-01 | 专注工作者希望计时结束用轻振提醒，避免打断或打扰同事 |
| US-02 | 图书馆学生希望提醒没有灯光和声音 |
| US-03 | 用户希望拍击开始、旋转重置，不必拿手机 |
| US-04 | 用户希望查看每周专注统计 |
| US-05 | 桌面美学用户希望外观完整、无灯，像雕塑 |
| US-06 | 送礼者希望包装和开箱有仪式感 |
| US-07 | 夜店顾客希望和全场同步感受振动 |
| US-08 | DJ 希望向全场编排不同情绪的振动短句 |
| US-09 | 派对主人希望手机临时主持小范围同步 |
| US-10 | 收藏者希望碰一碰查验出生与流转记录 |
| US-11 | 收藏者希望体验设备独特的振动签名 |
| US-12 | 二手买家希望登记成为新主人，保持流转连续 |
| US-13 | 恋人／密友希望互发私有振动短句 |
| US-14 | 进阶用户希望编排并保存自己的短句 |

US-03 等手势描述尚未更新为用户提出的立方体翻面交互；US-07 的“同一毫秒”是体验叙述，尚无对应实测定义。

### 3.4 原稿验收数字

| 项目 | PRD 草稿写法 |
|---|---|
| 振动提醒成功率 | ≥99.9%，包括蓝牙断连后的本机兜底 |
| 计时精度 | 25 分钟误差 <1 秒 |
| 断连可用性 | 断连后番茄钟完整可用 ≥24 小时 |
| 续航 | 每日 4 次番茄钟的使用条件下 ≥7 天，稿中仍称“待机续航” |
| 马达寿命 | ≥100 万次；未给出单次振动定义与试验条件 |
| 振动启停响应 | <10ms；需定义如何测量起振、刹车和触感 |
| 手势识别 | 拍击 ≥98%，旋转 ≥95% |
| 触感偏好 | 相比手机振动的盲测偏好率 ≥70% |
| 新手使用 | 不看说明，3 分钟内完成首次番茄钟 |
| App 配置 | 开机、配对、设置在内 ≤3 步 |

这些数字是历史草稿门槛，尚无样本、测试结果、统计置信度或项目批准。

### 3.5 竞品与指标建议

原稿比较番茄钟 App（Forest、番茄 ToDo）、计时硬件（Time Timer、厨房计时器）、桌面潮玩、Apple Watch 触觉反馈及 NFT 潮玩，强调实体触感、摆件与语言扩展。该部分不是本次完成的市场调查。

北极星指标被命名为“日活跃振动会话数 DAVS”，但定义实际是“当天至少有一次交互的设备数”，名称与统计口径不一致。其他建议包括：

- 获取：转化率和获客成本对标同类硬件，具体基线待建立。
- 激活：开机 24 小时内首次番茄钟完成比例 ≥80%。
- 留存：4 周 ≥30%，周均会话 ≥5 次。
- P1 后观察消息对数与语义词汇使用；P2 后观察 B 端签约。
- 收入观察限定款售罄；传播观察邀请、K 因子和用户晒图，基线未设定。

### 3.6 风险预案与里程碑

| 风险 | 原稿触发信号 | 原稿建议 |
|---|---|---|
| 宽频马达良率 | 试产 <85% | 砍质感维度，采用三维编码与双供应商 |
| 番茄钟留存低 | 4 周 <20% | 提前消息功能，重新验证情侣／密友场景 |
| 酒吧试点冷淡 | 3 家场均使用率 <15% | 尝试 Livehouse、电竞馆、影院等 |
| NFT 认知误解 | 出现相关负面反馈 | 强调防伪证书，调整传播表达 |
| 无屏学习难 | 新手任务完成率 <70% | 增加 App 动画和振动教学 |

| 节点 | 原稿内容与出口 |
|---|---|
| M1 | PRD 与硬件 ID 冻结；产品、研发、供应链确认 |
| M2 | EVT、马达选型和短句演示；盲测 ≥70% |
| M3 | DVT、App 内测与 OTA；技术指标达标 |
| M4 | 500–1000 台众筹／预售，验证 H1–H3 |
| M5 | 数据复盘，决定是否进入下一阶段 |

原稿最后建议固件、App、云端存证三线推进，但云端存证又被列在 P1，存在排期与范围需要解释的地方。以上角色、数量和里程碑不是当前 OPC 已配置成员或获授权任务。
