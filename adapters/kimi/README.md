# Kimi Work 使用方式

根据当前会话实际支持的方式，以项目文件、附件或可访问目录提供框架资料。本框架不假定 Kimi Work 可以直接读写电脑目录、自动同步文件或自动唤醒其他会话。

## 启动入口

从根 [AGENTS.md](../../AGENTS.md) 进入。管理员会话声明“你是超级管理员”，按 [SUPER_ADMIN.md](../../SUPER_ADMIN.md) 工作；成员会话使用管理员返回的启动消息，或以实际值替换占位符：

```text
框架根目录或资料包：<repository-root>
项目：<project-id>
成员：<member-id>
目标项目资料位置：projects/<project-id>/
请按 SESSION_PROTOCOL.md 初始化，并查看当前工作。
```

若当前使用方式支持项目公共指令，可放入 [PROJECT_INSTRUCTIONS.md](PROJECT_INSTRUCTIONS.md)；否则将其作为新会话的已提供资料，再追加身份声明。本说明不保证特定平台入口存在。

## 资料提供与同步

提供当前 clone 的根目录与目标项目位置，或保留原路径标识的文件副本。副本标明来源路径、版本或提供时间，并说明资料包覆盖的项目范围；仅提供一个项目不代表仓库只有一个项目。

身份解析、知识加载和项目资料的分层读取按 [会话协议](../../SESSION_PROTOCOL.md)，根据当前所需层次提供资料，不把全部历史文件作为固定上传清单。字段规则见 [CONFIG_SCHEMA.md](../../CONFIG_SCHEMA.md)，建项与工作流见 [项目运行协议](../../PROJECT_PROTOCOL.md)。

用户负责当前仓库每次只有一个会话执行，并在本轮全部评审意见提交前保持受评版本可读取且不变；具体约定以项目运行协议为准。附件副本也须使用同一受评版本，框架不提供会话锁或自动同步。

缺少所需资料时列出具体缺口。无法写文件时，输出目标路径和建议内容，明确尚未保存，交由用户或有权限的会话写回；不可将附件副本的变化描述为仓库已同步。实际文件访问与写回能力以当前会话为准。
