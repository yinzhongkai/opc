## 1. 正文围绕眼前的代码和操作展开

- 以第 4 章 4.2 节为本轮语言参照：句子简洁，先给代码，再解释代码做了什么、为什么这样设置。
- 小节开头紧扣标题。查找配方、浏览文件、阅读模型、接入 patch、构建启动分别在对应小节展开，避免提前塞入后面才需要的操作。
- 删去重复的路线预告和交叉引用，例如“后面某节还会检查这里”“看到输出就能确认已经执行到 main”。需要跨章查阅时保留有用的引用。
- 背景辨析、缩写释义适合放在紧邻代码的提示中；正文已经说明的环境和前提不再另起提示重复。RVBAR 的解释最终放在 4.2.3 节末。
- 技术分析直接叙述。对话用于引出问题即可，不为解释一组寄存器值额外安排人物问答。
- 用具体动作代替抽象说法，例如“启动汇编调用 `main`”，比“进入 C”清楚。解释 CPU 属性时，逐项对应代码中的属性名，避免提到代码里没有设置的参数。

## 2. 示例要够读者对照，解释按功能组织

- 核心操作应贴出实际代码，例如创建 CPU 的调用，不能只给文字结论。
- 文件较短且需要逐段理解时，按源码顺序拆成完整的功能段，再解释各段作用。4.3.3 的 `main.c` 采用这一方式，避免只解释文件的一部分。
- 链接脚本和 `start.S` 优先把简短说明放在对应代码行后；注释已经解释清楚时，删去重复表格。
- 对属性、寄存器和链接语法的解释要落到当前代码。比如说明数据的装载地址和运行地址时，要对应具体输出节、边界符号及启动汇编中的复制操作。
- 聊天中应用户要求作出的额外答疑，先在会话中解释；用户明确要求补入文章时再写入正文。

## 3. 代码与图表排版

- 代码块围栏外前后各留一行空白；围栏内首尾紧贴内容，不额外塞入一两行空白。代码内部为分组保留的空行按需要使用；真实输出本身的空白遵循 A-004 原文保真规则。
- 示例代码不为页面宽度手动折行，实际源码同步采用相同写法。单条打印语句、链接脚本中的节定义及构建命令保持完整一行。
- 配置清单按内容组织：`SRC_URI` 中多个文件采用续行形式，一个文件一行。此项与上一条的单条语句排版分别处理。
- 行尾注释纵向对齐，注释自身不截断成下一行。目录说明前加 `#`；C 和汇编使用对应语言的注释符。
- 目录清单参考 `tree` 输出，使用分支线和缩进表示父子关系，不用空格堆成平铺文件列表。
- 框图检查对应竖线和边框的列位置；目录注释对齐按等宽显示宽度检查，不只数源码字符。

- 读者从前几章的 Poky 环境和同一个 `meta-tiger` 仓库开始，使用对应章节标签。正文不能依赖作者私有工作区中恰好已有的源码或历史。
- 使用书中约定的正常路径，保留读者可以照抄的命令。随机测试目录、临时后缀和为验证而建的独立构建树放在核验证据中，不带入操作主线。

- 命令优先选择能直接回答当前问题的形式：查配方位置用 `devtool find-recipe qemu-system-native`；查追加文件用 `bitbake-layers show-appends qemu-system-native`。需要 `bitbake -e` 时筛出目标变量，避免整屏环境输出。
- 需要读者判断结果的命令应给出实际输出的关键行，并说明观察对象。正文不反复加“实测”字样，原始核验证据仍按 D-010 保留。

- 前置条件说明具体原因和适用环境。涉及网络、设备权限等要求时，先核对实际启动流程，再决定是否需要放入正文。

- 改函数名、文件名、目录、Makefile 或 patch 中的代码时，同步实际工程、代码节选、构建命令、输出文件名和后文引用。
- 删除或移动小节后，检查本章和其他章节的旧节号，尤其是把 devtool 内容移到 chapter 15 后留下的引用。
- 描述任务依赖时，先展示实际配方，再解释每个任务的职责、输入、产物和先后关系。4.5 对 `do_write_qemuboot_conf` 与 `do_deploy` 的解释采用这一方式。

## 6. 第 4 章已经采用的具体取舍

以下内容保留适用范围，后续章节按实际学习目标决定是否沿用。

- 固件只演示 UART 初始化和打印。移除 `TIGER_BUILD_ID`、自定义摘要/标记、额外异常判断和验证框架，使读者先看清串口主线；后续章节有相应教学目标时再引入检查逻辑。
- 构建使用简洁 Makefile，删除 `build-minboot.py` 等 Python 构建辅助脚本；配方继续负责 BitBake 集成。
- C 入口统一为 `main`。配方采用 `minboot` 和 `minboot-image`，去掉重复的 `tiger-` 前缀。
- 最终保留 `TIGER_ASSET = "minboot-${PV}-${MACHINE}"` 和 `IMAGE_NAME = "${PN}-${MACHINE}"`，构建产物保留机型后缀。用户此前提出过删除，随后已明确要求恢复，以最终结果为准。
- 固件配方构建、部署固件；镜像配方使用标准 `qemuboot` 类生成并部署启动配置。不要在固件配方中另写一套配置生成逻辑。
- 4.5 聚焦裸固件的构建、部署和 `runqemu`，MACHINE 的详细教学留到 chapter 5。
- 删除本章完整 devtool 开发练习、单独修改问候语的练习以及“踩坑实录”；4.6 保留手工观察启动、UART 和复位。工程 `tests/` 已按用户要求归档移除，证据见[清理与命名同步记录](server-workspace-cleanup-20261120.md)。
