# 读者学习反馈与修订

适用于接收试读、学习或使用反馈，并在本岗位范围内整理、修订或交接问题。不要求读者承担台账维护，不因读取本知识而接管其他成员的实现或评审。

## 接收与定位

接受自然语言、截图、日志、操作结果和疑问。先保留反馈者、时间或消息来源、章节标识、所读版本、位置以及原始描述；能从上下文确定的信息不重复问。不能定位时只补问影响判断的缺口。

理解疑问不强制提交运行环境；操作问题按需补齐环境、示例版本、步骤、预期和实际结果。观察、用户解释和 AI 推断分开，整理摘要不能替换原始证据，也不把“没有收到反馈”当作理解或通过。

## 分类与处理

| 问题 | 处理方向 |
|---|---|
| 解释不清 | 补理由、例子、术语说明或调整表述 |
| 前置知识缺失 | 检查蓝图与目录依赖，提出补充或调整建议 |
| 技术或示例错误 | 交专业成员定位，保留最小复现及修复证据 |
| 环境差异 | 核对适用条件，补充替代步骤或明确不支持范围 |
| 范围争议 | 提出选择及影响，请有权者确认 |
| 框架缺口 | 记录具体事件与重复成本，提出通用改进建议 |

读者现象不一定意味着书稿错误，先验证原因，不归咎读者也不盲目改书。跨成员行动、任务安排和管理员请求走公共协议；问题分类本身不构成指派权。

## 修订闭环

问题使用章节内稳定编号，记录原版本、处理说明、修订版本、复核者与依据；只链接原任务中的评审和批准，不复制一份结论。新反馈关联到已完成任务时，按公共协议新建任务或经授权重开，不静默继续旧任务。

验证修订是否解决原问题：理解问题可请读者解释或尝试一个变式；操作问题复跑受影响步骤；跨章修改检查引用和前置依赖。读者尚未复试时明确待反馈，不因已作答或改过文字而关闭问题。非阻断建议可经确认留待后续处理，保留理由。

## 学习记录与使用边界

学习记录描述实际表现和未解决疑问，不用单一分数或“已掌握”代替证据。照做成功、能够解释、能够迁移应用分别记述；是否要求全部达到由本书目标决定。

将个人经历写成面向读者的案例前核对事实，区分真实经历、教学演示与推测。日志和截图用于对外书稿时检查隐私、凭据及发布范围；保留经授权的原始材料与脱敏副本对应关系。
