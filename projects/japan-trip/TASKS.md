# 任务

以下是初始示例任务，均未启动。每项任务由具体成员 ID 负责；完成条件需结合实际项目澄清后确认。

- [ ] `TRIP-001` 收集日期、人员、预算和偏好；负责人：`project-manager-01`
  - 完成条件：关键旅行输入明确，剩余未知项记录清楚。

- [ ] `TRIP-002` 研究目的地、交通与时效信息；负责人：`researcher-01`；依赖：`TRIP-001`
  - 完成条件：形成有来源、核对时间和适用条件的资料清单。

- [ ] `TRIP-003` 编排行程、预算与备选方案；负责人：`planner-01`；依赖：`TRIP-002`
  - 完成条件：方案满足已确认约束，移动时间、费用口径与待预订事项清晰。

- [ ] `TRIP-004` 独立评审可执行性与准备度；负责人：`reviewer-01`；依赖：`TRIP-003`
  - 完成条件：核对约束、依据和未确认项，形成明确评审结论。

成员直接在自己负责的任务下更新状态、进展、产物链接和阻塞；需要独立验收的任务区分自报完成与已验收。项目经理维护任务增删、负责人、依赖、优先级、范围和完成条件，并汇总项目状态。普通进展无需重复写交接；需要其他成员行动或接手时再记录 HANDOFFS.md。

发现问题后由对应成员修订并复测，不将依赖任务完成等同于后续验收通过。负责人停用时，保留已完成任务历史和未完成工作，注明待重新分配；项目经理随后安排接收者并记录接收确认。任务转交不阻碍成员直接停用，停用也不会自动完成任务。
