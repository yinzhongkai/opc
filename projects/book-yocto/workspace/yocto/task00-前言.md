# 前言

这是一本任务驱动的嵌入式 Linux 实战指南。你将跟随一个完整的项目，从零开始为一块虚拟开发板搭建全套软件栈——从模拟硬件到启动链、内核、文件系统，再到镜像发布。书名中的 "Yocto BSP" 会在后续章节逐步展开，现在你只需要知道：我们用的是一套工业界主流的项目构建框架，目标是做出一块能真正启动的板子支持包。

## 1. 为什么写这本书

市面上的 Yocto 书籍大致分两类。一类按知识域组织——BitBake 一章、Layer 一章、Kernel 一章——读完后你有了知识地图，却依然不知道一个真实的 BSP 项目从头到尾怎么走。另一类是 Cookbook 风格，提供大量操作配方，照着做能成功，但一出错就不知道为什么，因为书中没有呈现决策过程和踩坑经验。

我在学习 Yocto 的过程中踩过大量类似的坑。花了三天搞懂某个变量为什么生效，一周后遇到另一个场景又发现理解错了——这种"知道碎片却拼不出全貌"的痛苦让我意识到，需要有一本书按真实工程任务的顺序推进，把"为什么这么做"和"怎么做的"放在一起讲。比如我曾以为 `DEPENDS` 能解决所有依赖问题，直到某次构建报错提示找不到 native 版本的库，才意识到交叉编译环境里"target 依赖"和"native 依赖"是两条完全不同的路径。这类教训如果只是零散地记在笔记里，下次换个人、换个场景，照样会再踩一遍。

本书的写法与市面书籍有七点不同，这些差异贯穿全书：

- **按任务顺序推进**，不按知识点分章——你面对的是"启动链怎么串起来"，而不是"U-Boot 有哪些配置项"
- **完整的虚拟硬件栈**——不需要任何真实开发板，用 QEMU 模拟一块 ARM Cortex-A53 板子
- **真实的启动链路**——覆盖 TF-A、U-Boot、Kernel、UBI rootfs 的完整链条
- **NAND + UBI 存储方案**——消费电子产品的主流选择，市面书籍极少涉及
- **多仓库工程组织**——4 个开发仓库加 1 个集成 layer，建立正确的工程直觉
- **明确的边界感**——讲清楚什么该进 Yocto、什么不该进，这是从 Buildroot 迁移过来的第一道坎
- **发布合规与交付**——版本固定、可重现构建、license 清单、SBOM，这些不是选修课

此外，每章末尾都有 git tag，你可以随时 checkout 到对应状态排查问题。跟着书做遇到构建失败时，这是最有用的兜底手段。

## 2. 这本书适合谁

本书的主受众是芯片厂、模组厂和 ODM 厂的 BSP 工程师——特别是 Yocto 新手，或正从 Buildroot 迁移过来的工程师。

阅读本书之前，你需要熟悉 Linux 命令行、git 基本操作和交叉编译的概念。但**不需要**有 Yocto 经验，也**不需要**准备任何真实硬件。如果你符合以下描述，这本书适合你：

- 你知道 `make menuconfig` 是做什么的，但还没系统接触过 BitBake
- 你用过 Buildroot 搭过根文件系统，现在想理解 Yocto 的工程组织方式
- 你的项目需要处理 NAND Flash、启动链集成或开源合规，但找不到系统的中文资料
- 你想在硬件回来之前，先把软件栈跑通——这是嵌入式行业常见的"软硬件并行开发"模式

## 3. 怎么读这本书

本书的章节前后有依赖关系，建议按顺序阅读，不建议跳读。

每章末尾会标注对应的 git tag。正文章节使用 `chapter1`、`chapter2` 这样的命名，边界章节（前言、序章、尾声）使用 `preface`、`prologue`、`epilogue`。如果你在实操过程中遇到构建失败，可以随时 checkout 到对应 tag 对比排查。

全书项目围绕一个代号为 tiger 的虚拟开发板展开。项目涉及以下代码仓库：

- `meta-tiger/` —— tiger 的 BSP layer（集成态）
- `linux-tiger/` —— 内核补丁仓库（开发态）
- `qemu-tiger/` —— QEMU 补丁仓库（开发态）
- `tf-a-tiger/` —— TF-A 补丁仓库（开发态）
- `u-boot-tiger/` —— U-Boot 补丁仓库（开发态）

此外，构建时还需要 Yocto 官方的 `poky/` 参考发行版作为上游依赖，需从 Yocto Project 上游仓库克隆。`poky/` 本身不是 tiger 项目自有的仓库，而是整个构建系统的基础框架。本书的 4 仓库 + 1 layer 工程组织方式，会在后续章节详细展开。

建议在 Ubuntu 24.04 LTS 环境下实操。你可以使用 Docker 容器运行 `ubuntu:24.04` 镜像（即 Ubuntu 24.04 LTS 的 Docker 官方镜像标签），也可以直接在物理机或虚拟机上安装。Docker 环境能最大程度减少"我的环境和书不一样"带来的问题，但不是强制要求。
