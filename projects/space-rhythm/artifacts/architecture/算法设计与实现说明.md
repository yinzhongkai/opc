## 2. 核心数据模型

### 2.1 逐样本点

统一数据类型：

```cpp
struct BeamPoint {
    float x = 0.0f;
    float y = 0.0f;
    float z = 0.0f;   // 几何深度
    float brightness = 1.0f;
    float r = 0.0f;
    float g = 0.0f;
    float b = 0.0f;
    bool hasRgb = false;
    bool breakBefore = false;
};
```

必须区分三种情况：

- `hasRgb == false`：没有逐点颜色，渲染器使用全局束流色；
- `hasRgb == true` 且 `r,g,b == 0`：明确指定黑色；
- RGB 已指定：保留原三通道，并使用显式亮度字段。需要复现参照实现时，由适配器把 `max(r,g,b)` 的亮度解释转换为该字段。

点块可使用 SoA（分通道连续数组）：`X[]、Y[]、Z[]、Brightness[]、R[]、G[]、B[]` 加颜色有效性与断线标记。效果器内部可按样本临时组装 `BeamPoint`，热路径优先使用便于批量计算的平面缓冲。参照格式复用 Z 表示亮度或使用负色值哨兵的行为仅在输入适配器解释，核心遵循 TRD 的显式字段契约；上述结构不定义跨 DLL ABI 布局。

### 2.2 路径段

```cpp
class ICurveSegment {
public:
    virtual BeamPoint evaluate(float t) const noexcept = 0; // t ∈ [0,1]
    virtual float length() const noexcept = 0;
    virtual Bounds3 bounds() const noexcept = 0;
};
```

帧为有序段列表，并预计算：

- 每段长度 `L_i`；
- 前缀和 `S_i = Σ(k<i)L_k`；
- 总长 `L = ΣL_i`；
- 包围盒、颜色存在性和消隐/断线标记。

参照实现逐段推进并携带超调量；Qt 实现建议用前缀和维护当前索引，随机定位时二分查找，顺序播放时保持 O(1) 增量推进。

### 2.3 快照与时间

- `GeometryFrame`：不可变、引用计数、含路径和预计算表；后台线程构建。
- `EffectChainSnapshot`：不可变效果拓扑；音频线程仅原子切换指针。
- `ParameterBlock`：块起点参数和必要的逐样本调制缓冲。
- 所有音频、几何帧和视频帧使用单调样本位置 `samplePosition`；显示时间由 `samplePosition / sampleRate` 推导。

## 3. 从路径到音频的主算法

这是 osci-render 最核心的转换。

### 3.1 等速走线

设一帧总路径长度为 `L`，目标重复频率为 `f`，采样率为 `Fs`，则每个音频样本沿路径前进：

```text
Δd = max(L × f / Fs, Δd_min)
```

等价于参照实现的：

```text
Δd = L / (Fs / f)
```

逐样本流程：

```text
for each output sample:
    seg = frame.segments[current]
    t = (seg.length > 0) ? distanceInSegment / seg.length : 1
    p = seg.evaluate(clamp(t, 0, 1))
    distanceInSegment += Δd

    while distanceInSegment >= seg.length:
        distanceInSegment -= seg.length
        current = current + 1
        if current == segmentCount:
            current = 0
            frameSync = true

    p = effectChain.process(p, context)
    p *= voiceEnvelope × velocityGain × killFade
    write/add p to XYZRGB output
```

零长度段必须跳过，并设置单帧最大跨段次数，避免损坏文件形成无限循环。若 `L≈0` 或 `f≤0`，输出静音/中心点，不得产生 NaN。

### 3.2 参考兼容与改良

| 项目 | 参照行为 | Qt 实现要求 |
|---|---|---|
| 曲线速度 | 依赖各段 `length()` 估算 | 使用自适应弧长表，屏幕速度更均匀 |
| 跨段 | `while` 携带超调距离 | 保留；加零长段和最大迭代保护 |
| 帧边界 | 产生 frame-sync 脉冲 | 保留，供 Trace/Dash 等状态效果复位 |
| 大量小段 | 顺序线性推进 | 顺序 O(1)，跳转用前缀和二分 |
| 新帧供给 | 后台队列约 10 帧 | 固定容量 SPSC 队列；过载丢旧帧还是阻塞须配置 |

## 4. 几何基元与空间变换

### 4.1 直线、二次和三次 Bézier

直线：

```text
P(t) = P0 + t(P1-P0)
length = ||P1-P0||₂
```

二次 Bézier 的控制点为 `P0、P1、P2`，可直接求值或升阶为三次：

```text
C1 = P0 + 2/3(P1-P0)
C2 = P2 + 2/3(P1-P2)
B(t) = (1-t)³P0 + 3(1-t)²tC1 + 3(1-t)t²C2 + t³P2
```

参照实现对三次曲线长度采用只看端点差的快速近似，控制点对长度影响不足；Qt 实现必须使用递归细分或高斯求积建立 `(t, cumulativeLength)` 表，再以弧长反查 `t`。建议容差为归一化空间 `1e-4`，并允许质量档位调整。

### 4.2 圆弧

```text
θ(t) = θ0 + tΔθ
P(t) = C + (rx cos θ(t), ry sin θ(t))
```

圆的精确长度为 `r|Δθ|`；椭圆弧使用数值积分。内部字段使用明确的 `startAngle + sweepAngle`，不要沿用容易混淆的“endAngle 实为增量”命名。

### 4.3 变换

点依次应用缩放、X/Y/Z 旋转、平移。必须在项目格式中固定旋转顺序和矩阵约定。建议：右手坐标系、列向量、局部变换 `M = T·Rz·Ry·Rx·S`，导入 GPLA 时单独适配其行主序 3×4 约定。

透视投影：

```text
f = 1 / tan(FOV/2)
x_screen = f × x_camera / z_camera
y_screen = f × y_camera / z_camera
```

参照代码不同模块同时存在“前方为正 z”和 Blender“前方为负 z”的约定。Qt 实现的相机层必须统一符号，只在适配器处转换，并正确裁剪穿越近平面的线段。

### 4.4 包围盒、归一化和裁剪

参照实现对部分曲线只抽样少量点求边界，并出现用 `numeric_limits<float>::min()` 初始化最大值的风险。Qt 实现要求：

- 直线取端点；Bézier 求导数根或以弧长细分表求保守边界；
- 最大值初始化为 `lowest()`；
- 统一居中，等比缩放到可配置安全范围，默认约 `[-0.9,0.9]`；
- 直线裁剪用 Liang–Barsky/Cohen–Sutherland；曲线先自适应展平再裁剪；
- 越界连接不得只看端点后粗暴删除。

## 5. 素材生成算法

### 5.1 OBJ：边图与中国邮路

参照流程：

1. 解析 OBJ 顶点、面和 `l` 线，不强制三角化。
2. 顶点减去质心；按最大半径缩放，留约 1/1.2 的边界余量。
3. 从每个面的相邻顶点提取无向边，对重复边去重；合并显式线边。
4. 找图的连通分量。
5. 每个分量按欧氏边长求中国邮路，使每条边至少走一次且重复距离尽量小。
6. 把顶点序列转换为直线段。

Qt 实现建议：

- 全为偶度顶点：Hierholzer 算法直接求 Euler 回路，复杂度 O(E)。
- 存在奇度顶点：求奇点间最短路，再做最小权完美匹配，把匹配路径复制后求 Euler 回路。
- 多个连通分量：把每条分量路径看作可正反的任务，用“最近端点 + 2-opt”减少消隐跳线。
- 大模型提供快速近似模式，避免一般最小权匹配的成本失控。
- 保留“绘制边”和“消隐移动”两类段，不能用一条亮线跨越不相连组件。

### 5.2 SVG 与文字

参照实现把 SVG/JUCE Drawable 展成路径，处理 move、line、quadratic、cubic 和 close；Y 轴反转、等比缩放到约 1.8 的最大尺寸并居中。文字先取字形轮廓，再进入同一路径转换。

Qt 实现：

- 文字轮廓使用 `QRawFont::pathForGlyph()` / `QPainterPath`；
- SVG 若要得到真实路径几何，不能仅依赖 `QSvgRenderer` 的最终栅格绘制，应使用能保留 path/transform 的解析层；
- 展开所有层级变换、viewBox 和单位；保留闭合路径、洞、颜色与消隐移动；
- 使用曲线精确/自适应边界与弧长采样；
- 笔画排序同时考虑反向，并提供路径首尾连接策略。

### 5.3 GPLA / Blender 线稿

二进制协议以 8 字节字为基本单位，关键标签包括：`GPLA    `、三个 int64 版本号、`FILE`、帧数、帧率、`FRAME`、焦距、`OBJECTS`、`MATRIX`、`STROKES`、`STROKE`、顶点数、`VERTICES`、`DONE`、`END GPLA`。数值包含 little-endian int64 和 IEEE-754 double。

每点矩阵变换（参照的行主序 3×4 部分）：

```text
x' = x·m0 + y·m1 + z·m2  + m3
y' = x·m4 + y·m5 + z·m6  + m7
z' = x·m8 + y·m9 + z·m10 + m11
```

Blender 相机约定前方 `z'<0`，投影近似：

```text
x_screen = x' × focalLength / z'
y_screen = y' × focalLength / z'
```

参照实现只保留两端都在相机前的线段，且以“离上一终点最近的未访问笔画起点”做 O(n²) 贪心排序。Qt 实现需要：

- 使用显式小端读取和 `std::bit_cast`/`memcpy`，禁止指针类型双关；
- 每个计数、乘法、偏移和总消息大小都做溢出检查；
- 线段穿越近平面时执行裁剪，而非整段丢弃；
- 排序同时比较笔画的首、尾端，允许反转，再以 2-opt 改良；
- 兼容现有 Base64+换行的回环 TCP，同时定义长度前缀、版本、上限和校验和的新协议。

### 5.4 图片、GIF 与视频的随机寻迹

参照的 Hilligoss 风格算法不是传统 Canny 轮廓提取，而是把灰度像素当作“可被随机访问的亮点场”：

```text
eligible(pixel):
    gray > 0.2
    and random01() < gray^(threshold×10 + 1)
```

每次从当前像素出发，以约 10 像素半径和用户步长做向外方形螺旋，寻找最近的未访问合格点；找不到时最多随机尝试约 100 次。约每 5 ms 可随机跳转，以避免长期困在局部。像素坐标按长宽比等比映射到 `[-1,1]²`。

参照实现中有一个高风险表达式：`count % 10 * jumpFrequency() == 0` 按 C++ 优先级等于 `(count % 10) * jumpFrequency() == 0`，很可能不是设计者想要的 `count % (10*jumpFrequency()) == 0`。Qt 实现不得无意复制；建立两种测试模式：

- `LegacyCompatible`：只用于与旧输出比较；
- `Corrected`：按明确周期清理 visited/跳转，作为默认。

此外：

- 透明像素为 0；不能靠把纯黑强改为 1 来复用透明哨兵，应单独存 alpha/mask；
- 随机数支持固定 seed，便于黄金测试；
- 图片帧预处理在后台进行，音频线程只读不可变点序列；
- GIF/视频使用按需解码 + 有界 LRU 帧缓存，不一次把最多一万帧全部常驻；
- 完整版可增加 Sobel/Canny + 连通轮廓追踪，作为比随机点寻迹更稳定的新模式。

### 5.5 L-system 分形

输入为 JSON：axiom、angle 和单字符替换规则。每一层执行并行字符串重写：

```text
S₀ = axiom
Sₙ₊₁ = concatenate(rule(c) if exists else c, for c in Sₙ)
```

命令映射：大写字母（除 X/Y）=前进并画线，`f`=前进不画，`+/-`=转向，`[`=压栈位置/方向，`]`=出栈。海龟初始方向 90°，步长 1。一次遍历同时产生线段和边界，随后居中并按最大宽高缩放到 2.0。

参照限制为最多 16 次迭代、字符串最多约 3,000,000 字符，并缓存各层命令/线段。Qt 实现保留硬上限，但应在展开前用安全加法估算下一层长度、支持取消，并把缓存纳入全局内存预算。

### 5.6 音频文件

文件采样率 `Ffile` 到处理采样率 `Fs` 的重采样比为：

```text
ratio = Ffile / Fs
```

读取位置按输出块长度和比率推进；循环越界时回到 0。Qt 可用 `QAudioDecoder` 做有限格式解码，但为 WAV/AIFF/FLAC/OGG/MP3 的一致性建议抽象 `IAudioDecoder`，由 libsndfile/FFmpeg 等实现。重采样器要求：

- 各通道共享同一相位、独立滤波状态；
- seek 后重置滤波历史；
- 循环点可做极短等功率交叉淡化，且不能破坏 X/Y 相位关系；
- 离线渲染默认使用文件原采样率或用户指定采样率，避免重复重采样。

## 6. MIDI、声部与音高

### 6.1 音高

十二平均律：

```text
f(note) = A4 × 2^((note-69)/12)
pitchBendMultiplier = 2^(bendSemitones/12)
bendNormalized = (value14bit - 8192) / 8192
```

如启用微分音/MTS，最终频率来自 tuning 表；读取失败回退十二平均律。

### 6.2 Portamento

参照实现在线性时间中插值对数频率：

```text
f(t) = exp(ln(f0) + g(t,slope) × (ln(f1)-ln(f0)))
```

可选八度缩放时，滑音时长乘 `|log2(f1/f0)|`。`g` 是可调曲率的归一化单调函数。必须处理 `f0≤0`、同音和极短时长。

### 6.3 声部生命周期

- 复音 1–16；每个声部独立保存路径位置、主包络、调制包络、效果器状态、Lua 上下文和 kill fade。
- Note On：分配或窃取声部，装载当前不可变帧；非 legato 时复位包络。
- Note Off：进入 Release；延音踏板按 MIDI 语义延迟释放。
- 声部窃取：优先已释放且包络最低者；随后用短线性/等功率 kill fade，防止跳变。
- XYZ 叠加混音；RGB 不能简单相加到哨兵值。建议积累“预乘亮度颜色 + 权重”，最后归一化。

力度增益与参照一致可写为：

```text
gainVelocity = 1 + velocityTracking × (velocityNormalized - 1)
```

## 7. DAHDSR 与曲线

主音量包络和调制包络状态机：

```text
Delay → Attack(0→1) → Hold(1) → Decay(1→S) → Sustain(S)
      → Release(current→0) → Done
```

参照曲率函数：

```text
g(c,t) = (1-exp(c·t)) / (1-exp(c))
|c| ≤ 0.001 时 g=t
```

每段输出为 `lerp(start,end,g(c,t))`。阶段以样本计数推进，参数变更可在阶段边界生效或按明确规则平滑，禁止因块大小不同而改变总时长。零时长阶段在同一样本内跳过，但设置最大跳阶段数。

通用节点曲线按 time 排序，以 `upper_bound` O(log n) 找区间；区间进入节点携带曲率。编辑线程校验节点数量、有限数、严格单调时间并生成不可变快照。

## 8. LFO、随机与侧链调制

### 8.1 LFO

8 个 LFO，波形是 `[0,1]×[0,1]` 的分段节点曲线。基础预设含正弦、三角、锯齿、方波以及节奏门控类图案。

相位步进：

```text
phase = fract(phase + rateHz/Fs)
```

节拍分频：若一个周期占 `B` 拍，BPM 为 `b`：

```text
rateHz = b / (60B)
B = 4×numerator/denominator
dotted: B×1.5
triplet: B×2/3
```

模式状态：

- Free：始终循环。
- Sync：`phase = fract(hostSeconds×rateHz + phaseOffset)`；无活动声部时参照输出 0。
- Trigger：Note On 从 phaseOffset 重置，音符活动期间循环。
- Envelope：从 phaseOffset 单次走到 1，结束输出 0。
- Sustain Envelope：从 0 走到 phaseOffset 并保持，Note Off 后走到 1。
- Loop Point：先从 0 前进，再循环 `[phaseOffset,1)`。
- Loop Hold：Note Off 前循环 `[0,phaseOffset)`，释放后走向 1。

延迟期间保持起始值；平滑使用一阶低通：

```text
α = 1-exp(-1/(smoothSeconds×Fs))
y[n] = y[n-1] + α(x[n]-y[n-1])
```

参照代码在音频线程持有 waveform spinlock。Qt 实现应让 UI 构建 `WaveformSnapshot` 后原子切换，音频线程不等待。

### 8.2 随机调制

3 个随机源，xorshift32：

```text
s ^= s << 13
s ^= s >> 17
s ^= s << 5
```

每跨过一个相位周期生成新目标：

- Sample & Hold：直接跳到新值；
- Perlin-like：`u=t²(3-2t)`，`y=lerp(prev,next,u)`；
- Sine Interpolate：`u=0.5(1-cos(πt))`。

每个项目保存 seed；“每次播放随机”和“完全可复现”作为用户选项。

### 8.3 侧链包络

输入：`raw[n]=max(|L[n]|,|R[n]|)`。

```text
αattack  = 1-exp(-1/(Tattack×Fs))
αrelease = 1-exp(-1/(Trelease×Fs))
α = raw > env ? αattack : αrelease
env += α(raw-env)
dB = clamp(20log10(env), -60, 0)
mod = transferCurve(dB)
```

### 8.4 调制合成

设参数原值 `p`、范围 `R=max-min`、源值 `m∈[0,1]`、深度 `d∈[-1,1]`：

```text
unipolar: p' = clamp(p + m·d·R)
bipolar : p' = clamp(p + (2m-1)·d·R/2)
```

参照实现按调制源注册顺序逐个应用并逐次 clamp，所以顺序会影响饱和结果。为了项目兼容，Qt 实现应保存显式顺序；若新增“先求和后 clamp”模式，必须写入 schema。

## 9. 效果器算法目录

以下 `p=(x,y,z)`，`mix(a,b,w)=a(1-w)+bw`。RGB 默认透传，除非效果明确处理颜色。

| 效果 | 参照核心算法 | 状态/实现注意 |
|---|---|---|
| Bit Crush | 各分量按级数取整量化，再 dry/wet | 级数下限防除零 |
| Bulge | 极坐标半径 `r'=r^(1-value)`，坐标乘 `r'/r` | `r≈0` 特判 |
| Vector Cancelling | 按由参数决定的间隔交替翻转 X/Y 符号 | 逐声部计数器 |
| Ripple | `z += depth·sin(π·phase + 100·amount·(x²+y²))` | phase 来自处理上下文 |
| Rotate | X/Y/Z 三轴顺序旋转，角度约为参数×π | 固定旋转顺序 |
| Translate | 分量加偏移 | 无状态 |
| Scale | 分量乘比例 | 无状态 |
| Swirl | XY 旋转角约 `10·amount·|p|` | 原点安全 |
| Smooth | `avg=w·avg+(1-w)·input`，`w` 按 `w^(48000/Fs)` 校正 | 每声部独立状态 |
| Delay | 最长约 1 秒环形缓冲，`out=in+decay·delayed` | 预分配，参数变化平滑读指针 |
| Dash / Trace | 保存一周期环形轨迹，按 phase、数量、覆盖率取样/门控 | frame-sync 复位，分数延迟线性插值 |
| Wobble | 给 XYZ 添加同一正弦位移 | phase 连续 |
| Duplicator | 按相位选择圆周复制位置，原点与径向偏移混合 | 拷贝数离散化 |
| Distort | 每样本交替正负的分量抖动 | 可复现随机/符号状态 |
| Perspective | `f=1/tan(FOV/2)`，设置相机 z，再混合投影 XY | 近平面保护 |
| Stereo | X 当前值，Y 使用最长约 0.1 秒延迟 | 环形缓冲 |
| Multiplex | 把输入缩入网格单元；相位遍历单元，可混合相邻格 | 可选源延迟 |
| Unfold | 极坐标角压入由 phase 选择的扇区，可含分数扇区 | 角度 wrap |
| Bounce | 缩放后积分恒速位移，在 `±(1-size)` 反射 | 大步长需 while 反射 |
| Twist | 绕 Y 轴旋转，角度约 `4π·strength·y` | 无状态 |
| Skew | `x+=sx·y; y+=sy·z; z+=sz·x`，均读原分量 | 禁止原地串联污染 |
| Polygonizer | XY 极角/半径分区并量化，Z 条纹量化，再 dry/wet | 负角归一化 |
| Kaleidoscope | 旋转、径向扩散、奇偶镜像、裁到楔形，再旋回各分段 | 边界连续性测试 |
| Vortex | 把 XY 当复数并做整数幂，再 dry/wet | 幂和幅值上限 |
| God Ray | xorshift 噪声经 `12^|bias|` 偏置，径向缩放点 | seed 可保存 |
| Spiral Bit Crush | 映射到对数极坐标，旋转/缩放并网格量化，再逆变换；Z 按 `log|z|` 量化 | 零半径、零 z 安全 |

推荐统一接口：

```cpp
struct ProcessSpec { double sampleRate; int maxBlock; int maxVoices; };
struct ProcessContext { const float* phase; const uint8_t* frameSync; int voice; };

class IEffect {
public:
    virtual void prepare(const ProcessSpec&) = 0;        // 非实时线程
    virtual void reset(int voice) noexcept = 0;
    virtual void process(PointBlock&, const ParameterBlock&,
                         const ProcessContext&) noexcept = 0;
};
```

验收标准：同一效果以单独、串联、旁路三种方式测试；块大小 1/63/64/127/512 时连续输出一致；任何有限输入不得输出 NaN/Inf；RGB 透传效果逐位或在容差内保持颜色。

## 10. Lua 生成器与 Lua 效果

参照环境为 LuaJIT/Lua 5.1。每样本更新 phase：

```text
phase += 2πf/Fs
if phase ≥ 2π: phase -= 2π; cycle_count++
```

按脚本实际引用情况注入全局量：`step、sample_rate、frequency、phase、cycle_count`、最多 26 个滑杆、效果输入 `x/y/z`、外部输入、MIDI note/velocity/voice/note_on、BPM/播放时间/拍号、包络值与阶段等。脚本返回表，读取前三项或六项作为 XYZ/RGB。

内置函数族包括：line/rect/ellipse/circle/arc/polygon/Bézier、square/Lissajous、square/saw/triangle/pulse 波形、mix/translate/scale/rotate/chain、noise/lerp/smoothstep/clamp/map、向量点积/叉积/长度/归一化，以及受控 print/clear。

参照实现每次调用约有 5,000,000 指令的 hook 限制，出错后回退到上次有效脚本；但它打开标准库，并可能在音频线程重建状态。Qt 实现的硬要求：

- 只开放白名单 base/math/table/string 和自定义 API；移除 `os、io、package、debug、loadfile、dofile`；
- 自定义 allocator 设置每 VM 内存上限；指令预算按“块/帧”定义并可中断；
- 后台线程编译、试跑和构建 VM；音频线程在安全点原子切换已验证实例；
- print 进入有界无锁队列，满时丢弃并累计计数；
- 脚本错误含行列、错误类别和最后有效版本，不在音频线程格式化日志；
- 多声部的可变 Lua 状态必须独立，或明确只允许无状态脚本。

## 11. sosci 通道解释与前处理

参照 sosci 以 5 通道输入、6 通道内部工作区为主：

```text
X = input[0]
Y = input[1]

if RGB detected:
    Z = 1
    R = input[2] (缺失时 1)
    G = input[3] (缺失时 0)
    B = input[4] (缺失时 0)
else:
    Z = brightnessEnabled ? clamp(input[2],0,1) : 1
    RGB = unspecified sentinel
```

参照自动检测以很小阈值（约 `1e-4`）检查附加通道，而且状态趋向“一旦检测便保持”。这会把微小噪声误判为颜色。Qt 实现改为：

- 模式：Auto / XY / XY+Brightness / XY+RGB，手动优先；
- Auto 使用块 RMS/peak、连续确认时间和回退滞回；
- 通道数不足时显示明确诊断；
- 每通道支持映射、交换、反相、增益、偏移和钳制；
- 阈值门只消隐束流或衰减亮度，不突然改写 X/Y，以避免跳线。

参照代码把未应用独立程序音量/阈值/静音的工作缓冲送往可视化，再处理音频输出。Qt 工程必须明确“预览前/后处理”选项，默认所见即所得。

## 12. 示波器 GPU 渲染

### 12.1 输入与扫频

显示模式：XY、XYZ（Z 为亮度）、XYRGB。普通 XY 按相邻样本形成线段。扫频模式：

```text
sweepIncrement = 1 / (Fs × sweepSeconds)
sweepX = (samplePosition-lastTrigger) × sweepIncrement × 2×1.135 - 1.135
```

当扫线越过右端，且 X 输入从触发值下方向上穿越时，重置触发位置。Qt 实现增加触发滞回、上升/下降沿、holdoff 和超时自动触发，否则带噪信号会抖动。

可选约 6× Lanczos 上采样降低折线感；各通道拥有独立滤波状态，但时间相位必须一致。颜色通道重采样后应钳制或采用不会明显过冲的插值。

### 12.2 线段光栅化

每条相邻样本扩成一个四边形。顶点着色器计算单位方向、法线和线宽；片元着色器以高斯束斑模拟电子束。长线段沿切向使用误差函数积分，短线段按点高斯计算，随后乘强度、亮度、屏幕纹理和逐点/全局颜色。

核心关系：

```text
Gaussian(x,σ) = exp(-x²/(2σ²)) / (sqrt(2π)σ)
σ ≈ focusSize/5
```

线纹理使用加法混合。核心根据 `hasRgb` 选择全局束流色或顶点颜色，并读取显式亮度；参照实现的 `r<0` 哨兵和最大颜色分量亮度规则由适配器转换，明确黑色仍是有效 RGB。

### 12.3 余辉、辉光与合成

参照每帧衰减：

```text
fade = min(1, 0.4 × 2^(-persistence) × 60/frameRate)
```

Premium afterglow 又根据当前像素亮度以 tanh 调整衰减。随后：

1. lineTexture 保留历史并绘制新线；
2. 17 tap 水平/垂直高斯模糊产生紧致辉光；
3. 降采样后 65 tap 水平/垂直宽模糊产生散射；
4. 可选显示器反射/屏幕辉光；
5. 输出阶段叠加 line、tight glow、scatter、背景/网格、环境光和噪声；
6. 色调映射 `1-exp(-exposure×light)`，再处理过曝趋白和饱和度。

Qt 6 建议用 `QQuickFramebufferObject` 的替代现代路径（`QSGRenderNode`/Qt Rendering Hardware Interface）或独立 `QWindow + QRhi`。不要从音频线程调用 GUI/渲染 API。渲染线程从有界 SPSC 环形缓冲读取最新窗口样本；落后时丢旧显示块，不反压音频线程。

### 12.4 分辨率和帧率无关性

- 余辉按实际 `Δt` 计算：`decay = exp(-Δt/τ)`，兼容模式再映射旧参数；
- focus 以物理/归一化像素尺度定义，DPI 或纹理分辨率变化时视觉宽度稳定；
- intensity 按采样密度、上采样倍数和帧时间归一化；
- 同一信号在 30/60/120 fps 下平均亮度和余辉时间应在容差内一致。

## 13. 线程与实时架构

```text
UI / Project thread
  ├─ 参数编辑、撤销、工程保存
  └─ 构建 Waveform/EffectChain 快照

Parser pool
  ├─ OBJ/SVG/Text/Image/GPLA/L-system/Lua 编译
  └─ 产出不可变 GeometryFrame → SPSC queue

Audio callback (最高优先级)
  ├─ MIDI/宿主时间 → LFO/ENV/Random/Sidechain
  ├─ GeometryFrame → voice sampling → effects
  ├─ 输出 XYZRGB / stereo
  └─ 最新样本窗口 → render ring / recorder ring

Render thread
  └─ 取最新样本 → line/persistence/blur/composite

Recorder/encoder thread
  └─ 时间戳对齐 → WAV/FFmpeg/共享纹理
```

音频回调硬约束：不分配/释放内存，不持有 mutex/spinlock，不做磁盘/网络 I/O，不创建 Lua VM，不解析 JSON/XML，不调用 Qt UI，不等待渲染信号量。所有缓冲在 `prepare(sampleRate,maxBlock)` 预分配。

参照实现中可见的 spinlock、动态 `resize`、渲染 semaphore 等做法不能直接移植到 Qt 的实时核心；它们是“行为参考”，不是架构模板。

## 15. 黄金测试方案

### 15.1 数值单元测试

- 直线、圆、Bézier 在 `t=0/0.25/0.5/0.75/1` 的坐标；
- 弧长表单调性、反查误差、退化曲线、巨大/极小坐标；
- 矩阵顺序、相机前后、穿越近平面；
- DAHDSR 各阶段的精确样本数和块边界不变性；
- LFO 七种模式、节拍分频、宿主跳转、phaseOffset；
- xorshift 固定 seed 序列；侧链 attack/release 63.2% 时间常数；
- 每个效果的有限性、状态复位、RGB 透传和块切分不变性。

### 15.2 文件夹具

- OBJ：三角形、立方体、重复边、奇度图、断开的两个组件、退化面；
- SVG：嵌套 transform、Bézier 极值、洞、open/closed subpath、不同 viewBox；
- GPLA：最小合法帧、多对象、空笔画、截断、巨量计数、NaN、错误标签；
- 图片：全透明、全黑、单亮点、渐变、棋盘、固定随机 seed；
- L-system：Koch、Sierpinski、栈不平衡、指数爆炸；
- Lua：正常 XYZ/RGB、无限循环、超内存、非法库访问、运行时错误与回退。

### 15.3 音频黄金测试

以固定 `Fs=48000`、块大小 64、固定参数/seed 输出 float32：

- 1 Hz 正方形路径、440 Hz 圆、含不同长度段的混合路径；
- Note On/Off、pitch bend、glide、声部窃取；
- 每个状态效果跨帧边界；
- 同一用例用块大小 1/63/127/512 重跑，除明确块级算法外误差 `<1e-5`；
- 30 秒压力测试无 NaN、无堆分配、无锁等待、无 underrun。

### 15.4 图像黄金测试

不应只做整张 PNG 像素完全一致；同时验证：

- 轨迹覆盖率、连通性、平均跳线长度；
- 余辉半衰期、峰值亮度、束宽 FWHM；
- 30/60/120 fps 与 512/1024/2048 分辨率的一致性；
- CPU 软件参考图与 GPU 结果的感知误差；
- 不同 GPU 后端允许小浮点差异，阈值写入测试规范。

### 15.5 与原软件的黑盒对照

在隔离环境运行随附 Linux 版本，用相同输入录 WAV/帧：

1. 先对齐无效果单声部轨迹和频率；
2. 再逐一加入效果；
3. 最后测试调制、复音、可视化和文件边界。

每个差异记录为：输入、版本、参数、原输出哈希、Qt 输出哈希、误差指标、是否采用兼容行为。不能只凭较新源码把差异判为 Qt bug。

## 附录 A：音频分析与声音映射实现

### A.1 基础帧分析

输入为规范化 PCM 块及其起始样本位置。分析器记录采样率、声道合成规则、窗口长度、hop、频带边界和版本；跨输入块保留不足一窗的尾部，使任意块切分得到相同的分析窗口。

可从 `Fs=48000、Hann N=2048、hop=512` 的研究配置开始验证；低延迟候选为 `N=1024、hop=256`。这些数值需要通过目标样本和基准硬件实验确认，最终写入分析配置与缓存键。

```text
w[n] = 0.5 - 0.5*cos(2*pi*n/(N-1)), 0 <= n < N
X[k] = FFT(x[n]*w[n])
power[k] = |X[k]|^2
rms = sqrt(sum(x[n]^2)/N)
peak = max(|x[n]|)
```

连续输出包括 RMS、peak、attack/release 包络、低/中/高频能量；频谱质心、rolloff、flatness、pitch/chroma 是可选扩展。RMS/包络须标明单位，不能直接等同于标准化响度指标。频带积分需固定窗增益及谱归一化，避免窗口改变导致映射强度漂移。

每帧记录窗口中心样本与延迟，末尾补零或截断策略属于分析器版本。静音、削波、非有限输入和尾部不足一窗均有明确结果；图表降采样不得改变用于求值的特征。

### A.2 起音检测

按相邻频谱的正向变化构造起音强度，再使用局部鲁棒阈值寻找峰：

```text
flux[t] = sum_k max(0, log(eps+|X_t[k]|)-log(eps+|X_(t-1)[k]|))
threshold[t] = median(localFlux) + lambda*MAD(localFlux)
onset = localMaximum(flux[t]) && flux[t] > threshold[t]
```

峰值后执行最小时间间隔抑制；需要亚 hop 定位时使用邻近峰值插值，并检查退化分母及偏移边界。低、中、高频可以独立计算 flux，再按配置合并。事件输出包含样本位置、强度、来源和置信度；时间需补偿窗中心及 look-ahead。

### A.3 BPM、beat 与 downbeat

离线分析流程：

1. 对 onset-strength 进行自相关或 tempogram 分析，生成多个周期/BPM 候选。
2. 在配置的候选范围内搜索；研究起点可用 50–220 BPM，范围不是产品硬性限制。
3. 动态规划同时考虑起音强度和拍间周期变化，选择 beat 序列并保留半拍/双拍歧义。
4. 利用低频重音、周期重音和可用的和声变化估计 downbeat/拍号候选；置信度不足时保持候选状态。
5. 用户修改 BPM、拍号或第一拍时重新生成网格，将用户事件和锁定事件作为保留约束；按工程 revision 提交未锁定自动结果。

实时扩展可使用因果 onset、多候选 tempo bank 和相位跟踪；已触发的过去事件不得被事后回写。V1 文件分析优先使用离线确定性路径，实时输入与可选 ML 按 PRD 范围处理。

验证数据需覆盖稳定节奏、半拍/双拍、切分、变速、静音与弱起。使用标注集分别测量起音和 beat/downbeat 的 precision、recall、F1 与定位误差；容差及最低指标在 TRD 第 13.3 节定义后冻结。

### A.4 连续特征映射

单条映射可以按以下顺序计算；多个目标合成规则及求值顺序由工程保存：

```text
u = clamp((source-inputMin)/(inputMax-inputMin), 0, 1)
v = curve(u)
v = gate_quantize_or_sampleHold(v)  // 可选，阶段顺序写入配置
y = attackReleaseSmooth(v)
target = clamp(base + polarity*depth*y, targetMin, targetMax)
```

`inputMax <= inputMin` 视为无效配置，在提交前拒绝。平滑系数按时间计算：`a = exp(-dt/tau)`、`y = a*previous + (1-a)*v`；上升/下降分别使用 attack/release，`tau=0` 表示立即响应。状态按确定性分析时间步推进，避免由 UI 帧率决定结果。

单条映射支持 Continuous 与 Trigger；Toggle/Step、Sample & Hold、门限、量化及延迟按对应范围采用。触发可驱动一次包络、粒子或镜头动作；以事件 ID 和半开样本区间判定触发，跨跳转、循环时按固定 seed 和状态重建规则求值。

范围学习结果、源/目标 ID、曲线、平滑、顺序、合成方式与 seed 必须随工程保存。UI、离线导出和预览读取同一映射契约，具体默认值与多映射交互以 TRD 为准。

## 附录 B：后续视觉事件与卡点算法

本附录保留独立研究价值，对应 PRD 后续版本，不增加 V1 需求。

### B.1 从视频提取视觉重音

解码帧携带 PTS，缩小后分别计算颜色/亮度直方图及边缘差异（切镜）、平均亮度一二阶差分（渐变/闪光）、块匹配或光流幅值分位数（运动能量）、运动能量变化（启动/急停）。需要区分镜头整体运动时估计全局仿射或单应性；语义插件作为额外事件源。

各序列先做局部 `median + lambda*MAD` 阈值与最小间隔抑制，再计算 `salience = wCut*cut + wMotion*motionAccent + wFlash*flash + wSemantic*semantic`。保存原事件类型、源帧 PTS 与各分项分数，供编辑和声音映射解释。

### B.2 视觉事件到节奏音轨

用户给定 BPM/拍号时，将事件软量化到最近的 1/4、1/8 或 1/16 网格；超出容差的事件保留自由时间。自动模式从高显著事件间隔产生网格候选，评分可采用：

```text
score(grid) = sum_i salience_i * exp(-distance(event_i, nearestGrid)^2/(2*sigma^2))
              - lambdaTempo*tempoChange - lambdaDensity*excessiveHits
```

限制 tempo 变化次数和每小节事件密度。事件按规则映射为鼓点、impact、riser、音效等，先输出可编辑事件/MIDI，再以受许可管理的采样或合成器生成音频。保存量化前后时间、力度、音色映射、swing、调式、seed 和来源，使局部重生成保留用户锁定事件。

### B.3 音乐约束下的自动视频剪辑

先提取音频 beat/downbeat 和视频合法切点，再用动态规划搜索受限编辑计划：

```text
cost = wTime*abs(videoEventTime-beatTime) + wSpeed*retimePenalty
       + wDrop*discardPenalty + wRepeat*repetitionPenalty - wSalience*visualSalience
```

约束包含镜头最短/最长时长、允许重定时范围、freeze/倒放/变速开关、downbeat/段落边界、重复次数及运动方向连续性。`0.8x–1.25x` 仅是研究范围示例，需按内容验证。

结果为非破坏性的 `EditDecisionList`，记录素材区间、目标样本区间、速度曲线、转场和事件引用；以锁定片段为约束局部重新求解。先验证计划合法性和同步，再生成成片，避免直接覆盖用户编辑。
