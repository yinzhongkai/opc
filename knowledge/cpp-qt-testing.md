# C++ 与 Qt 测试工程

用于 Windows x64 桌面项目中的 C++ 核心、Qt/C++ 适配层、Qt Quick/QML 界面及跨进程组件测试。它补充通用测试方法，不替代需求验收、架构决定或构建工程职责。

## 技术选择与测试分层

测试框架、版本和接入方式以项目已确认决定为准；处于 proposed 状态的 GoogleTest、Qt Test、Qt Quick Test 和 CTest 组合只能作为候选，不能因编写测试而被视为已批准。

按行为边界组织测试：无 GUI 的领域与算法逻辑放在纯 C++ 单元层，Qt 对象、模型和适配器放在 Qt/C++ 组件层，QML 交互放在界面层，媒体、Worker/IPC、存储和导出放在集成层，稳定输入输出放在黄金样例层，资源与延迟放在性能层。使用项目选定的统一运行入口登记测试，设置可筛选的名称、标签、超时、退出码和结构化结果，使本地与 CI 执行语义一致。

[Qt Test](https://doc.qt.io/qt-6/qtest-overview.html) 支持数据驱动测试、GUI 事件模拟和基准测量；[Qt Quick Test](https://doc.qt.io/qt-6/qtquicktest-index.html) 用于 QML 测试；[CTest](https://cmake.org/cmake/help/latest/manual/ctest.1.html) 可统一发现、筛选和执行已登记测试；若项目确认 GoogleTest，可按其 [CMake 接入说明](https://google.github.io/googletest/quickstart-cmake.html) 集成。工具能力不能代替项目决定和实际验证。

## 可测试契约

- 围绕公开行为、数据契约和不变量测试，避免把私有实现细节固化成用例。
- 为时钟、随机源、文件系统、进程启动和外部媒体接口保留可替换边界；固定随机种子、区域设置、时区和必要环境变量，减少不可复现结果。
- 覆盖对象所有权、生命周期、线程归属、取消和错误传播。Qt 模型与适配层检查角色数据、信号顺序、线程亲和性和事件循环边界，不用无条件休眠掩盖竞态。
- QML 测试聚焦用户可观察行为和 C++/QML 边界。无界面 CI 必须显式记录 Qt 平台插件、图形后端、缩放比例和字体条件；只有视觉结果重要且环境受控时才使用截图比较。

## 黄金样例

黄金样例应小型、合法、非敏感并可长期复现。每个媒体或结构化样例保存稳定 ID、来源与许可证、内容哈希、生成方式和相关工具版本；需要覆盖 CFR/VFR、非零起点、异常时间戳、静止或无节奏输入以及项目迁移等关键边界。

期望结果优先表达事件、音频峰值、帧时间戳、错误类型和状态转换等语义契约。只有结果确定时才做逐值比较；允许容差时记录单位、理由和适用环境。黄金结果变化必须说明需求、算法或工具链依据并单独评审，不能在同一项未经复核的变更中重新生成期望值后直接认定通过。

## 接口与异常测试

- 时间与媒体接口覆盖不同 `time_base`、PTS/VFR、舍入、负值、溢出、缺失时间戳和长时漂移，并核对项目规范时间的往返与单调性。
- Worker/IPC 覆盖协议版本、请求 ID、消息边界、乱序或重复、取消、超时、进程崩溃和重启恢复；传输失败不能留下半完成状态。
- 项目存储覆盖 schema 版本、迁移、未知字段、损坏输入、素材丢失、磁盘不足、临时文件和原子替换；失败后最近一次成功保存仍应可读取。
- Qt/C++ 与 QML 接口覆盖属性、角色、信号、错误信息和线程边界；媒体与导出接口同时验证成功、拒绝、失败和取消路径。

## 性能基线

先验证功能正确，再测量性能。基线记录提交或产物版本、构建类型、编译器与 Qt/依赖版本、硬件、Windows 版本、电源策略、数据集哈希、缓存冷热状态和执行命令。包含预热和多次重复，保留原始数据，并按场景报告中位数、P95 或资源峰值等合适统计量。

只比较条件一致的结果；测试代码、数据或环境改变时建立新基线并注明不可直接比较。性能预算和通过阈值必须来自已确认的硬件、素材边界和产品要求，不能用一次本机测量自行决定。波动或退化先复现和定位，再判定产品是否失败。

## CI、缺陷与证据

测试复用构建工程师维护的工具链、CMake Presets、依赖变体和 ABI 约束。CI 保存被测版本、环境摘要、输入清单、命令、日志和结构化结果，明确区分通过、失败、阻塞与未执行。重试只能用于诊断，不能把首次失败静默改写成通过；不稳定用例需记录复现条件、负责人和处理计划。

缺陷提供最小复现、期望与实际结果、影响、证据和复测范围。测试工程师可以提交测试代码与验证资料，但不静默修改被测实现，也不在没有实际运行证据时宣称质量门槛已满足。
