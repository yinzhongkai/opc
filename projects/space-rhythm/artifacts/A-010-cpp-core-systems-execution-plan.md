## 1. 执行判断

采用 `T-014 -> T-015 -> T-016` 的串行主线：先冻结可被媒体、测试、UI 和 Worker 共同消费的语义契约，再实现事件时间线核心，最后打通进程隔离与持久化。T-014 不依赖 Qt Quick、FFmpeg 或具体 IPC/存储实现，可立即开展；T-015 需等待 T-013 提供纯 C++ x64 目标；T-016 需再等待 T-015，并在具体 IPC/JSON 落地前取得 D-003 确认。

当前仓库尚无 `src/`、`tests/` 或业务 CMake 骨架，只有 Qt 构建工具和验证资料。D-006 已更新为 MSVC 2022 Build Tools x64 confirmed，D-007 已确认 LGPLv3/shared，D-008 已确认 Qt 6.11.2，且 T-012 已完成；A-004～A-007 和 H-003 中仍把 D-006 写成 proposed 的内容属于旧快照，不作为当前阻塞。剩余关键门禁是 D-003 与 T-013。

## 2. 不变量与实现边界

以下约束贯穿三个任务：

1. 项目规范时间的持久化真值是有符号 64 位纳秒；不使用浮点秒或帧号代替。非法值不借用特殊时间数值表达，而使用显式错误或可选状态。
2. 时间换算必须带来源时间基、显式舍入策略和溢出检查；媒体 PTS/DTS、start time、VFR 和 seek 的解释由 T-017/T-018 负责，核心只拥有换算目标和通用精确转换规则。
3. 时间线以不可变已提交修订对外提供；事务以基准 `timelineRevision` 做乐观冲突检查，要么整体提交并生成新修订，要么不改变当前状态。
4. 人工事件和锁定事件的身份及受保护属性不能被重分析覆盖；同一输入、算法版本、参数和种子必须得到等价且稳定排序的结果。
5. 命令、事务、作业和 DTO 不持有 QML 页面、`QObject`、FFmpeg 裸指针或生命周期不明的外部缓冲区。
6. IPC 只承载控制、进度、错误和稀疏 DTO；大帧、PCM 与大特征通过后续确认的缓存、文件或共享缓冲边界传递。
7. 项目主文档是用户状态真值，缓存必须可删除和重建；保存、自动保存、迁移和 Worker 临时结果均不得破坏最近一次成功保存。
8. API 版本、持久化 schema 版本、算法/参数版本和修订号分别管理，不能用一个整数混合表达不同兼容性维度。

## 3. T-014：核心契约 0.x

### 3.1 语义清单

先形成版本化契约成果，不等待工程骨架：

- 强类型标识与值：`TimeNs`、`DurationNs`、`EventId`、`TrackId`、`TimelineRevision`、`AnalysisRevision`、`DiagnosticId`。
- checked 时间运算：整数加减、区间端点、比例换算、采样索引/输出帧的通用换算入口；调用方必须选择 `floor`、`ceil`、`toward_zero` 或 `nearest_ties_to_even`，禁止隐式舍入。
- `RhythmEvent`：稳定 ID、时间/持续时间、种类、来源、强度、置信度、锁定、人工编辑、分析修订和可选声音分配；规定字段范围和缺省/不可用的表达。
- 候选与来源 envelope：算法 ID/版本、参数摘要、输入指纹、可选随机种子和原始候选追踪；领域 payload 由对应算法所有者扩展。
- 时间线快照：轨道、事件集合、全序排序键、修订与只读快照；相同时间事件必须以稳定 ID 等确定性字段完成最终排序。
- 命令与事务：增删、移动、锁定、批量偏移和候选合并的前置条件、基准修订、原子提交、空操作、失败、取消与冲突语义。
- 撤销/重做合同：执行—撤销—重做等价性、新分支修改清空重做栈、保存点语义、历史不持久化时的重开行为。
- 错误合同：稳定错误类别、阶段、诊断 ID、上下文和可恢复性；日志文本不是机器接口。
- DTO/schema 合同：版本字段、未知字段/枚举策略、必需字段、范围校验及兼容性规则；具体 JSON 编码留待 D-003。

### 3.2 契约测试向量

契约成果至少内置以下可直接移交给 T-017 与 T-020 的向量：

| 类别 | 最低覆盖 |
|---|---|
| 时间 | 零值、正负边界、纳秒加减、非整除比例、半值舍入、负数舍入、溢出/下溢、零分母 |
| 区间 | 点事件、零时长、相邻端点、越界移动、批量偏移全成/全败 |
| 排序 | 同时间跨轨道、同来源多候选、插入顺序变化、稳定 ID 最终决胜 |
| 修订 | 正常提交、过期基准修订、空事务、失败回滚、取消前提交、提交后取消竞态 |
| 锁定 | 人工事件、锁定事件、锁定窗内候选抑制、重分析保护、来源追踪 |
| 撤销 | 执行—撤销—重做、连续撤销、分支编辑、保存点、历史容量边界 |
| 兼容 | 已知版本往返、未知新版本、未知可选字段、缺失必需字段、未知枚举 |

## 4. T-015：事件时间线、事务与融合实现

T-014 完成且 T-013 提供纯 C++ 目标后，按下列垂直切片落地；实际目录和语言标准服从 T-013 与 D-003，不在本方案中提前创建第二套工程结构。

1. **时间与基础类型**：实现 checked 算术、显式舍入和强类型 ID/修订；先通过 T-014 时间向量。
2. **不可变时间线**：实现事件/轨道值对象、稳定全序、快照读取和修订生成；对外不暴露可变容器。
3. **命令与原子事务**：实现增删移锁、批量偏移、基准修订校验、结构化错误与无部分提交保证。
4. **撤销/重做**：实现可逆命令记录、分支编辑和保存点；大对象优先使用结构化差异或共享不可变快照，避免无界整项目复制。
5. **确定性融合**：规范化候选，按版本化窗口、最小间隔、密度、权重、优先级和种子处理；保留来源追踪，先保护人工/锁定事件，再单事务提交。
6. **开发自测与消费接口**：覆盖属性/模型测试、固定黄金结果、过期修订和取消竞态；提供无 Qt Quick 依赖的公共 API 与 DTO 适配边界。

T-015 的核心完成判据是：失败或取消不改变当前修订、过期修订被稳定拒绝、锁定和人工事件保持、同输入产生等价集合、完整合并可一次撤销。性能只记录输入规模、内存和耗时；在基准硬件与阈值未确认前不宣告性能通过。

## 5. T-016：Worker/IPC/存储与恢复

T-013～T-015 完成后实施，先用 mock job 证明系统语义，再接媒体/算法任务：

1. **纯作业状态机**：实现 `queued/running/cancelling/succeeded/failed/cancelled` 合法迁移、超时、幂等请求、重复/乱序消息和过期结果拒绝。
2. **协议 envelope**：定义协议版本、消息长度、request/job ID、操作、进度、结果修订、结构化错误和诊断 ID；握手失败与版本不兼容可诊断。
3. **传输适配与 mock Worker**：D-003 确认后再把协议绑定到 Qt 本地 IPC；通过回显、延迟、取消、崩溃和超限 mock 验证生命周期，不把传输机制写进领域接口。
4. **项目文档与迁移**：定义 schema、素材引用/指纹、时间线及参数 DTO、逐版本迁移、未知新版本处理和素材重定位；算法字段由其所有者提供，不在存储层解释。
5. **原子保存与恢复**：临时文件写入、刷新、校验、替换、自动保存和正常退出标记；故障注入覆盖磁盘不足、部分写入、权限失败和崩溃窗口。
6. **缓存与临时结果**：缓存键包含素材指纹、算法/参数版本和工具版本；定义配额、清理、孤儿资源恢复以及 Worker 结果提交前的修订复核。

T-016 在 D-003 未确认时只推进状态机、协议语义、schema 草案和 mock 设计，不冻结 `QLocalSocket`、JSON 编码、项目扩展名或大数据传输实现。
