# 图书生产与统稿

适用于把规划、逐章写作、读者反馈和全书编辑组织为连续工作的图书项目。本文提供方法，不新增成员身份、任务状态、审批权限或自动调度；协作规则以 [项目运行协议](../PROJECT_PROTOCOL.md) 为准。具体受众、完成条件和采用的方法在项目中确认。

## 三层边界

OPC 保存协作事实；图书知识保存可复用方法；单本书保存定位、目录、风格、资料和内容。技术书可补充实验验证，其他书采用适合题材的事实、论证或案例检查，不强制配置代码、硬件和测试成员。

## 全书规划与逐章生产

先明确目标读者、前置能力、阅读后应获得的能力、内容边界及验证办法，形成目录和写作约定。规划方法见 [图书规划](book-planning.md)。目录经项目约定的确认后展开写作；学习反馈可触发有依据的目录调整。

逐章采用：章节蓝图 → 草稿 → 审校与修订 → 试读版 → 读者学习或使用 → 反馈修订与复核 → 章节定稿。阶段是工作内容，不是额外的一套 OPC 状态。研究、示例实现和验证按本章需要穿插，不要求读者先学会才能得到草稿。

| 交付节点 | 检查重点 |
|---|---|
| 章节蓝图 | 学习目标明确，前置依赖可获得，示例和验证要求有着落 |
| 试读版 | 约定的审校范围已处理；必要前提齐备；不存在已知的主线操作阻断问题；剩余未知对读者可见 |
| 章节定稿 | 约定的事实、实践与读者反馈要求已满足，实质问题有处理和复核依据，并取得该版本的实际确认 |
| 全书交付 | 章节集合、跨章一致性、配套材料、输出格式及确认范围完整，不以章节数量代替整书验收 |

试读版表示用途，不等于最终批准。资料不足时可交付明确标注缺口的概念预览，但不能将其交付为可照做的实验章节。未执行的实验按原定计划留待读者验证；已知无法执行的主线实验则先解决依赖或经确认调整范围。

建议先闭环一章，再验证关联章节与全书。详细书稿适度领先读者进度；未验证的共同前提影响后续章节时，先解决它，再扩展依赖内容。数量与节奏由项目决定，不设固定的全员、全维度、固定轮数审校门槛。

## 分开观察三类进展

| 维度 | 原始依据 | 不可推导的结论 |
|---|---|---|
| 书稿 | 对应版本的正文、任务内评审与批准决定 | 草拟任务完成不代表书稿获批 |
| 验证 | 具体主张或示例的检查方法、执行记录与证据 | 资料核查不代表运行，编译不代表上板 |
| 学习 | 读者反馈、解释、操作或变式尝试 | 稿件写好不代表读者掌握，照做成功不代表全部理解 |

技术或学习维度不适用时说明原因，不虚填通过。总体摘要分别汇总这些事实，不在 README、目录与进度表中维护多份独立的完成清单。

## 版本与跨章影响

章节使用稳定标识，显示章号和阅读顺序只在目录中维护；章节标识、任务编号、成果编号互不推算。正文默认只有一份当前版本，试读或发布指向明确的版本、实际 Git 提交或可复核内容摘要。示例有独立版本时记录映射。

保留关键蓝图、反馈、实质修订以及公共协议要求的历轮评审记录；不在章节完成时批量删除这些资料。历史正文依赖实际保存的 Git 或必要快照，未保存的内容不声称可恢复。提交、对外发布仍须有相应授权。

修订基础概念、术语、环境或示例时，沿目录依赖和引用列出受影响章节，注明需改写、重跑或复核的范围。旧版结论只适用于旧版及原覆盖范围；依赖已变的结果标明待复核。公共事实由获授权的负责人修订，保留来源、变更依据和影响，不能因“权威资料只读”长期搁置已证实的错误。

## 全书统稿与输出

按读者的实际阅读顺序检查覆盖、重复、术语首次讲解、前后依赖、引用与示例演进。核对来源、图片使用依据、环境版本及遗留项；作者统稿不替代必要的专业复核。

输出前登记包含的章节及版本、示例版本、环境基线、批准依据和明确排除的内容。检查导出文件的目录、图表、代码换行和内部注记；保留对读者必要的风险提示。整书批准、文件导出与对外发布是不同动作，不因生成文件而自动发布。

## 用真实问题改进框架

从具体反馈或协作事件记录现象、影响、现有办法及通用性判断；技术缺陷先在本书处理，可复用的方法缺口再形成框架改进建议。成员按公共协议请用户转交超级管理员，公共变更需明确授权与影响检查。回到实际写作中验证改进效果；结构校验、单章闭环、跨章连续性与跨题材复用分别报告，不相互冒充。
