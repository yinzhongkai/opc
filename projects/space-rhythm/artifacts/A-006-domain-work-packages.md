## 1. 拆分结论

一期建议拆成十个专业工作包。工作包代表责任边界，不强制一包一人；同一人可兼任相邻领域，但每项交付必须有唯一责任人。跨包协作只通过第 3 节的版本化契约，不允许各领域自行复制时间、事件、错误或项目数据模型。

| 工作包 | 专业领域 | 建议专业画像 | 核心交付 |
|---|---|---|---|
| WP-01 | Windows x64 平台、Qt 源码与构建 | Windows C++/Qt 构建工程师 | 可复现 Qt SDK、应用构建预设、依赖基线和 CI 构建镜像 |
| WP-02 | C++ 核心领域与事件时间线 | 现代 C++ 领域/应用工程师 | 规范时间、事件模型、修订、命令、撤销重做和事件融合核心 |

| WP-04 | 媒体、播放同步与导出 | FFmpeg/C++ 多媒体工程师 | 媒体探测、解码、PTS 映射、代理、同步预览和封装导出 |

## 2. 领域工作包

### WP-01：Windows x64 平台、Qt 源码与构建

- **专业画像**：熟悉 Windows x64、MSVC/MinGW、CMake/Ninja、Qt 6 源码构建、二进制 ABI、vcpkg、CI 缓存和符号管理。
- **负责范围**：D-004/D-005、D-006 落地；Qt 官方源码获取、校验、shadow build、安装和最小 QML 冒烟验证；应用/worker/测试构建骨架；非 Qt 依赖的统一 triplet 与运行时策略。
- **输入**：Qt 确切版本与许可证路线、D-006 编译器决定、最低 Windows 版本；模块白名单来自 WP-03/WP-06/WP-07。
- **输出**：版本化构建脚本与 presets、Qt x64 shared SDK、工具版本清单、configure 参数/摘要、安装文件与哈希清单、开发机/CI 使用说明、最小 QML 程序验证记录。
- **接口边界**：只提供工具链、SDK 和构建目标，不实现产品 UI 或业务算法；其他工作包不得自行引入第二套编译器、Qt 或 C++ 运行时。
- **验收条件**：全新 Windows 构建环境可按文档生成同版本 Qt SDK；Qt、应用空壳、worker 空壳和测试目标均可编译；x86/ARM64 配置被明确拒绝；ABI/运行时检查无混用。
- **前置与阻塞**：D-006 未确认前只能准备双方案，不能冻结 SDK；Qt 版本与许可证未确认前不能形成发布基线。
- **对应需求**：TR-A-006、TR-F-017、TR-Q-007～009。

### WP-02：C++ 核心领域与事件时间线

- **专业画像**：熟悉现代 C++、不可变数据、命令模式、事务/撤销、确定性算法、序列化边界和并发安全。
- **负责范围**：项目规范时间、`RhythmEvent`、轨道、`timelineRevision`、`analysisRevision`、锁定与人工编辑语义、事件融合、密度/偏移、重分析合并、撤销/重做；定义无 Qt UI 依赖的公共 C++ 契约。
- **输入**：A-004 第 4 节；WP-04 的媒体时间映射、WP-05/WP-06 的候选事件和特征。
- **输出**：领域头文件/实现、事件与命令 schema、融合参数、版本迁移规则、确定性测试、供 QML bridge/worker/存储使用的 DTO。
- **接口边界**：拥有规范时间和事件语义；不拥有媒体解码、QML 页面、音频设备、GPU 绘制或文件编码。其他工作包不得另定义事件结构或以浮点秒数作为持久化真值。
- **验收条件**：人工与锁定事件在重分析后保持；合并以一次可撤销事务提交；失败/取消不改变当前修订；相同输入、版本、参数和种子产生等价事件集合。
- **前置与阻塞**：应在算法和 UI 大规模开发前先冻结 0.x 接口；产品“卡点自然”阈值未确认不阻止契约实现，但阻止算法效果验收。
- **对应需求**：TR-A-002～005、TR-F-004、TR-F-006～007、TR-Q-001～002、TR-Q-009～010。

### WP-03：Qt Quick/QML UI 与应用桥接

- **专业画像**：熟悉 Qt Quick/QML、Qt Quick Controls、Qt/C++ 类型注册、`QAbstractItemModel`、ViewModel、可访问性、桌面快捷键和 UI 自动化测试。
- **负责范围**：主窗口、导入/项目流程、媒体预览容器、时间线与播放头交互、事件编辑、参数面板、作业进度、取消入口、错误/恢复提示；Qt/C++ bridge 和 UI 状态机。
- **输入**：WP-02 的领域模型与命令，WP-04 的预览表面/状态，WP-07 的高密度渲染 Item，WP-08 的作业/错误消息。
- **输出**：QML 页面和组件、主题与键盘交互、ViewModel/模型适配、UI 状态图、Qt Quick Test、错误文案所需的结构化映射。
- **接口边界**：QML 只负责视图、布局、绑定、交互和轻量动画；不得执行解码、FFT、光流、逐像素/逐采样循环、长时导出或持有 worker 原始缓冲区。
- **验收条件**：事件增删/移动/锁定/偏移、撤销重做和播放控制可用；后台任务不阻塞 UI；错误包含失败阶段、项目是否安全、恢复动作和诊断 ID；高密度数据不采用“一点一个 QML Item”。
- **前置与阻塞**：依赖 WP-01 空壳 SDK 和 WP-02 契约；可使用 mock service 与媒体/算法并行开发。
- **对应需求**：TR-A-001、TR-A-003～005、TR-F-003～004、TR-F-016、TR-Q-003、TR-Q-008。

### WP-04：媒体、播放同步与导出

- **专业画像**：熟悉 FFmpeg C API、PTS/time_base、VFR、重采样、像素格式、硬件/软件编解码、音视频同步和容器封装。
- **负责范围**：只读媒体探测、解码、旋转/颜色与格式归一化、代理帧/缩略图/波形源数据、源 PTS 与 `timeNs` 映射、预览帧调度、导出编码/封装与临时文件事务；维护媒体格式能力矩阵。
- **输入**：WP-02 规范时间与固定 `timelineRevision`，WP-06 PCM 输出，WP-07 离屏视频帧，WP-08 作业/缓存服务。
- **输出**：Media Service、时间映射 API、帧/PCM 缓冲契约、代理生成器、预览同步适配、Export Coordinator、结构化媒体错误、格式/编码器测试矩阵。
- **接口边界**：媒体 PTS 解释归 WP-04，规范项目时间归 WP-02；不实现镜头/动作算法、音频特征算法、视觉模板或 QML 页面。导出不得读取正在变化的时间线。
- **验收条件**：CFR/VFR 样例可正确定位；不整段加载长视频；损坏/不支持素材返回结构化错误；预览与导出事件位置误差不超过一个输出帧；取消/失败不覆盖既有输出。
- **前置与阻塞**：依赖 WP-01 ABI 基线和 WP-02 时间契约；H.264 后端、容器/编码器矩阵与许可尚待确认，原型可先覆盖约定测试格式。
- **对应需求**：TR-F-001～003、TR-F-014～015、TR-Q-001、TR-Q-004～006、TR-Q-010。

### WP-05：视频节奏分析

- **专业画像**：熟悉 OpenCV/C++、镜头检测、光流/运动估计、信号平滑与峰值检测、数据集设计、算法评估和性能优化。
- **负责范围**：代理帧预处理、镜头切换、全局/局部运动、动作峰值候选、强度归一化、置信度与低质量原因；输出可解释候选，不直接修改用户时间线。
- **输入**：WP-04 代理帧与真实 PTS，WP-02 `AnalysisCandidate` 契约，产品代表性视频与评分口径。
- **输出**：无 GUI C++ 分析库、参数 schema、候选事件与诊断曲线、算法版本标识、样例集评估报告、性能基准；经典算法未达 G1 门槛时再提交 ONNX 评估输入。
- **接口边界**：只负责候选检测；密度、跨来源融合、锁定保护和人工编辑归 WP-02，媒体解码归 WP-04，模型是否进入产品需另行决定。
- **验收条件**：分别输出 `shot`、`motion_peak`、`action_peak`，每项含时间、强度、置信度、来源和算法版本；覆盖静止、运镜、闪烁、快切、慢镜头等样例；相同输入与参数可复现。
- **前置与阻塞**：接口开发依赖 WP-02/WP-04；“卡点自然”和人工修正量阈值未确认时只能报告测量结果，不能宣告效果通过。
- **对应需求**：TR-A-002～005、TR-F-005、TR-Q-002、TR-Q-004、TR-Q-010。

### WP-06：音频 DSP、节奏与音轨

- **专业画像**：熟悉 C/C++ DSP、采样时钟、STFT/FFT、谱通量、起音/节拍检测、实时缓冲、混音、削波和音频文件输出。
- **负责范围**：PCM 归一化、节拍/瞬态/响度/频段能量、置信度与失败原因；事件到音色映射、采样精确触发、混音、峰值/削波检测、`QAudioSink` 设备适配和独立 WAV/PCM 渲染。
- **输入**：WP-04 解码/重采样 PCM 与采样率，WP-02 事件修订和 `soundAssignment`，产品确认的音色及许可。
- **输出**：无 GUI DSP 库、`AudioFeatureFrame`、节拍/起音候选、混音核心、设备输出适配、音轨渲染器、音频黄金样例与性能数据。
- **接口边界**：采样索引和 DSP 真值归 WP-06，媒体 PTS 转换归 WP-04，事件融合归 WP-02，QML 展示归 WP-03；离线导出和试听必须复用相同混音核心。
- **验收条件**：稳定节拍、自由节奏、弱瞬态和噪声样例有明确结果/低置信度；相同事件和种子生成确定性 PCM；重叠、尾音、峰值和削波受控；设备失败不破坏离线导出能力。
- **前置与阻塞**：依赖 WP-01、WP-02、WP-04；FFT 后端和 D-003 未确认时通过接口隔离实现；随包音色许可证未确认则只能使用合法测试音色。
- **对应需求**：TR-F-008～010、TR-Q-001～004、TR-Q-010。

### WP-07：Qt 场景图与视觉模板

- **专业画像**：熟悉 Qt Quick Scene Graph、`QQuickItem`、`QSGGeometryNode`、Shader Tools、渲染线程、批量几何、离屏渲染和 GPU 性能分析。
- **负责范围**：高密度波形/事件/频谱绘制；波形/示波器、频谱几何、粒子或线条脉冲三类视觉模板；统一 `RenderRecipe`、随机种子、屏上/离屏渲染核心和兼容路径。
- **输入**：WP-02 时间/事件，WP-06 音频特征，WP-03 视图参数，WP-04 输出帧规格。
- **输出**：自定义 QQuickItem/场景图节点、视觉渲染核心、离屏帧接口、模板参数 schema、GPU 能力探测、性能和像素容差测试。
- **接口边界**：拥有视觉配方和绘制实现；不拥有 UI 工作流、音频分析、媒体编码或事件语义。不得为每个采样点/事件创建独立 QML 对象，也不得让业务层直接绑定 OpenGL/Direct3D。
- **验收条件**：三类模板可调灵敏度、密度、强度和偏移；屏上与离屏使用相同事件修订、参数和随机种子；时序一致，GPU 差异落在批准容差内；高密度场景达到后续确认的交互预算。
- **前置与阻塞**：依赖 WP-01 Qt 模块、WP-02 契约和 WP-06 特征；视觉风格与基准硬件未确认时可完成技术模板，不能完成观感/性能最终验收。
- **对应需求**：TR-F-011～012、TR-Q-001～004、TR-Q-008～010。

### WP-08：Worker、IPC、项目存储与恢复

- **专业画像**：熟悉 Windows 进程/命名管道、Qt `QLocalSocket`、并发作业、取消/超时、崩溃隔离、JSON schema、原子文件操作、缓存和恢复设计。
- **负责范围**：UI/worker 进程生命周期、版本化消息帧、权限、作业状态机、取消与崩溃恢复；项目保存/另存/重开/迁移、自动保存、素材重定位、缓存索引与配额、临时结果提交。
- **输入**：WP-02 DTO/schema，WP-04～WP-07 作业接口，WP-03 需要展示的进度/错误。
- **输出**：`space-rhythm-worker` 宿主、IPC 协议、Job API、错误 taxonomy、项目 JSON schema/迁移器、原子保存、自动恢复、可重建缓存服务和故障测试。
- **接口边界**：IPC 传命令、进度、错误和稀疏元数据，大帧/PCM 不经 JSON 反复复制；存储层不解释算法内容，不把缓存当用户持久数据，也不允许 worker 直接访问 UI `QObject`。
- **验收条件**：worker 崩溃、取消、磁盘不足、素材丢失、缓存损坏和项目迁移失败均不破坏最近成功保存；重复作业可复用验证缓存或产生等价结果；同一输出不存在并发覆盖。
- **前置与阻塞**：WP-02 契约先行；可用 mock job 与 WP-04～WP-07 并行；项目扩展名等低影响细节可后定。
- **对应需求**：TR-A-003～005、TR-F-002、TR-F-013、TR-F-015～017、TR-Q-002、TR-Q-004～006、TR-Q-009～010。

### WP-09：自动化测试、性能与质量

- **专业画像**：熟悉 GoogleTest/CTest、Qt Test/Qt Quick Test、媒体黄金样例、属性/故障测试、性能剖析、Windows CI 和可重复测试环境。
- **负责范围**：建立需求到测试追踪；单元、契约、worker/IPC、项目迁移、UI、端到端和发布冒烟测试；CFR/VFR、音频峰值、事件、像素容差与性能测量；构造取消、崩溃、损坏媒体、磁盘不足等故障。
- **输入**：所有工作包的接口和验收项，产品样例/规模/自然度口径，WP-01 的 CI 环境。
- **输出**：测试计划、自动化套件、合法小型 golden media、基准数据、性能报告、兼容矩阵、缺陷证据和 G1～G4 放行记录。
- **接口边界**：独立验证而非代替各开发包自测；不修改验收阈值，不以测试通过替代产品自然度确认或许可证审查。
- **验收条件**：TR-A/F/Q 全部可追踪；核心算法无 GUI 测试；端到端覆盖导入→分析→编辑/锁定→试听→保存重开→导出；故障测试验证无数据破坏；性能结果注明硬件、素材和版本。
- **前置与阻塞**：测试框架可随 WP-01/WP-02 首批启动；最终性能和自然度放行依赖最低 Windows/基准硬件、素材上限和评分阈值。
- **对应需求**：TR-A-006、TR-F-001～018、TR-Q-001～010，作为横向验证责任。

### WP-10：Windows 分发、安全与许可证

- **专业画像**：熟悉 Windows 安装/升级/卸载、代码签名、DLL 搜索安全、SBOM、开源许可证履约、恶意软件扫描和发布归档。
- **负责范围**：应用私有依赖部署、安装器与升级策略、发布者签名、哈希/SBOM/许可证清单、Qt/FFmpeg/OpenCV/音色等来源归档、干净环境和卸载验证；定义崩溃信息及可选遥测隐私规则。
- **输入**：WP-01 SDK/依赖清单，WP-04 编解码矩阵，WP-06 音色清单，所有包的运行时文件；Qt 许可证和 H.264 后端决定。
- **输出**：Windows x64 安装包、签名/验证记录、依赖与许可证归档、SBOM、第三方 notices、发布哈希、安装升级卸载测试结果和已知限制。
- **接口边界**：不在运行时下载未知编解码器或覆盖系统共享 DLL；不替法律专业人员作最终法律结论，不把未批准的 GPL/nonfree 组件或未知许可音色带入发布包。
- **验收条件**：干净 Windows 环境完成安装、首次启动、导入、保存、导出、升级和卸载；发布者身份可验证；依赖均可追溯且完整性通过；默认不上传素材、特征或崩溃附件。
- **前置与阻塞**：原型期可先建立清单；发布构建依赖 Qt 许可证、最低 Windows、安装器/签名、H.264 后端和输出矩阵确认。
- **对应需求**：TR-F-014、TR-F-017～018、TR-Q-005～008。

## 4. 依赖顺序与并行边界

```text
阶段 0：确认 D-006、Qt 版本/许可证、最低 Windows 基线
    ↓
阶段 1：WP-01 构建底座 + WP-02 核心契约 + WP-09 测试骨架
    ↓
阶段 2：WP-03 / WP-04 / WP-05 / WP-06 / WP-07 / WP-08 基于 mock 与冻结契约并行
    ↓
阶段 3：WP-04 + WP-06 + WP-07 + WP-08 汇入端到端垂直切片，WP-03 完成交互闭环
    ↓
阶段 4：WP-09 执行 G1～G3，修复后冻结接口和依赖
    ↓
阶段 5：WP-10 完成 Windows 分发，WP-09 执行 G4
```

并行开发的硬约束：WP-05/WP-06 不等待完整 UI，可用 CLI/测试驱动；WP-03 不等待真实算法，可用 mock 候选和作业；WP-07 不等待最终模板风格，可用固定测试特征；WP-08 不等待真实 worker，可用回显/故障 mock。WP-02 的时间、事件、修订和错误 envelope 必须优先冻结，否则并行只会把集成成本后移。

## 5. 招募与人员组合建议

完整专业覆盖约为 8～10 个责任方向，不等于必须配置 10 人。建议按以下组合控制早期规模：

| 阶段 | 建议人员组合 | 可兼任关系 | 不建议兼任 |
|---|---|---|---|
| 起步底座 | 1 名 Windows/Qt 构建工程师；1 名 C++ 核心工程师；1 名测试工程师（可先兼职） | WP-01 可暂兼 WP-10 的依赖清单；WP-02 可暂兼 WP-08 契约骨架 | WP-01 不应单独决定许可证和产品格式范围 |

## 8. 自查结论

- 十个工作包覆盖 A-004 的 TR-A-001～006、TR-F-001～018、TR-Q-001～010，没有把现有 reverse-engineering 成员擅自改派为实现人员。
- 时间、事件、项目、IPC、媒体缓冲、渲染配方和构建清单均指定唯一契约所有者，避免多领域重复建模。
- 已确认技术约束与 D-003/D-006 proposed 选择明确分离；人员可以先按接口准备，不得提前把候选依赖当作批准基线。
- 每个工作包具有独立可交付物和验收条件，可用于后续建员 scope、任务拆分、报价或技术面试，但实际人员创建和排期须按项目流程另行执行。
