# 任务

以下是初始示例任务，均未启动。每项任务由具体成员 ID 负责；完成条件需结合实际项目澄清后确认。

- [ ] `BOOK-001` 明确读者、定位、范围与完成条件；负责人：`project-manager-01`
  - 完成条件：取得用户关键输入，记录范围和未决定事项。

- [ ] `BOOK-002` 调研主题、案例与可靠来源；负责人：`researcher-01`；依赖：`BOOK-001`
  - 完成条件：形成可追溯研究摘要与来源清单。

- [ ] `BOOK-003` 设计图书结构与章节大纲；负责人：`planner-01`；依赖：`BOOK-001`、`BOOK-002`
  - 完成条件：章节目标、核心论点与资料需求明确，大纲得到确认。

- [ ] `BOOK-004` 撰写并修订稿件；负责人：`writer-01`；依赖：`BOOK-003`
  - 完成条件：稿件遵循确认大纲、风格与事实引用要求，未核实项明确标识。

- [ ] `BOOK-005` 独立评审事实、结构与完成条件；负责人：`reviewer-01`；依赖：`BOOK-004`
  - 完成条件：形成可定位、可复核的评审意见和结论。

成员直接在自己负责的任务下更新状态、进展、产物链接和阻塞；需要独立验收的任务区分自报完成与已验收。项目经理维护任务增删、负责人、依赖、优先级、范围和完成条件，并汇总项目状态。普通进展无需重复写交接；需要其他成员行动或接手时再记录 HANDOFFS.md。

发现问题后由对应成员修订并复测，不将依赖任务完成等同于后续验收通过。负责人停用时，保留已完成任务历史和未完成工作，注明待重新分配；项目经理随后安排接收者并记录接收确认。任务转交不阻碍成员直接停用，停用也不会自动完成任务。
