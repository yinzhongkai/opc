## 2. 场景记号与共同断言

下列为用例的输入规格，尚不是已生成的夹具或实际用户数据。测试应使用隔离的临时存储域，不能清空用户真实菜单。

| 记号 | 前置/输入规格 |
|---|---|
| E | 全新、可读取且无菜单的存储；当前候选为空、无当前菜单关联。读取失败不属于 E。 |
| M / N | 两个不同 menuId：M 名为“午餐”，保存有序名称“面馆、饺子”；N 名为“晚餐”，保存“咖喱”。加载 M 为无改动基线；所有比较使用完整有序名称及必要元数据。 |
| W | 加载 M 后追加“米饭”的工作副本，currentMenuId=M、dirty=true；持久 M 仍为“面馆、饺子”。 |
| C(n) | n 个互不重复的名称，按输入顺序排列；覆盖 n=0、1、12、13、23、24、25。25 用作被拒绝的操作或损坏快照，不能作为有效保存菜单。 |
| G(k,t) | 同一种已说明字素 t 重复 k 次，用于 1/20/21 扩展字素簇边界；具体字符序列见第 4 节。 |
| Before / After | 一次操作前后工作副本、当前关联、保存基线、dirty、各菜单 ID/名称/版本/有序候选、可见提交根和错误结果；原始存储按需另存副本用于差异核对。 |

拒绝操作共同检查原候选、顺序、旧保存记录及当前编辑态不变；允许有明确的错误/提示状态变化。抽取只读候选及菜单，不改变 dirty。编辑按有序名称内容与加载/成功保存基线比较 dirty；内部 ID 或抽取变化不制造内容改动。快照与工作副本不共享可变内容，后续编辑不得反向改变旧快照。

存储断言比较“有效根可达的完整菜单”，不把新建但未提交的孤立块误判为已保存菜单。准备阶段失败时旧根与旧菜单保持有效；根提交结果不明时按第 5 节核验，不承诺所有错误都回到旧版本。

## 5. 存储故障注入与恢复矩阵

L 层使用可控制的独立 StoragePort 替身。针对 create/overwrite/rename/delete 及保存并切换执行适用行；每行先用成功路径证明前置有效，再从隔离快照重建并单点注入。区分“抛错前未生效”“已生效但回调报错”“回读失败”；不能只让所有 write 一律抛错来覆盖全部阶段。记录故障发生的第几次调用、阶段、是否实际生效、旧/新可达版本和目标 load 调用数。

| 故障 ID | 注入点与操作 | 预期断言 / 恢复检查 | 关联 |
|---|---|---|---|
| FI-01 | 启动 list/load 时根、索引或内容读取失败。 | 明确读取错误，不当空库新建覆盖；原始存储和当前副本保留；成功重试能恢复原菜单。 | AC-05/06/07/37，PV-02 |
| FI-02 | 容量预估已满；另预估足够但准备写入真实失败。 | 两条路径均保留旧提交、编辑态和 dirty；不删旧项腾空间，不成功切换。 | AC-30/31/35，B-03 |
| FI-03 | 候选内容块第一个/中间/最后一次写入失败，含写入部分生效。 | 未提交新根；旧完整菜单仍可加载；孤立新块不进入列表；当前副本不丢。 | AC-16/31/35 |
| FI-04 | 新内容块回读缺失、错误、校验值不符。 | 不提交引用坏块的根、不报成功；旧根及记录可用；记录错误原因。 | AC-05/31/35 |
| FI-05 | 新索引写入或回读失败；元信息/序列化失败。 | 新根未提交，旧菜单名称/ID/内容完整；失败不清 dirty。覆盖重命名/删除路径。 | AC-14/16/31/32/35 |
| FI-06 | 根写入在生效前失败，随后回读确认为旧 revision。 | 判定未提交并明确失败；旧版本不变、当前副本保留；可按版本安全重试。 | AC-31/35 |
| FI-07 | 根已写入成功，但回调报错；随后的根/内容回读确认新 revision 完整。 | 依据真实提交结果确认成功/恢复，不同时报失败又声称旧记录必然未变；更新成功基线一次。若为删除，不能复活旧菜单。 | AC-14/16/32/35，PV-02 |

## 6. 受控随机输入与失败

按 A-006 第 5 节：N≥2 取 32 位无符号 x，B=floor(2^32/N)×N；仅 x<B 接受，返回 x mod N。字节序、随机接口映射和有限重试预算由 developer 锁定并说明。下表中的数字为精确十进制，B 计算不能溢出 32 位或把 x 变为有符号负数。

| 子 ID | 输入/前置与步骤 | 预期断言与证据 |
|---|---|---|
| RN-01 | N=0 / N=1，随机端口配置为调用即失败。 | 0 无结果且提示；1 直接唯一项；随机端口调用数均为 0，菜单不变。 |
| RN-02 | N=2，依次 x=0、1、4294967295；另两次都给 x=0。 | B=4294967296；索引为 0、1、1；重复输入可重复同项；不按历史轮换。 |
| RN-03 | N=3，x=0、1、2、4294967294；另序列 [4294967295,1]。 | B=4294967295；前者索引 0、1、2、2；后一先拒绝再得索引 1，恰消耗两次熵。 |
| RN-04 | N=24，x=0、23、4294967279；另 [4294967280,4294967295,23]。 | B=4294967280；索引 0、23、23；后一两次拒绝后得到 23，共三次熵，无越界。 |
| RN-05 | 按已声明预算 K 连续给拒绝域值；另熵源抛错/返回无效长度或失效数据。 | 有限结束并报 RANDOM_UNAVAILABLE 或等价明确错误；无伪结果/备用偏差算法；恢复可操作状态，持久菜单不变。N=2 无拒绝域，预算场景用 N=3/24。 |
| RN-06 | 两个不同候选快照、drawId/generation；旧异步结果迟到，重复回调或点击。 | 结果属于发起时快照且只提交一次；过期 generation 结果不显示、不改菜单。D/M 再确认指针和名称对应。 |
| RN-07 | 审查 N=2～24 的 B 和各余数原像数，检查端口熵源依据和历史依赖。 | 每余数接受输入数量为 floor(2^32/N)，无直接取模偏差；均匀/独立结论以熵源假设和算法为依据。有限抽样仅辅助发现异常，不能证明等概率。 |

关联 AC-04/09/10/15、PV-04、B-04。L 不验证真实 wx 熵源或基础库支持，平台适配及失败行为待 D/M。重试预算的具体 K 属于实现参数，不新增用户可配业务规则。
