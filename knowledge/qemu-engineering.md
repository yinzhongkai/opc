# QEMU 模型开发与验证

本技能提供虚拟板和设备模型的开发、测试与交接方法，不定义成员权限或平台设计。具体 CPU、地址、设备、启动协议和功能范围取自项目已确认资料，未知项先形成缺口，不以示例值代替决定。

## 锁定基线与行为契约

记录 QEMU 上游版本和精确提交、已有 patch、目标架构、构建选项、宿主环境和运行参数。由 Yocto/Poky 配方获取源码时，与集成成员核对实际选中的配方、源码版本和既有补丁；不能另选上游 master 冒充项目基线。

先阅读该版本相近 machine 和设备的实现及测试，再核对对应版本文档。列出 CPU 型号与启动状态、RAM/ROM/MMIO 范围、总线和中断拓扑、寄存器契约、时钟及复位语义；固件、设备树和 guest 驱动须引用同一契约。标明复用的上游设备、需要新建的模型和不支持的行为。

## Machine、内存与设备实现

按目标版本的 QOM/qdev 生命周期组织对象、属性、设备实例化和连接，区分 machine 装配与设备自身逻辑。复用上游模型时核对实际能力，不仅凭名称判定兼容。

检查 RAM/ROM、MMIO、别名与容器的地址范围、覆盖优先级、对象生命周期，以及越界、访问宽度、端序和对齐规则。MMIO 回调按契约处理只读位、保留位、读写副作用、错误访问和复位值；中断的触发、屏蔽、清除与撤销须与 guest 驱动一致。

同步维护该基线要求的构建注册和依赖，验证目标 machine 能被实际生成的 QEMU 二进制识别，不把源文件存在当作已经编入。

## ARM 启动、复位与后续外设

按确认的启动方式核对 CPU 初态、入口地址、镜像装载范围、设备树或其他启动参数及固件交接。直接装载内核、固件引导和完整启动链是不同验证对象；只执行其中一种时说明未覆盖路径。

复位逻辑须按基线接口处理设备状态、计时器和中断线，检查冷启动、系统复位和设备复位的区别以及复位后的再次启动。存在复位域或依赖时明确传播关系，不能只把寄存器清零后宣称完成复位模型。

NAND 等存储模型先核对容量、页/块与 OOB 几何、命令序列、状态和后端数据布局，按范围验证读写、擦除、边界及错误行为。watchdog 等计时设备先核对时钟、装载、喂狗、使能、超时及中断或复位动作；使用目标版本可控制的虚拟时间验证临界点，避免依赖宿主等待时间判断模型正确性。未要求或未实现的功能明确标注，不能用固定返回成功的桩代替主线功能。

## 按行为验证与定位

针对模型选择该版本可用的 unit test、QTest 或系统运行测试。QTest 可用于寄存器、内存访问、中断和计时器等设备行为，不能替代 guest CPU 执行、驱动或内核启动的实际验证。用例覆盖正常路径、边界、错误处理、重复操作和复位后状态；依据硬件契约独立确定预期，不照抄实现逻辑。

保留最小复现参数、二进制和源码版本、测试返回码、串口日志，以及必要的 QMP、trace 或调试证据。区分地址映射错误、设备语义错误、镜像/设备树错误和集成参数错误，向相应负责人交接。若项目要求迁移或保存恢复，再验证相应状态兼容；不以本机启动成功推断未测试能力。

## Patch 与集成交接

按可评审的功能拆分模型、构建注册和测试 patch，记录上游基线、应用顺序、依赖、许可及未覆盖项，检查 patch 可在锁定的源码上应用。交付测试命令、预期和实际结果、日志位置、模型接口及启动参数；由集成成员核对配方与正式 patch 的对应关系。

项目采用上游源码加 layer patch 的模型时，临时开发 workspace 只用于实现与调试，长期 patch 进入已声明的成果物仓库。模型测试证据与集成成员清理临时 workspace 后的干净构建、系统运行证据分别保存并引用同一版本；不因 patch 导出完成就宣称系统验证通过。
