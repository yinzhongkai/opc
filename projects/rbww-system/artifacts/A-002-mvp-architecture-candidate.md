## 1. 结论摘要

MVP 采用 Windows 桌面客户端与服务端分工的架构。客户端使用 C++、Qt 和 SQLite，负责用户交互、结构化明细人工编辑与确认、本地确定性计价、报价留存和追溯。服务端以 Linux/glibc 为运行基线，使用 C++17/20、Drogon、libcurl 和 PostgreSQL，负责账号与年度订阅授权、PDF 临时分析、平台标准目录匹配、原材料价格快照、计价规则包发布和平台管理。生产环境在 Drogon 前部署 Nginx，开发环境可以由客户端直连 Drogon。

PDF 不在客户端解析。客户端上传 PDF 后，服务端异步完成文本提取、必要时 OCR、大模型结构化和目录匹配，返回候选 JSON；客户端只展示结构化明细并要求用户确认，不显示原始 PDF，也不实现字段原文定位或高亮。服务端仅临时保存 PDF 和分析中间结果，到期清理，不长期保存客户、报价单等生产商业务数据。

服务端不返回固定销售价，而是发布带签名和版本信息的价格与公式包。客户端以已确认的结构化数据、本地业务参数和目标毛利率完成计算，并保存完整计算凭证。目标毛利率以不含税、不含运费的出厂价计算：

```text
不含税不含运费出厂价 = 单位成本 / (1 - 目标毛利率)
```

税费与运费单独计算和展示。目标毛利率必须小于 100%，支持本地默认值和逐项覆盖。

## 2. 设计依据与约束

### 2.1 已确认约束

- 首期仅提供 Windows 桌面客户端，不建设 Web 客户端。
- 客户端不实现 PDF 解析、OCR 或大模型接入，不展示原始 PDF，也不做原文位置高亮。
- 结构化明细必须支持人工编辑和确认；未确认或无法处理的明细不得进入自动计价。
- 服务端维护全局标准管件目录、别名、计价公式模板、原材料价格及其来源，不维护生产商的长期业务数据。
- 当前不启用企业业务数据或多租户业务域，不为此预埋无实际语义的 `organizationId`。商业授权仍需区分订阅客户、账号和已激活客户端。
- 生产商只能通过受控业务接口取得授权范围内的平台数据，不能修改服务端平台目录、公式、价格源或其他客户数据。
- 同一 Windows 客户端可按服务端签发的平台管理员角色显示管理入口；管理接口与普通业务接口逻辑隔离。
- 原材料行情使用可插拔数据源适配器；没有正式行情网站时先实现人工维护和文件导入。
- PostgreSQL 用于服务端持久化；SQLite 和受管本地文件用于客户端持久化。

### 2.2 当前未知项

- 不同来源 PDF 的真实版式、扫描质量、字段名称、单位和异常样例。
- 管件目录的最终分类、规格属性、别名和匹配优先级。
- 实际成本公式、损耗、工艺费和本地参数的定义与取值边界。
- 正式行情网站或 API、授权方式、刷新频率、税口径和区域口径。
- 账号、客户端数量档位、离线宽限期、数据保留期和恢复目标。

这些未知项不阻止架构拆分，但会阻止识别准确率、报价正确性和生产可用性的最终验收。

## 3. 系统上下文与边界

```text
生产商用户
   |
   v
Windows 客户端（Qt / SQLite / 本地受管文件）
   | HTTPS
   v
Nginx（生产环境 TLS、反向代理、限流、上传限制、访问日志）
   |
   v
Drogon API（Linux/glibc） ───── PostgreSQL（平台数据、授权、任务元数据、审计）
   |
   +──── 分析 Worker（PDF 提取 / OCR / 大模型 / 目录匹配）
   |          |
   |          +──── 临时对象或文件存储（TTL 清理）
   |
   +──── 数据源适配器 ──── 人工录入 / 文件导入 / 未来 HTTP API 或网页源
   |
   +──── 大模型供应商接口

平台管理员 ── 同一客户端的管理入口 ── 独立管理 API ── 平台资源
```

边界原则：报价客户资料、报价单、毛利设置和计算凭证默认只在客户端长期保存；服务端只持久化跨客户端共享且由平台负责的数据，以及完成授权、异步处理和审计所必需的最小元数据。

## 4. Windows 客户端候选结构

建议模块如下：

| 模块 | 主要职责 |
|---|---|
| 登录与授权 | 登录、令牌刷新、订阅状态和设备激活状态展示 |
| 采购清单导入 | 选择 PDF、计算文件哈希、上传、轮询分析任务 |
| 结构化明细工作台 | 展示候选字段、校验告警、人工编辑、批量确认、无法处理标记 |
| 目录与规则缓存 | 缓存服务端发布的目录摘要、价格快照和带签名公式包 |
| 本地计价引擎 | 根据固定版本输入执行确定性公式，输出中间值和结果 |
| 报价管理 | 管理客户、报价单、版本、导出状态和手工销售价覆盖 |
| 凭证与追溯 | 保存输入哈希、结构化版本、价格和公式版本、参数、过程和结果 |
| 本地存储与备份 | SQLite 在线备份、文件引用、加密备份包和恢复校验 |
| 平台管理入口 | 仅平台管理员可见，调用独立管理 API，不提供远程 Shell、任意文件或直接数据库访问 |

建议将 UI、领域模型、网络访问、本地持久化和计价引擎分层。计价引擎不依赖 Qt 界面组件，以便使用固定测试向量进行单元测试和未来复用。

### 4.1 人工确认状态

每条结构化明细至少包含以下状态：

- `unreviewed`：尚未人工检查；
- `questionable`：系统识别或匹配存在歧义；
- `modified`：用户已编辑但尚未再次确认；
- `confirmed`：允许进入查询和计价；
- `unprocessable`：本轮不能自动处理，需人工报价。

只有 `confirmed` 明细可以自动计价。已确认字段发生修改后，目录匹配和计算结果立即失效，状态回到 `modified`。

## 5. 服务端候选结构

### 5.1 接入层

- Nginx 在生产环境终止 TLS、反向代理、设置上传大小和超时、限流并记录访问日志。
- Drogon 提供 HTTPS 后的业务 API，负责认证、参数校验、任务创建、数据查询和管理操作。
- PDF 分析不得在 HTTP 请求线程中等待大模型完成。创建任务后返回 `202 Accepted` 和 `jobId`，由 Worker 异步处理。

### 5.2 核心服务

- 授权服务：账号、年度订阅、席位、Windows 设备激活、短期令牌和权限校验。
- 分析任务服务：任务状态、临时文件引用、重试、超时、失败原因和 TTL 清理。
- 文档分析 Worker：原生 PDF 文本提取、OCR 降级、大模型结构化、字段规范化和置信度输出。
- 标准目录服务：标准管件、别名、核心关系字段与可扩展属性、候选匹配和歧义说明。
- 行情服务：数据源适配器、单位与币种归一、人工修正、不可变价格快照和过期策略。
- 公式服务：安全声明式公式、参数定义与边界、版本和生效期、签名发布包。
- 管理服务：平台配置、全局目录、公式、价格源、账号订阅、设备、任务队列、审计、备份恢复和版本信息。
- 审计服务：记录高权限及关键平台数据变更，不把密钥明文写入数据库或日志。

服务端内部访问外部大模型和行情接口使用 libcurl 等出站 HTTP 客户端；Drogon 是链接进应用的 C++ Web 框架，最终运行的是项目自己的 API 与 Worker 程序。

## 6. 关键业务数据流

### 6.1 PDF 到可确认明细

1. 客户端计算 PDF 哈希并调用分析任务接口上传文件。
2. 服务端校验授权、类型和大小，将文件放入临时存储，登记任务并返回 `jobId`。
3. Worker 优先尝试文本提取；文本不可用或质量不足时调用 OCR。
4. Worker 将受约束的字段模型交给大模型，取得候选 JSON；大模型输出必须经过模式、类型、枚举和范围校验。
5. 标准目录服务按规范化字段和别名给出唯一匹配、多个候选或未匹配结果，不自动猜测歧义项。
6. 客户端取得结构化结果，在明细工作台中编辑并逐项或批量确认。
7. 服务端按 TTL 删除 PDF、OCR 文本和大模型中间结果，仅保留完成任务和审计所需的最小元数据。

### 6.2 价格与公式包到本地计价

1. 数据源适配器获取原始行情，行情服务完成单位、币种、税口径、区域和时间归一。
2. 服务端生成不可变价格快照；人工修正生成新快照，不覆盖旧快照。
3. 服务端发布已签名计价包，包含价格快照、公式版本、参数定义与边界、生效和过期时间、最低客户端引擎版本。
4. 客户端校验授权、签名、有效期和引擎兼容性，将服务端平台参数与生产商本地参数组合。
5. 本地计价引擎只处理已确认明细，并保存过程值和计算凭证。
6. 用户可覆盖逐项目标毛利率或最终销售价；若覆盖销售价，客户端反算并显示实际毛利率，且记录操作者、时间和覆盖原因。

## 7. 数据与存储设计

### 7.1 服务端长期数据

- `subscription_customers`、`subscriptions`、`accounts`、`device_activations`、`roles`；
- `catalog_items`、`catalog_aliases`、`catalog_versions`；
- `materials`、`price_sources`、`price_observations`、`price_snapshots`；
- `formula_templates`、`formula_versions`、`parameter_definitions`、`pricing_packages`；
- `analysis_jobs` 的最小任务元数据和清理状态；
- `admin_audit_events`、运行配置的非敏感引用。

目录采用“关系型核心列 + JSON 扩展属性”：用于标识、筛选、关联和约束的稳定属性进入关系列；品类差异较大的附加属性进入受模式约束的 JSON。敏感密钥由专用密钥管理或部署环境提供，数据库只保存引用或加密材料。

### 7.2 客户端长期数据

- 客户、报价单、报价版本和明细；
- 原始 PDF 的本地受管副本及哈希；
- 结构化候选、人工修订、确认状态和目录匹配结果；
- 本地默认毛利率、逐项覆盖、生产商参数和用户偏好；
- 价格及公式包缓存、计算凭证、导出记录和本地审计信息。

PDF 等大文件保存在受管文件目录，SQLite 保存相对引用、哈希、大小和状态，不将大文件作为数据库 BLOB。客户端备份使用 SQLite 在线备份机制取得一致快照，再与受管文件和清单打包、校验并加密。

### 7.3 服务端临时数据

- 上传 PDF、提取文本、OCR 结果、大模型原始响应和规范化中间结果；
- 任务租约、重试上下文和短期诊断信息。

每类临时数据都要定义保留时长、成功与失败清理路径、清理失败告警以及人工清理入口。日志不得写入完整 PDF 内容或无脱敏的大模型请求。

## 8. 接口草案

接口版本统一放在 `/api/v1`，管理接口使用独立的 `/admin/v1` 路径、权限和审计策略。候选接口如下：

| 方法与路径 | 用途 | 关键结果 |
|---|---|---|
| `POST /api/v1/auth/login` | 登录 | 短期访问令牌、刷新令牌、角色和订阅摘要 |
| `POST /api/v1/devices/activate` | 激活 Windows 安装 | 设备激活状态与占用名额 |
| `POST /api/v1/analysis-jobs` | 上传 PDF 并创建分析任务 | `202`、`jobId`、清理期限 |
| `GET /api/v1/analysis-jobs/{id}` | 查询任务 | 状态、进度阶段、错误码 |
| `GET /api/v1/analysis-jobs/{id}/result` | 取得候选结构化明细 | 结构化版本、字段、置信度、匹配候选 |
| `POST /api/v1/catalog/match` | 对已编辑字段重新匹配 | 唯一、歧义或未匹配结果 |
| `GET /api/v1/pricing-packages/latest` | 获取适用计价包 | 签名包、版本、有效期和兼容要求 |
| `GET /api/v1/subscription/status` | 检查授权 | 订阅、席位、设备、宽限状态 |
| `/admin/v1/...` | 平台管理 | 目录、公式、价格源、授权、任务、审计与运维操作 |

所有写接口使用请求 ID 或幂等键；错误响应包含稳定错误码、可展示信息和可追踪请求 ID。管理接口不暴露远程 Shell、任意文件访问或直接 SQL。

## 9. 计价规则与追溯

### 9.1 规则表达

公式使用受白名单约束的声明式表达，允许算术、条件、查表和明确的单位转换，不允许任意脚本、动态库调用或文件/网络访问。每个公式版本必须声明：

- 适用品类和版本号；
- 所需输入、单位、精度、舍入规则；
- 平台参数、本地参数及取值边界；
- 中间结果与最终成本字段；
- 生效时间、失效时间和兼容的最低计价引擎版本；
- 内容哈希、服务端签名和替代关系。

### 9.2 目标毛利率

设单位成本为 `C`，目标毛利率为 `G`，不含税不含运费出厂价为 `P`：

```text
P = C / (1 - G)
实际毛利率 = (P - C) / P
```

客户端必须校验 `0 <= G < 1`；默认毛利率由生产商在本地设置，可逐项覆盖。税与运费是出厂价之外的独立项目，不能混入目标毛利率分母。若用户手工修改销售价，应显示反算后的实际毛利率，避免将“成本加价率”误当成“毛利率”。

### 9.3 计算凭证

每次计算至少保存：

- PDF 或输入数据哈希、结构化数据版本和确认状态摘要；
- 标准目录项及目录版本；
- 价格快照 ID、来源、采集时间、单位、币种、税和区域口径；
- 公式版本、计价引擎版本、计价包哈希和服务端签名；
- 平台参数、本地参数、目标毛利率及其默认或覆盖来源；
- 中间结果、舍入过程、最终结果和手工覆盖记录；
- 操作者、计算时间与客户端实例标识。

历史报价重放默认使用原凭证中的固定版本，不静默切换到最新行情或公式。

## 10. 价格数据源适配器

统一适配器输出候选字段包括：材料编码、原始名称、价格、币种、计量单位、税口径、区域、报价或采集时间、来源引用、原始内容哈希和质量标记。首期实现：

- `ManualPriceAdapter`：平台管理员人工录入，保留录入人与依据；
- `FileImportAdapter`：从约定模板导入并生成校验报告；
- `MockPriceAdapter`：只用于开发和测试，不得用于生产报价。

未来的 HTTP API 或网页适配器实现同一接口。每次导入先形成原始观测，再经归一化和审核生成不可变快照。价格过期阈值按材料或来源配置；过期、缺失或口径不匹配时禁止静默使用，客户端显示明确告警或停止自动计价。

## 11. 认证、订阅与平台管理

年度商业授权按“订阅客户 + 账号席位 + 已激活 Windows 客户端数量”建模。访问令牌短期有效，敏感管理操作要求更强认证，可启用 MFA 和再次认证。订阅到期后至少阻止新 PDF 分析、最新价格和公式包下载及重新计价；是否提供只读和导出宽限期由商业规则另行决定。

平台管理员是服务运维和平台数据维护角色，不是生产商企业管理员。管理能力包括运行健康、分析任务和队列、模型与数据源非敏感配置、全局目录与公式、订阅账号与设备、审计、备份恢复、版本和升级状态。密钥输入只写不回显，列表和日志只显示掩码。

普通生产商账号不能调用管理 API，也不能更改服务端目录、公式、行情源或授权数据。未来若确有企业业务数据需求，再以明确业务边界引入租户标识和数据隔离，不提前把无语义字段扩散到现有接口。

## 12. 备份与恢复候选方案

### 12.1 服务端

- 每日 `pg_dump` 逻辑备份业务数据库，并备份角色和全局对象；
- 备份加密后复制到服务器之外，按日、周、月设置保留策略；
- 定期执行自动完整性检查和人工恢复演练，记录恢复时间与结果；
- 当数据量和恢复目标要求提高时，引入 `pg_basebackup`、WAL 归档和时间点恢复；
- 临时 PDF 默认不进入长期数据库备份，避免与 TTL 清理策略冲突。

### 12.2 客户端

- 使用 SQLite 在线备份 API 生成一致数据库快照；
- 将数据库快照、受管 PDF/导出文件和清单打包，校验哈希并加密；
- 恢复前验证版本、完整性和可用空间，恢复后校验数据库与文件引用；
- 明确本地备份位置、保留数量和用户责任，避免只备份单个 `.db` 文件。

具体 RPO、RTO、保留天数和异地介质待生产部署需求确认。

## 13. 关键质量属性

| 属性 | 候选要求与设计响应 |
|---|---|
| 正确性 | 未确认明细不计价；目录歧义不猜测；固定版本公式、价格和舍入；测试向量校验 |
| 可追溯性 | 输入、人工修订、目录、行情、公式、参数、中间值和结果均带版本或哈希 |
| 安全性 | HTTPS、短期令牌、最小权限、管理面隔离、密钥不回显、审计、临时数据 TTL |
| 隐私 | 报价业务数据客户端长期保存；服务端最小化持久化；日志脱敏 |
| 可用性 | 异步任务、可重试、幂等、超时和错误码；本地历史报价在服务暂不可用时仍可读取 |
| 可维护性 | Qt 客户端分层；Drogon API 与 Worker 共享领域库；价格源适配器和声明式公式版本化 |
| 可恢复性 | PostgreSQL 异机备份与恢复演练；SQLite 一致快照和文件清单 |
| 可观测性 | 请求 ID、任务阶段、指标、结构化日志和平台审计，不记录敏感正文 |

具体并发量、响应时间、识别准确率、清理时限、RPO 和 RTO 需在取得样例及部署规模后量化。

## 14. 候选方案权衡

| 选择 | 采用理由 | 代价与控制 |
|---|---|---|
| 服务端 PDF 分析 | 集中管理 OCR/大模型能力和提示词，客户端更轻 | 上传涉及隐私和网络依赖；采用 HTTPS、最小留存、TTL 与日志脱敏 |
| 客户端本地计价 | 保护本地参数和报价数据，可离线重放，降低服务端业务数据责任 | 必须保证引擎一致和规则可信；使用签名版本包、测试向量和最低引擎版本 |
| PostgreSQL 服务端 + SQLite 客户端 | 分别适合并发平台数据与单机业务数据 | 形成双端备份责任；分别定义恢复流程，不做隐式双向同步 |
| Drogon + Nginx | Drogon 适合 C++ 业务 API，Nginx 承担生产入口通用能力 | 增加部署组件；开发环境可直连，生产以配置和监控降低复杂度 |
| 关系列 + JSON 扩展属性 | 兼顾标准查询与品类差异 | JSON 仍需模式和版本管理，禁止成为无约束字段仓库 |
| 当前不启用多租户业务域 | 符合当前没有企业业务数据的边界，降低误用 | 若需求出现需显式迁移，不承诺零成本扩展 |

## 15. 主要风险与验证计划

| 编号 | 风险或假设 | 验证实验 | 通过标准候选 | 所需输入 |
|---|---|---|---|---|
| V-01 | 非固定 PDF 的抽取质量未知 | 建立脱敏样例集，分别测试文本 PDF、扫描 PDF、复杂表格和异常页 | 关键字段准确率、漏项率和人工修订耗时达到与用户共同设定的阈值 | 真实脱敏 PDF 与正确答案 |
| V-02 | 大模型输出可能不稳定或越界 | 对固定样例重复运行，执行 JSON Schema、枚举、范围和提示注入测试 | 非法输出全部被拒绝或转人工；同样例关键字段稳定 | 模型候选与字段模型 |
| V-03 | 标准目录匹配可能误报 | 用已标注目录项测试唯一、歧义、未匹配和别名场景 | 不把歧义项自动判为唯一；误匹配率达到商定阈值 | 目录、别名和历史描述 |
| V-04 | 本地与服务端规则版本可能不兼容 | 使用签名包、最低引擎版本和黄金测试向量做兼容测试 | 篡改包被拒绝；不兼容版本被阻止；黄金结果一致 | 真实公式和舍入规则 |
| V-05 | 行情口径不同导致成本错误 | 对单位、币种、税、区域和时间做归一化与过期测试 | 口径不完整或过期时明确阻断或告警，不静默换算 | 行情样例或导入模板 |
| V-06 | 临时 PDF 未按承诺清理 | 覆盖成功、失败、超时、重试和进程中断场景的清理测试 | 到期文件和中间结果可证明清除，失败触发告警 | 确认 TTL 与部署存储 |
| V-07 | 订阅与设备计数可被绕过 | 测试并发激活、令牌撤销、过期、时钟偏差和离线场景 | 超额和到期策略一致，审计可追踪，不破坏历史只读数据 | 商业授权细则 |
| V-08 | 备份存在但无法恢复 | 在隔离环境执行 PostgreSQL 与客户端备份恢复演练 | 数据、文件引用和凭证抽样一致，达到约定 RPO/RTO | 部署规模和恢复目标 |
| V-09 | Nginx 与异步任务配置不当 | 测试大文件、慢上传、超时、限流、任务积压和 Worker 重启 | API 快速返回任务 ID；无重复计费或任务丢失；可观测 | 目标文件大小和并发量 |

在 V-01、V-03、V-04 和 V-05 获得真实资料并通过之前，架构可以进入技术骨架设计，但不能宣称已验证报价正确性。

## 16. 推荐的后续开发拆分

1. **领域与接口基线**：确认字段字典、JSON Schema、状态机、错误码、目录模型和计价凭证格式。
2. **服务端骨架**：Drogon API、PostgreSQL 迁移、认证授权、任务队列抽象、审计和健康检查。
3. **PDF 分析验证原型**：文本提取、OCR 降级、大模型结构化、模式校验及 V-01/V-02 样例报告。
4. **目录与行情**：标准目录导入、别名匹配、人工/文件价格适配器、归一化和快照。
5. **规则与本地计价原型**：声明式公式、签名包、Qt 侧计价引擎、黄金测试向量和凭证。
6. **Windows 业务工作台**：登录、导入、异步任务、结构化编辑确认、报价管理、导出和本地备份。
7. **平台管理面**：独立权限的目录、公式、价格源、授权、设备、任务、审计和运维界面。
8. **生产入口与恢复验证**：Nginx、TLS、限流、部署配置、服务端和客户端备份恢复演练。

每项开发工作需在有明确授权和产品工作区后另建任务；当前 `WORKSPACE.yaml` 为 `none`，本文不授权创建产品源码。
