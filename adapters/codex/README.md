# Codex 使用方式

向当前会话提供所克隆仓库的根目录，并确认所需文件可访问。本说明不假定会话能从标题获得身份，也不保证会话之间自动通信或同步资料。

## 启动入口

从根 [AGENTS.md](../../AGENTS.md) 进入。新建管理员会话时可发送：

```text
框架根目录：<repository-root>
你是超级管理员。我要创建一个 space-rhythm（太空律动）的项目。
```

管理员工作遵循 [SUPER_ADMIN.md](../../SUPER_ADMIN.md)。启动项目成员时，使用管理员返回的启动消息，或以实际值替换下面的占位符：

```text
框架根目录：<repository-root>
项目：<project-id>
成员：<member-id>
请按 SESSION_PROTOCOL.md 初始化，并查看当前工作。
```

## 资料与协作条件

身份解析、知识加载和项目资料的分层读取统一按 [会话协议](../../SESSION_PROTOCOL.md)，本说明不另列全量历史必读清单。建项与工作流见 [项目运行协议](../../PROJECT_PROTOCOL.md)，配置字段见 [CONFIG_SCHEMA.md](../../CONFIG_SCHEMA.md)。

用户负责启动和切换实际会话，保证当前仓库每次只有一个会话执行；评审期间保持受评版本可读取且不变，直到本轮全部意见提交。具体约定以项目运行协议为准，框架不提供自动调度或会话锁。

无法读取所需资料时列出具体缺口；无法写回时提供目标路径和建议内容，明确尚未保存。不要把无法访问的文件视为已读，或把建议写回描述为已完成变更。
