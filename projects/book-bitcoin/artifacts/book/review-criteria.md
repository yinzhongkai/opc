## 已确认结论

审核全部 13 篇，保留面向有 1–3 年经验、能读 C/C++ 并使用 Linux 的开发者定位。采用“关键主张有一手依据、主线操作可复现、配套资料可取得、问题有实际复核”的标准。正文的图和脚本随书提供；附录保留从零构建的学习过程，同时提供独立入口的完整参考解答，便于读者排查失败。

## 实验覆盖与证据最低要求

T-006 先建立矩阵，再取得证据。覆盖序章搭建与 regtest 冒烟、九章不同主线实验、18 个引用脚本、钱包 / RPC / 索引 / 通知的关键前置，以及附录四个子命令和 UTXO 对账。一个实验可以覆盖多个 C 编号；源码节选可通过版本定位检查，示意输出通过标注与解释检查。

每条运行记录至少包括：章节与示例 / 脚本 ID、受评正文 commit、配套 commit 或文件指纹、Core commit 与二进制来源、操作系统 / 内核 / 工具实际版本、必要配置与网络、执行者与日期、前置状态、命令、预期、实际结果、原始证据位置、结论和未覆盖范围。数据分析另记链高区间、相应块哈希、索引 / prune 状态及价格数据来源。凭据不进入证据包。

读者主线需要的每条关键路径应有一次完整的端到端证据；影响结论的拒绝、回滚、替换、索引未就绪或数据不完整情形，按章节实际主张加入检查。该要求不扩展成通用软件测试套件，不要求跑遍所有可选平台、全量链数据或 Core 全部测试。

性能结论需有采样条件与原始数据，并说明自身测量的限制；没有运行记录时可保留明确标注的演示，但不得继续作为“实测”或定量性能证明。缺失关键运行证据记未验证，不用静态核查或框架链接校验填成通过。

存储采用现有产品仓库；`bitcoin-tools/` 和书稿资源目录是 T-004 落实布局的起点。治理清单、审校意见与验证结论继续在 OPC；可交付的图、程序、样例和原始运行文件保存在声明且获授权的产品工作区。本轮只固化标准与边界，业务材料由后续获授权任务提供。

## 问题分级与通过条件

| 级别 | 影响 | 处理要求 |
|---|---|---|
| 阻断 | 核心概念 / 规则错误、主线实验无法完成、所需配套缺席、证据与结论不一致，或误导性数据解释影响章节核心结论 | 候选验收前修正并实际复核；若改范围或保留限制，由用户决定且更新正文承诺，不由项目经理代作技术通过 |
| 重要 | 关键前置未交代、来源 / 版本不完整、跨章不一致或解释使目标读者容易误用 | 本轮明确处理；残余项有理由、影响和用户接受记录 |
| 一般 | 局部措辞、体例、非主线提示或图稿可读性问题 | writer 统一修订并按影响检查；不要求每条纯格式调整重新跑实验 |

分级由实际专业评审者依据影响提出，项目经理协调分歧。评审结果可以是 pass、revise 或 blocked；“本轮全部意见提交”表示可进入统一修订，不表示所有人通过。出版候选必须有完整覆盖和实际复核，无未处置的阻断；其他残余项向用户明示。任何例外记录到具体版本与决定，不能默默降低标准。
