## 2. 用户准备的数据

已有记录继续在实操表中更新。表内没有的日期、费用或说明，可随通知补充，不要求另建一套台账。

| 内容 | 每次需要核对的记录 | 不完整时仍可做什么 |
|---|---|---|
| 月份与时点 | 分析月份、期中/已结月/更正、持仓和余额截至日期、估值时间 | 可以核对已发生投入，结论标明记录阶段 |
| 外部资金流 | 本期新增资金、提款、转出分红的实际金额及日期；账户间转账注明去向 | 金额明确可对账；日期缺失时不计算 XIRR |
| 定存 | 新存本金、合同利率、起息及到期日、已结利息、续存和提前支取记录 | 可确认本金及合同信息，未确认利息不当作实际到账收益 |
| ETF | 实际持有份额、资金池余额、交易日期与金额、费用、分红去向 | 可区分拨款、买入和现金等待 |
| ETF 逐笔预算 | 归属月份、实际划入日期、已用及剩余金额；成交时参考溢价及来源、时间 | 缺划入日期则到期日待核实；缺成交时估值依据则规则执行无法核实 |
| BTC 与 USDT | BTC 数量、USDT 余额、买卖及兑换日期金额、手续费；平均取得成本的币种 | 可核对持仓与成本，实际换汇成本和当前估值汇率分别处理 |
| 估值依据 | ETF 价格、BTC 价格、USD/CNY、独立 USDT/CNY 的来源与时间；期初及期末持仓快照 | 可提供注明时点的参考估值，期间收益需可比期初数据 |

资金流范围保持一致。资金从银行进入组合计为外部投入；组合内部账户划转只记一次；ETF 预算留在现金池、BTC 预算留为 USDT 时，分别显示为现金和 USDT，不当作已经买入 ETF 或 BTC。

## 3. 投资顾问收到材料后的顺序

1. **固定输入版本。** 刷新项目规则、工作区和当前版本，重新读取文件，记录文件大小、SHA-256、月份、阶段及估值时点。先保存用户输入的 Git 提交，再进行分析；文件没变则引用已有提交。发现另一个文件也被独立修改时先核对来源。
2. **核对资金和持仓。** 对照本期计划、实际外部投入、内部转账、成交、费用和余额，解释变化。后续空白月份保持“未记录”。
3. **检查 ETF 纪律。** 逐笔核对积压资金的年龄和剩余金额，对照买入时能取得的溢价信息，列出已到期及下一期将到期的资金。规则见第 4 节及 A-002。
4. **确定估值范围。** 核对持仓、价格与汇率时点；已结月使用该期保存的估值依据，期中使用注明时间的参考报价。公开报价查询保留来源、报价时间、查询时间及可用性；无法取得的数据继续标缺失。
5. **计算能核实的指标。** 按第 5 节区分本金增加、成本浮盈和期间投资盈亏；现金流日期及估值完整才计算 XIRR。检查实际配置、存款到期及可动用资金。
6. **比较上期。** 从上期对应的 Git 提交读取原文件或复盘结果，检查时期、账户范围和币种口径是否可比。上期只有期中记录时明确注明，不能当作上月末基准。
7. **交付并留存。** 按第 6 节回复本期结论，更新成果物仓库唯一当前详细复盘，治理记录保存来源、口径与缺口；完成本地 Git 验证和引用同步。每季度在当期复盘中补充实际仓位检查。

完整数据未齐时，先交付已经核实的部分，并列出缺少哪项、影响哪个指标、由谁补充。一次分析完成不代表缺失数据已经获得验证。

## 4. ETF 每月检查清单

以下为 A-002 v1.0 的执行摘要；调整规则时先更新其确认记录，再同步本流程。

| 买入时可核对的参考溢价 | 本期检查事项 |
|---|---|
| ≤2% | 当月未投入预算及可投入积压按准则处理，核对有无重复使用同一预算 |
| >2% 且 ≤5% | 当月未投入预算可以投入，旧积压继续等待；已到期资金按到期规则处理 |
| >5% | 暂缓普通买入，资金留在指定现金池；已到期资金按到期规则处理 |

每笔积压从**实际划入日期起计算六个日历月**。按 A-002 的固定交易日及到期后首个交易日安排，处理该笔剩余余额；不能仅凭资金池达到 6 万元就认定全部到期。优先核实合适的同指数低溢价产品或净值渠道，没有合适替代时按已确认准则投入 513500。到期处理优先于 >5% 暂缓规则。成交由用户执行，限价、费用和零头按台账核对。

复盘逐笔列出“预算月份、划入日期、剩余金额、到期日、执行状态、下期事项”。缺少日期或交易时溢价依据，状态写“待核实”。公告提示高溢价不等于给出了具体溢价率；不得用今天的溢价或事后净值重判过去交易，也不使用事后才能确定的“当月最低溢价日”。

ETF 等待资金留在专项池，不转给 BTC。定存月度计划为 25000 元，ETF 为 10000 元，BTC 为**不超过 5000 元**；BTC 上限不等于必须全部买入 BTC。投入计划与实际资产占比分别核对。

## 5. 市值、收益和目标的统一口径

全部汇总为人民币，并注明估值截止点、覆盖账户和费用状态。定存按已确认账面价值，ETF 按持有份额和价格，BTC 按数量和相应报价，现金及 USDT 分别估值。USD/CNY 与 USDT/CNY 使用独立含义；聚合行情隐含换算汇率须注明来源，实际成交汇率和费用另列。

| 指标 | 计算与解释 |
|---|---|
| 组合市值 | 定存确认账面价值 + ETF 市值 + BTC 市值 + 各账户现金/USDT；避免同一资金重复计算 |
| 本期净外部投入 C | 外部新增资金减外部提款/转出；内部转账及组合内分红再投资不重复计入 |
| 本期投资盈亏 | 期末市值 − **经核实的期初市值** − 本期净外部投入；期初、期末和资金流范围必须一致 |
| 相对累计成本的浮盈 | 当前市值 − 对应累计成本；可能包含原有持仓的收益，不能直接称为本月收益 |
| XIRR | 按实际日期：期初估值与新增投入为负，外部提款为正，终点估值为正；输入完整且可计算时单独列示年化结果 |
| 实际配置 | 分别列定存、ETF、BTC、人民币现金、USDT 的市值与占比，必要时说明币种敞口和资金限制 |
| 目标观察 | 组合市值 ÷ 10000000 为金额进度；10000000 − 组合市值为缺口，超过目标时列超过金额 |

总资产增加可能来自追加本金。XIRR 是现金流年化指标，短期结果须注明实际覆盖期间；它不代替本月盈亏金额。未知费用不默认为零，参考市值与扣费后的可变现净额分开。

当前实操表的 C5、C6、C7、C9 分别为 ETF 价格、BTC 美元价格、USD/CNY、USDT/CNY，来源时点在 D 列。C8 为固定期初基准，仍需核实；AE/AF 列的现有公式不能直接当作已验证的月度收益或年化收益。共享价格参数更新会重估以前月份的行，历史比较必须读取当期 Git 版本。

目标沿用 2036 年 12 月人民币 1000 万元及原有持仓纳入范围。金额进度不是达标概率；实际回撤需要可比的收益序列，不能把含持续投入的总资产峰谷直接当作投资回撤。风险阈值、统一复盘截止点及提示条件仍按 A-001 待定。

## 6. 每次复盘的交付结构

以下是重复使用的结构，不是已完成的新月份报告。详细个人数值写在成果物仓库和本次分析回复中，OPC 仅留口径、版本、缺口与结论。

| 输出 | 应回答的问题 |
|---|---|
| 复盘说明与主要结论 | 哪个月、哪个阶段、截至何时、用了哪个输入版本；本期最需要关注的变化是什么 |
| 投入执行表 | 定存、ETF、BTC 的计划与实际差异；多少已划入、已买入、仍为现金或 USDT |
| 估值与收益表 | 各资产市值和占比；本期净投入、期间盈亏、成本浮盈分别是多少；哪些指标无法核实及原因 |
| ETF 预算检查表 | 每笔积压何时到期；交易是否有当时的溢价依据；下期按准则需处理哪些资金 |
| 配置、流动性与目标观察 | 实际敞口如何变化；定存何时到期、可用现金是否明确；可靠市值对应的目标进度与缺口 |
| 下月行动清单 | 用户需补哪些记录或按既定准则处理哪些资金；投资顾问下次需核对哪些问题，涉及规则调整的建议单独列示 |

季度复盘增加实际资产和币种占比、集中度、存款到期与近期用钱需求检查。未确认仓位或回撤阈值时描述事实与变化，不自动触发卖出或调仓。

常规月度复盘沿用已有模拟资料的已知状态。需要重新模拟或改变假设时单独登记任务，保存数据区间、模型/程序、参数和随机种子，核查之后再解释情景结果；不把已有静态分位当作已验证的未来达标概率。

## 7. 版本和历史怎么保存

- **当前输入：** 成果物仓库 `portfolio/实操记录.xlsx`；模拟文件独立，按 A-003 v2.0 维护。
- **当前详细结果：** 成果物仓库 `portfolio/analysis/latest.json`，记录月份、阶段、原始输入提交/哈希、估值来源、计算口径、结果及缺口。后续新一期更新同一文件，旧结果通过 Git 读取。
- **治理记录：** OPC 的对应任务、A-004 当前核查记录及成果索引，注明成果物仓库、路径和最终提交。流程修订更新本文件版本记录。
- **历史与更正：** 不另建永久月度副本、历史目录或索引。更正新增提交，保留原提交、原因和影响，不改写已采用的历史。

每次实际工作先核对工作区与 Git 基线，按根 [分支策略](../../../BRANCH_STRATEGY.md) 建立任务分支。用户输入先单独提交；授权报价/公式写回与复盘结果注明差异。成果物先以 `--ff-only` 合入 main 并验证，再将最终提交同步到 OPC，完成治理合并和核对后安全清理开发分支。只有治理文档变化时，成果物变更记为不适用。

最新的行情只在明确的当前参考范围使用。需要写回时先保存用户输入，记录实际修改单元格和来源，再验证公式、缓存及非目标内容；当前参考估值不能替换已固定的历史估值。

## 8. 本流程的执行边界

用户每月更新并通知，投资顾问收到对应版本后分析一次；后续补录或更正依据新材料再次核对。日期和阶段由材料说明，尚未采用统一的月末截止规则。本流程沿用已确认的投资纪律，预算、阈值、等待期限或产品调整由用户决定。

数据更新后的分析与本地 Git 留存按现有授权进行；价格写回按用户当次要求执行。后台定时运行、额外提醒、账户访问、远程推送或交易执行若另有需要，单独按对应请求安排。本次仅生成流程文档，当前 10 月核查结果及工作簿保持现有版本。
