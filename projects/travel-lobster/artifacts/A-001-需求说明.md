## 1. 背景与已确认目标

已确认目标（PROJECT.md）：打造「旅行龙虾」——一个龙虾形象（类似数字人），代替打工人去旅行，以 plog 形式记录龙虾自己的旅行，并发布到小红书。

需求分析解读：核心用户价值是**情绪代偿**——没时间/没钱旅行的打工人，通过龙虾的"替我去旅行"获得治愈、代入感和谈资。"龙虾"是差异化记忆点，"plog 形式"和"发布到小红书"是当前明确的载体选择，不直接等同于需求本身（载体可随决定调整）。

## 2. 目标用户与场景（对应 D-001）

【候选】两类相关人群需区分：

- **内容消费者（主要服务对象）**：18–35 岁一二线城市打工人，刷小红书解压；对"可爱动物 + 旅行 + 打工人梗"内容有天然好感。
- **项目所有者（账号运营方，即用户本人）**：希望以可控成本持续产出内容。

【候选】三个典型读者画像（验收时需可核对）：

1. 加班后深夜刷手机的互联网从业者，看到龙虾在海边发呆会心一笑，点赞收藏。
2. 计划旅行但一直没成行的白领，把龙虾 plog 当"云攻略"收藏。
3. 喜欢萌宠/玩偶账号的年轻女性用户，关注龙虾人设追更。

【待确认】核心场景判断标准：每篇内容发布前应能回答"目标读者为什么会点赞/收藏/关注"，回答不出则不发布。

## 3. 龙虾形象设定（对应 D-002）

【候选】视觉路线三选一：

| 方案 | 描述 | 优点 | 风险/成本 |
|---|---|---|---|
| A. 实拍玩偶 | 购买龙虾玩偶，在真实场景实拍 | 真实感强、成本低的"实景感" | 需要真实旅拍素材或出门拍摄 |
| B. AI 生成 | AI 生成统一形象的龙虾 + 场景 | 不出门即可产出任何目的地 | 形象一致性需工程化控制；平台对 AI 内容有标注要求 |
| C. 插画/表情包 | 手绘或设计固定龙虾插画形象 | 一致性最好、风格化强 | 需要设计资源；真实感弱 |

【候选】人设方向：社畜龙虾——替打工人请了年假出门旅行，第一人称碎碎念，偶尔吐槽老板和 KPI，但整体治愈向。

【待确认】龙虾名字、性格关键词（3–5 个）、视觉路线（A/B/C 或组合）。

## 4. plog 内容形式（对应 D-003）

【候选】单篇结构：封面图 + 6–9 张图，龙虾第一人称叙事；统一封面模板与固定开场/收尾句式，形成可识别的系列感。

核心流程拆解：

- **正常路径**：选定目的地主题 → 规划本篇行程点 → 产出素材（实拍/AI/插画）→ 撰写文案 → 套模板成稿 → 发布。
- **边界**：单个目的地拆成多篇时，需提前规划拆分点（到达篇/美食篇/发呆篇等），避免内容重复。
- **异常路径**：素材不足时允许纯文案 + 表情包式配图兜底；发布审核不通过时需有修改重发流程。

【待确认】叙事视角（第一人称 vs 第三人称旁观）、单篇图片数量区间、是否固定栏目（如"龙虾周一不想上班"）。

## 5. 更新节奏（对应 D-004）

【候选】每周 2–3 篇；单个目的地 3–5 篇后"转场"下一个目的地；重大节日做特别篇。

【待确认】可承诺的最低更新频率（影响账号权重与读者预期）；是否预留素材缓冲（建议常备 2 篇存量）。

## 6. 小红书发布方式（对应 D-005）

【候选】初期人工发布（手机端手动），流程稳定后再评估工具辅助；账号使用专用新账号而非个人主号。

【待确认】

- 账号归属与注册主体（个人号/企业号）。
- 发布执行方式（人工 / 工具辅助 / 自动化），及对应的账号安全风险接受度。
- 合规边界：AI 生成内容的平台标注要求、实拍素材版权、商业推广接口（首期不涉及则记入非目标）。

## 7. 范围与非目标（对应 D-006）

【候选】首期范围：小红书单平台、plog 图文、单一龙虾形象、中文内容。

【候选】非目标（首期不覆盖）：

1. 视频 / vlog 形式。
2. 多平台分发（抖音、微博、Instagram 等）。
3. 商业化变现（接广告、带货）。
4. 多形象或龙虾"宇宙"扩展。
5. 与读者线下互动 / 寄明信片等实体玩法。

## 8. 优先级建议（依据：用户价值 → 依赖 → 风险 → 成本）

| 优先级 | 事项 | 依据 |
|---|---|---|
| P0 | 龙虾形象与视觉路线（D-002） | 所有内容产出的前置依赖，返工成本最高 |
| P0 | 账号与发布方式（D-005） | 没有账号无法验证任何东西 |
| P1 | 内容形式与栏目（D-003） | 决定单篇生产流程与模板 |
| P1 | 目标用户确认（D-001） | 影响文案语气与选题方向，可与形象并行 |
| P2 | 更新节奏（D-004） | 可在首批内容上线前确定 |
| P2 | 范围与非目标（D-006） | 框定后续所有扩展请求的判断基准 |

## 9. 验收标准汇总（需求 → 可验证条件）

| 编号 | 需求 | 可验证验收条件（候选，随决定修订） |
|---|---|---|
| AC-1 | 形象可识别 | 任意 3 篇内容封面并排，读者能认出是同一个龙虾形象 |
| AC-2 | 人设一致 | 任意 5 篇文案不出现相互矛盾的性格表述（由 3–5 个性格关键词清单核对） |
| AC-3 | plog 结构统一 | 单篇图片数量在约定区间内，封面套用统一模板 |
| AC-4 | 更新可承诺 | 连续 4 周实际更新频率不低于约定最低频率 |
| AC-5 | 发布通道可用 | 账号正常发布、无因操作方式导致的处罚记录 |
| AC-6 | 读者价值自检 | 每篇发布前完成"为什么会点赞/收藏"自检并留痕 |
