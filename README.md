# 成员、岗位与知识：项目协作框架

用普通 Markdown 和 YAML 组织多个成员会话，适用于软件开发、研究、旅行规划、图书写作等工作。一般每个业务项目独立克隆一份框架；超级管理员负责建项和创建成员文档，用户打开并启动成员会话，成员通过项目文件共享进展与成果。

框架提供共享岗位和基础知识。`projects/` 用于存放实际项目，允许为空或尚不存在（Git 不保存空目录）；空白模板位于 `templates/project/`，不代表实际项目或已创建的成员会话。

## 核心关系

- 超级管理员是当前克隆仓库的框架管理入口，不是项目成员，不替代项目经理推进业务。
- 成员是项目中的具体工作身份，以独立 `members/<member-id>.yaml` 保存唯一配置，只对应一个岗位，以 `scope` 表达分工。
- 岗位定义共同职责、边界和基础知识，位于 `roles/`。
- 知识是可复用的工作方法，位于平铺的 `knowledge/`；项目通过 `roleKnowledge` 补充知识。
- 项目保存目标、成员、任务、决定、交接与成果；TEAM 只登记成员 ID 和项目岗位知识，不重复成员字段。

例如前端和后端成员可以同属 `developer`，加载相同的项目岗位知识，以 `scope` 区分工作。读取知识不授予额外职责或工具权限。这些知识文件也不是平台原生 Skills。

## 推荐使用流程

以下是操作示例，不会在仓库中预置太空律动或任何真实成员。

1. 克隆框架并在使用的平台打开，确认各会话能访问同一项目资料及所需版本。不同克隆或工作副本不会因为项目同名就自动同步。
2. 打开一个会话，可以命名“超级管理员”，并发送：

   > 你是超级管理员。我要创建一个 space-rhythm（太空律动）的项目。

   会话按 [超级管理员入口](SUPER_ADMIN.md) 建立项目资料；未知目标保持待确认。没有指定首批成员时先建空团队，不需要预先加入项目，也不默认配置管理员成员。
3. 继续在超级管理员会话中说明：

   > 为这个项目创建项目经理、产品经理和系统架构师。

   超级管理员按需求建立各成员配置文件、登记团队索引，并返回实际路径、分工和启动消息。配置岗位不等于替用户创建平台会话。
4. 用户分别打开新会话，发送例如：

   > 你是项目经理，请初始化并查看当前工作。

   当前仓库只有一个实际项目、该岗位只有一名在册成员时，直接找到成员文件、加载岗位和知识并返回绑定回执；多个项目或多人同岗时只补问必要信息。未创建成员时提示先找超级管理员，不在新会话中自动建员。会话名称只是标签，不代替这一条声明。
5. 向成员指派工作，成果保存到项目中。需要跨角色评审时，由项目经理组织已有成员在原会话处理，用户进入相应会话继续，不默认增设评审会话。

精确指定身份时也可以使用“项目：<project-id>；成员：<member-id>；请初始化”。会话绑定的是项目与成员配置，不是岗位名称本身，也不是平台账号。更换会话同样遵循下文的用户控制串行执行约定。

维护框架、建项和创建成员的规则见 [项目运行协议](PROJECT_PROTOCOL.md)；初始化、失败处理和刷新见 [会话协议](SESSION_PROTOCOL.md)。

初始化分层进行：身份、岗位与有效知识必读；台账先定位本人当前任务、评审和交接，再读取相关条目及依赖；无关的已完成任务、旧交接和历史成果按需追溯。扫描或摘要不冒充相关正文已读。

| [roles/INDEX.md](roles/INDEX.md) | 岗位目录及定义 |

## 日常协作

成员可以登记用户明确指派给自己的任务，记录授权来源、完成条件和实际结果。项目经理负责团队计划；暂时没有项目经理时，由用户确认跨成员安排，指定成员整理记录。

项目的 `TEAM.yaml` 保存成员 ID 和项目岗位知识，成员文件保存身份与分工，`TASKS.md` 保存任务事实，`DECISIONS.md` 保存决定，`HANDOFFS.md` 保存行动请求，`STATUS.md` 汇总当前进展。无协调记录维护人时可标待指定，不阻止有效成员处理已授权任务。具体责任和工作流状态转换统一在 [项目运行协议](PROJECT_PROTOCOL.md) 中定义。

专业交叉评审按“作者提交版本、项目经理安排、相关成员依次在原会话评审、本轮全部意见提交后作者统一修订、评审者复核”进行。评审期间由用户保证受评版本可读取且不变，不强制保存快照或提交 Git。意见必须注明实际评审人、受评版本和证据；任务完成、评审通过与最终批准分别记录。独立评审者岗位保留为可选项，当前默认流程不要求新增该岗位或会话。

小规模评审默认直接记录在原任务中，保存安排、署名意见、作者回复与复核结果，不为每位评审者另建任务、交接和报告。需要单独跟踪或正式报告时再按项目运行协议拆分。

用户负责启动和切换会话，保证当前仓库每次只有一个会话执行，包括超级管理员和项目成员；前一会话完成或停止后再启动下一会话。交接记录不会自动启动其他会话，框架不实现文件锁或自动调度。无法写文件时，会话应交付具体写回路径与建议内容，并说明尚未保存。资料同步和历史由用户通过 Git 管理。

## 检查框架

需要 Python 3.10 或更新版本和 PyYAML。在所选 Python 环境中安装依赖后运行：

```text
python -m pip install -r scripts/requirements.txt
python scripts/validate_framework.py
python -m unittest discover -s scripts -p "test_*.py"
```

校验器检查必需文件、配置类型、成员索引与文件对应、定义引用、模板和本地 Markdown 链接。无实际项目或空团队都是合法状态；模板中的占位符不代表已建项。当前配置版本为 3，版本 1、2 必须按迁移说明处理，不能只改版本号。校验成功不证明业务成果正确、自然语言已被正确解析、用户已经批准或会话已经初始化。

平台使用说明：[Codex](adapters/codex/README.md)、[Kimi Work](adapters/kimi/README.md)。
