# C++ 核心系统工程

用于实现时间模型、事件时间线、撤销重做、事件融合、Worker/IPC 和项目存储等基础能力。具体 C++ 标准、并发原语、IPC 传输、序列化格式和存储介质由项目架构与决定提供；本知识说明实现方法，不自行冻结候选技术。

## 先固定契约与不变量

开始编码前列出模块的输入输出、不变量、所有权、线程或进程边界、失败语义和版本兼容要求。把业务事实与派生缓存分开，把已提交状态与后台计算中的临时状态分开。公共核心接口避免泄露界面框架对象、进程内指针或隐式全局状态。

以小型值对象表达跨模块数据，标识符、时间、版本和可选状态使用明确类型。解析外部数据时先检查长度、范围、版本和资源上限，再构造内部对象；错误包含稳定类别和足以定位的上下文，不依赖日志文本作为机器接口。

## 时间模型与事件时间线

选定唯一的规范时间表示并显式携带时间基准。需要可重复换算和持久化时，优先使用整数刻度与明确的分子/分母或等价精确表示；所有换算规定舍入、溢出和边界策略。浮点秒可以用于显示或局部计算，但不能在未定义容差时成为跨模块比较和持久化的唯一真值。

时间线事件至少具有稳定 ID、类型、规范时间、来源和修订信息；相同时间事件规定稳定排序规则。区间操作明确端点包含关系，查找、吸附、移动和批量偏移复用同一套比较与换算逻辑。素材时间、项目时间和输出时间之间的转换集中在边界模块，并使用恒定帧率、可变帧率、不同采样率和极端时长用例验证。

每次分析或编辑生成可识别的时间线修订。读取者使用不可变快照、版本句柄或等价机制，避免后台任务在界面或导出读取期间原地改写当前修订。

## 撤销、重做与状态事务

将用户可见修改表示为具备明确前置条件和结果的命令或事务。每次提交要么完整生效，要么保持原状态；撤销必须恢复该命令负责的状态，重做得到与原提交等价的结果。新分支修改如何处理重做栈、连续操作何时合并、历史容量与保存点语义都应显式规定。

后台分析结果先形成候选修订，再通过单次可撤销事务合入当前状态。命令不能持有生命周期不受控的界面对象或临时缓冲区；大数据使用结构化差异、共享不可变结果或检查点控制内存，而不是无界复制整个项目。

测试覆盖执行—撤销—重做往返、连续撤销、分支编辑、空操作、批量失败和保存点判断。涉及持久化时说明撤销历史是否保存；若不保存，重开项目后的历史起点必须可预测。

## 事件融合

候选事件进入融合前统一时间基准、类型、强度、置信度、来源和分析版本。融合顺序、权重、窗口、最小间隔、密度限制、冲突优先级及可选随机种子均作为版本化输入，确保同一输入可复现。

算法输出保留到原始候选的追踪信息。人工事件和锁定事件的保护规则先于自动替换；新分析在临时修订完成，验证通过后原子提交，取消或失败不能破坏当前时间线。参数变化与算法升级生成新修订，不静默改写旧结论。

用边界和黄金样例覆盖同刻度冲突、窗口边缘、极密事件、空输入、跨片段合并、锁定覆盖和确定性；性能测量同时记录输入规模与参数，不能只给出脱离场景的耗时。

## Worker 与 IPC

把长时、易崩溃或处理不可信输入的工作隔离在 Worker 中，主进程负责生命周期和已提交状态。协议消息包含版本、请求 ID、操作、输入引用和结构化结果或错误；定义启动、进度、取消、完成、超时、崩溃及重复消息的状态转换。

跨进程不传递裸指针、引用或框架私有对象。根据数据规模和复制成本选择管道、套接字、文件或共享内存等传输方式；无论方式为何，都明确创建者、读取者、释放方、长度、校验、权限和清理时机。共享内存只减少复制，不替代所有权、同步和输入校验。

取消与完成可能竞态，协调端以请求状态和修订号决定结果是否仍可接纳。限制并发数、消息尺寸、队列和磁盘占用，避免 Worker 或异常输入拖垮主进程。重启后清理孤儿资源，过期结果不得覆盖更新的项目状态。

## 项目存储骨架

项目主文档包含显式 schema 版本、核心状态、素材引用与指纹以及生成状态所需参数；可重建的代理、波形和分析缓存独立存放，不混成唯一真值。保存使用临时文件和校验后替换等原子化策略，失败时保留最近一次成功版本，并提供可说明来源的恢复路径。

迁移逐版本执行并保存可测试的旧格式样例。读取未知新版本时应明确拒绝或按已定义的前向兼容策略处理，不能静默降级后覆盖原文件。素材丢失时按路径和指纹辅助重新定位，不自动把同名不同内容文件认作原素材。

存储测试覆盖首次创建、往返、旧版本迁移、未知版本、部分写入、磁盘不足、素材移动、缓存损坏和崩溃恢复。测试在临时副本进行，不通过破坏用户真实项目验证恢复逻辑。

## 验证与交接

为核心不变量建立单元、属性或模型测试，为模块边界建立集成测试；对时间换算、融合和序列化保存固定输入的黄金结果。并发与 IPC 测试覆盖乱序、重复、取消、超时、Worker 崩溃和过期结果，失败须能通过请求 ID、修订和结构化日志复现。

交付说明包含接口与数据版本、线程/进程模型、持久化边界、迁移策略、实际测试、性能环境和已知限制。实现与架构契约不一致时先记录差异并协调，不用代码既成事实替代已确认设计。
