# 体例约定

> 本约定 2026-09-19 经用户确认，是全书统稿依据（D-005）。每条给出**现状**（经全稿统计核实的实际情况）与**约定**。

## 1. 章节标题层级

**现状**：边界章（前言/序章/尾声）章标题用 H1（`# 前言`），节用 H2（`## 1. xxx`）；16 个技术章与 3 个附录用 H2 作章标题（`## 1 把 Yocto 跑起来`），节 H3、小节 H4。

**约定（2026-09-19 用户确认，按方案 A）**：

- 全部章标题统一 H1，节 H2、小节 H3。Markdown 语义上每个文件即一章，应有且仅有一个 H1；GitHub/编辑器预览下章名也最醒目。
- 改动为机械升级（19 章），**不单独批量执行**，并入 P3 各章修订时顺带完成，避免产生遮蔽实质修订的大面积 diff。
- 依据：D-002 已定 Markdown 终稿即交付、无排版转换环节，标题层级就是最终呈现层级。

## 2. 节编号风格

**现状**：技术章节号带章号前缀（`### 9.3`，小节 `#### 9.3.2`）；边界章用无前缀序号且带点（`## 1. 又一年`）；附录用字母前缀（`### A.1`）。技术章的 `N.x.y` 编号被全书大量交叉引用（如 9.3.2、5.6.1），**不可变动**。

**约定建议**：

- 技术章 `N.x(.y)`、附录 `X.y` 保持现状。
- 边界章序号统一为**数字后不加点**（`## 1 又一年`），与技术章章标题"数字后空格无点"的风格对齐。改动 3 章约 18 行，同样建议并入各章修订时顺带执行。

## 3. 交叉引用格式

**现状**：全书以 `chapter N` 为主（统一良好）；节级引用同章内用纯节号（`9.3.2`），跨章用 `chapter 4 的 4.6 节`。

**约定建议**：

- 跨章引用一律 `chapter N`；边界章用名称（序章/尾声/附录 A）。
- 节级引用：同章内纯节号，跨章 `chapter N 的 X.Y 节`——维持现状，写成规则。
- 旧式"第 N 章"清理：经逐处核对，真正的旧式交叉引用只有 **1 处**——task02:417 对话中"那是第三章的事"应改为"那是 chapter 3 的事"（A-001 原报 2 处，另一处 task12:619"排在'做工程'的第一章"是对话修辞、非引用，建议保留）。P3 修订 task02 时处理。

## 4. 中英文术语书写

**现状**（全稿统计）：配方 600 / recipe 388，层 265 / layer 390，poky 443 / Poky 44，bitbake 463 / BitBake 120。实际用法已形成稳定规律，建议把惯例写成明文：

- **首释给对照，后文用中文**：术语首次出现写 **中文（English）**（如 层（Layer）、配方（recipe）），之后行文用中文名。
- **代码、命令、变量、文件路径、程序输出一律英文原样加反引号**，不翻译、不"修正"大小写。程序输出按真实输出逐字引用（例：task02:48 引用的 `Do not use Bitbake as root` 属输出引用，出版前与真实报错核对，不适用体例改写）。
- **poky / Poky 分工**：行文指参考发行版用 Poky；路径、分支、仓库名用 `poky`（小写反引号）。现状已如此，写死。
- **bitbake / BitBake**：命令写 `bitbake`，行文指工具写 BitBake。
- **Yocto**：指项目本体写"Yocto 项目"，泛指生态可单写"Yocto"，英文全称 "Yocto Project" 只用于正式名称场合（前言、延伸阅读）。
- **缩写**：BSP、SDK、eSDK、CI、OTA、TF-A、UBI 等首次出现给全称或中文解释（现状基本如此）。
- **首释中的代码性标识加反引号**（v0.3 补充条款草案，2026-09-23 随 T-006 提出，待用户确认）：变量、命令、配方、脚本等代码性标识参与首释对照时，括号内写英文原样并加反引号、不改大小写，格式为 **中文名（`标识`）**，如 **下载目录（`DL_DIR`）**、**层列表变量（`BBLAYERS`）**；非代码性概念仍按普通 **中文（English）** 写法，如 **层（Layer）**。
- **概念名大小写遵循官方写法**（v0.3 补充条款草案，待用户确认）：行文中的概念名按官方约定俗成的大小写（如 sstate 缓存，首释 **共享状态缓存（sstate）**）；`SSTATE_DIR`、`sstate-cache`、`sstate.bbclass` 等变量、目录、类名按本节反引号规则保持原样。
- **git 分支名属代码标识符**（v0.3 补充条款草案，2026-09-25 随 T-006 U-18 提出，待用户确认）：行文引用分支名时按代码标识符处理——反引号加原样小写，如 `scarthgap` 分支；指发行版/版本名时用官方大写写法（如 Scarthgap，官方文档作 "Yocto Project 5.0 Scarthgap"），与上一条"概念名大小写遵循官方写法"同族。
