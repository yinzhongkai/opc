## 产品目标

先服务用户本人每天到饭点不知道吃什么的场景。首次打开时可以直接用内置默认菜单抽取，后续启动直接恢复上次使用的已保存菜单；用户可自行输入、删除想吃的候选名称，由转盘随机选出一个，并管理多份本机菜单。

核心闭环是“首次加载默认菜单或手动准备候选 → 转盘抽取 → 保存完整菜单 → 再次加载和抽取”。小程序不获取定位信息，不提供附近餐厅搜索，也不根据位置、距离或第三方餐厅数据生成候选。仅在能够确认全新本机状态时，一次性建立并自动加载内置默认菜单；已有菜单、已使用后的空菜单库及异常读取不能被当作首次使用而重置。

再次启动恢复现存菜单的最新已保存内容，不重建原始 8 项，也不自动保存未保存编辑。菜单列表有默认菜单但旧版未记住选择时，按本版兼容规则直接加载该现有菜单，让转盘可用；无需用户先手动选择一次才能获得升级行为。

## 首版范围与变更

本版共有 **13 项有效需求、13 条有效操作规则、40 项有效验收条件**。保留旧编号及撤销表，不复用编号；本次新增 R-18、P-15、AC-43 至 AC-50，修订 AC-07/AC-39/AC-40 的启动选择语义，其余 29 项验收保持。旧 12/12/32 及初始化功能的专业结论按其版本和范围保留。

本版包含首次默认菜单、名称输入与删除、最多 24 项候选、等概率转盘、多份命名菜单、本机保存和原样加载，以及菜单管理和必要异常处理。视觉沿用用户截图方向。候选来自本次固定内置菜单、用户输入或其已保存菜单，不要求名称必须对应地图上的真实门店。默认菜单只提供初始内容，后续与其他本机菜单遵守相同的编辑和保存规则。

D-019 的固定默认菜单及一次性初始化继续有效；D-024 新增再次启动选择恢复。当前产品 main/v1.1.0 基线 3800e6dd8bc32b7d767bfc873a4b9ae57d10232b 包含旧默认菜单功能，尚不含本次启动恢复；按旧契约再次启动不自动加载的实现和测试保持原适用结论，不改写为测试失败。历史测试和已发布标签不作为本轮新功能证据。

按 D-016，定位权限与位置获取、1/3/5 公里或任何距离限制、附近搜索、地图餐厅自动加入及更新、用餐类别筛选、距离排序和地图最多 12 家规则全部移出本版。餐厅数据源选型、免费额度与保存授权核实、林萃桥覆盖验证、成功样本/分页规则、跨来源同名处理和来源标注也不再是本版待办。

长期免费仍是使用偏好，但本版无需餐厅数据接口；不据此承诺小程序注册、运行和发布的全部成本永远为零，也不授权开通付费服务。微信小程序平台、本机存储、字符计数及实际运行能力由架构师按新范围验证，系统边界、数据结构和实现方式仍由其设计。

首版不要求跨设备同步、换机找回或清除本机数据后恢复。抽中结果仅显示候选名称，不要求地址、距离、评分、人均或导航。

## 候选与菜单的含义

当前候选是此刻参与抽取的一组名称，来自首次内置菜单、用户手动输入或其已保存菜单。用户只提供名称，产品不要求补充地址、位置、门店标识或来源资料，也不区分地图项和手动项。

已保存菜单是用户命名并保存的一份完整候选。加载后原样恢复名称和候选顺序；修改当前候选不会自动覆盖已保存菜单，必须明确保存。抽取仅产生结果，不修改候选。

同一份候选内，名称去首尾空白后逐字相同的重复输入被拒绝并提示，不利用同名项增加概率；不同菜单可以包含相同的候选名称。旧“手动项与地图项同名可分别保留”的例外已退出本版。

| 4 | 醉面 |
| 5 | 吉野家 |
| 6 | 阿香米线 |
| 7 | 喜家德 |

| 使用状态 | 可观察的产品行为 |
|---|---|
| 能够确认的全新本机状态 | 无需用户先输入或点击加载，成功初始化后当前候选即为上列 8 项；本机菜单列表可找到唯一一份“默认菜单”，可直接抽取并按普通菜单保存、加载及管理。初始化成功是后续可加载的前提，不只显示一份未留存的演示列表。 |
| 已有一份或多份菜单，包含用户自己命名的“默认菜单” | 不建立另一份默认记录，不覆盖、重命名、合并或增删旧菜单内容；按 R-18 选择并加载现有保存快照，允许留存选择记忆。用户同名菜单仍保留其原内容，不能用原始 8 项替换。 |
| 已初始化后重复启动，或用户删光候选/删除最后一份菜单 | 不重复建立默认菜单。启动按 R-18 恢复现存保存快照；删空候选但未保存时，重启可恢复原保存快照，这不属于重新播种。删除全部保存菜单后的已使用空库仍为空，不补回 8 项；不能单凭菜单数为 0 认定首次。 |
| 读取失败、数据损坏/格式未知、初始化写入失败或结果不明 | 不把读不到数据当作首次，不清库、不替换旧记录；提示实际失败或待核验状态，不宣称初始化成功。保留当前可用内容及已有编辑状态，安全恢复/重试后仍至多形成一份完整默认记录，不能留下可加载的半份菜单或复活用户已删除的记录。 |
| 用户主动清除全部本机数据后重新进入 | 不要求找回已清除的用户菜单；清除后若成为可确认的全新本机状态，按首次规则提供固定默认菜单。这不属于恢复旧菜单。仅通过菜单管理删除记录不等于清除全部本机数据。 |

首次自动建立/保存是 D-019 的一次性初始化例外。初始化后增删候选不自动覆盖保存记录，覆盖/另存仍需用户明确操作；默认菜单也可改名、删除，删除当前菜单继续保留未保存副本。每项按 1/8 独立等概率参与首次抽取，用户修改后按实际 N 项执行 P-02。无需为默认菜单新设不可删除、固定候选或自动复活规则。

首次识别、旧版有效空库和一次性初始化的原契约见 A-006 v0.6 第10节，原实现/测试结论按原版本保留；本轮启动选择恢复由 T-033 在其上补充。本需求规定行为与数据保护结果，不能证明可安全初始化或恢复时，保留旧数据、明确提示并先核验。

## 启动恢复与菜单选择记忆

“启动”指新建使用会话时的加载过程；同一页面从后台返回、关闭弹层、刷新菜单列表不重新恢复候选或丢弃未保存编辑。“上次使用”是最后成功加载并成为当前关联，或成功保存后成为当前关联的菜单身份，不是最后抽中的名称，也不根据菜单名或最后一次增删输入推断。启动读取该菜单现在的保存快照，候选名称及顺序完整恢复，菜单名显示现名，工作副本与保存基线一致且无未保存标记，可直接抽取；加载不改写菜单内容。

### 启动选择及兼容降级顺序

下表仅在菜单库与选择状态可可靠判断时应用。步骤按顺序匹配，选择到一份即可停止；兼容降级是本次 D-024 范围内的既有菜单选择，不新增菜单、不猜测旧版实际使用历史。

| 顺序/状态 | 选择与可观察结果 |
|---|---|
| 可确认全新本机状态 | 按 R-17 一次性建立并加载默认菜单，并记住该菜单；失败继续既有保护和核验规则。 |
| 有有效选择记忆，所指菜单仍存在且可读取 | 优先加载该身份当前的保存内容，即使菜单已改名、内容已修改或另有“默认菜单”。不得回放旧快照或原始 8 项。 |
| 选择记录明确缺失，或所指身份确认已不存在 | 优先加载可识别且仍存在的内置默认菜单（包括已改名的那一份）；无可识别内置身份时，使用名称去首尾空白后逐字等于“默认菜单”的现存菜单，保留其真实用户内容。无需先手动选择，覆盖旧版默认菜单已保存但启动空转盘的升级场景。 |
| 上述默认菜单不存在，但有其他完整有效菜单 | 加载当前菜单列表既有显示顺序中的第一份，不额外重排或新建；正常成功后记住此次选择，后续优先恢复它。加载时可显示正常菜单名；不能把兼容选择宣称为已知的旧版“上次使用”。 |
| 已使用过的合法空库 | 保持空候选并引导输入，不播种、不复活已删除菜单；清理失效选择记忆本身不得删除或创建任何菜单。 |
| 菜单或选择读取报错、损坏、未知格式或结果不明 | 不冒充“记录缺失”或“全新”，不静默跳过损坏记录而改选/覆盖另一份；保留原字节，提示失败并允许安全核验/重试。菜单库已可完整可靠读取、仅选择记忆不可用时，可由用户手动明确选择菜单继续，但不得假称本次自动恢复或选择留存成功。 |

存量菜单无需通过重新初始化或重新保存才能被恢复；已有一份同名用户菜单时也只加载其现存内容，不转成内置模板。已记忆身份被删除后，新建的同名菜单不能按旧身份认作原菜单，只能按上述兼容顺序作为现存记录选择。仅全部本机数据被主动清除且重新满足全新条件时，才按 R-17 建立初始菜单。

| 启动自动恢复、兼容加载或用户手动加载成功 | 当前菜单已完整加载后记住其身份；不能在点击目标、尚未读完时就记为已切换。 |
| 新建/另存/覆盖成功并关联当前菜单 | 记住保存后当前关联的菜单。另存为 N 后恢复 N；覆盖 M 后恢复 M 的最新保存内容。只抽取、输入或删候选不另改选择，也不自动保存。 |
| 有未保存改动时切换 | 取消或目标加载失败不记目标；放弃并成功加载 B 才记 B。保存 A 后切 B，只有 A 保存确认且 B 加载成功才记 B；A 保存成功而 B 读取失败时保留 A 的已保存事实与当前副本，选择仍以 A 为准。空保存或保存失败阻止切换，旧选择不变。 |
| 重命名 | 当前菜单身份不变，启动显示新名及原保存内容；改名另一份菜单不把当前选择改到该菜单，也不能因名称匹配把用户菜单当成旧身份。 |
| 删除 | 成功删除被记忆的菜单后该身份失效；删除当前菜单仍只删保存记录并保留本次未保存副本，不把副本自动另存。下次按兼容顺序加载其他现存菜单或空库；删除非当前且非记忆目标不改变选择。取消/明确失败不作成功删除处理。 |

选择记忆是独立于菜单内容的状态：正常成功路径应留存选择，不能只在当前页面显示已切换而未做持久留存。若菜单已经加载/保存成功，但选择记忆明确写入失败，保留当前可用菜单和已保存内容，分别如实反馈“本次菜单已加载/保存，启动选择未能记住，请重试”；不回滚已确认保存，不重复保存菜单补记选择，也不保证下次恢复这次未记住的目标。下次使用最后一次可确认的有效记忆，明确缺失/失效再走兼容顺序。

菜单保存或选择记忆的提交结果不明时，先安全核验实际结果，再继续可能覆盖存储或改变恢复目标的操作；不报完整成功、不盲目重试、清库或替换选择。重试只补齐仍适用于当前操作的选择，用户之后已切到其他菜单、编辑或删除时，迟到结果不得覆盖新工作副本、把选择倒退到旧目标或复活记录。具体一致性、存储格式和生命周期控制由 T-033 设计，需求不指定存储 key、算法或实现位置。

未保存改动仍不承诺跨启动留存：关联 M 后只改工作副本或删空候选而未成功保存，重新启动恢复 M 原保存内容；未保存的新副本不自动另存。正常在同一页面切后台再返回保留当前工作态，不以本次恢复功能替用户放弃编辑。

## 核心使用流程

### 准备并抽取

1. 全新首次按 R-17 建立并加载默认菜单；再次启动按 R-18 恢复上次菜单的保存内容，旧版无选择记录按有界顺序加载现有默认菜单或其他现存菜单。合法空库保持空；用户仍可手动输入或切换菜单。
2. 用户填写名称并添加，按非空和同名规则校验；可继续添加至 24 项，也可删除不想参与抽取的项。
3. 点击转盘中心“开吃”，抽中结果只显示候选名称；可继续抽取，允许连续抽中同一项。
4. 当前候选非空时，可用合法且不重名的菜单名保存整份候选；保存失败不报成功、不丢失当前编辑状态和旧菜单。

整个流程没有定位申请、距离选择、附近搜索或餐厅数据查询。固定内置默认菜单无需联网获取；用户在平台能够打开小程序的前提下，可在断网时初始化并继续使用上述流程与本机菜单。

### 使用已保存的菜单

1. 选择一份已命名菜单；当前有未保存改动时，先选择保存并切换、放弃改动并切换，或取消切换。
2. 加载后恢复该菜单保存时的完整候选，可直接抽取，也可手动增删。
3. 修改后的候选由用户明确选择覆盖当前菜单或另存为新菜单；加载和抽取均不自动改写保存记录。

### 管理和保存菜单

菜单名去首尾空白后为 1～20 个用户可见字符；去空白后逐字相同的不同菜单名视为重名。新建或重命名重名时提示换名，不自动覆盖；重命名为自身原名不算重复，明确覆盖当前菜单也不算新增重名。20 字符上限仅约束菜单名，不约束候选名称。

0 项不能新建或覆盖菜单，但可以删除当前最后一个候选。保存被阻止时保留当前编辑状态和旧保存记录。“保存并切换”只有保存成功才继续，空候选或空间不足时不能报成功或继续切换。不设固定菜单份数上限，实际空间不足时不得自动淘汰旧菜单。

删除当前菜单前说明仅删除保存记录；确认后保留当前完整候选为未保存副本，并解除与已删除记录的关联，不自动另存。取消时保存记录和当前编辑状态均不变。后续保存需另存，不会复活已删除记录。保存前退出不要求保留该未保存副本供下次加载。

删除或重命名某份菜单不改变其他菜单。正常关闭后再次进入，可找到并加载本机已保存菜单；用户清除本机数据后不要求恢复。
