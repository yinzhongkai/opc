## 2. 系统目标、边界与上下文

### 2.1 V1 技术目标

系统必须在本地完成以下闭环：

```text
本地音频文件
  → 解码与波形/特征分析
  → 节拍、事件和置信度
  → 可编辑映射与关键帧
  → 模板场景求值
  → 实时预览
  → 确定性离线渲染与音视频封装
```

系统还必须保存上述过程所需的工程状态，并在异常退出、素材移动、缓存损坏和后台任务取消后保持用户数据可恢复。

### 2.2 系统边界

V1 系统包含：

- Qt 桌面应用及其交互模型；
- 与 Qt 解耦的 C/C++ 核心；
- 无界面核心验证程序；
- 音频解码、音频输出、GPU 渲染和视频编码适配器；
- 工程、素材引用、缓存、恢复副本和诊断数据；
- 示波器、粒子和基础 3D 三类模板的运行时支持。

V1 系统外部依赖包括：

- 本地文件系统；
- 音频输出设备及其系统后端；
- GPU/图形驱动；
- 音视频编解码实现；
- 操作系统安装、文件选择和打开目录能力。

以下能力不因技术预留而进入 V1：Blender Live Link、VST3/AU、云同步、账号体系、模板市场、完整 NLE/DAW/建模、视频生成音频、音乐自动剪辑多视频以及旧 `.osci` / `.sosci` 工程完整兼容。

### 2.3 架构边界

```text
apps/qt-studio                 apps/headless-validator
        │                                │
        ├──────── application services ──┤
        │                                │
adapters/qt  adapters/media  adapters/render  adapters/audio
        │             │             │             │
        └─────────────┴──── ports ───┴─────────────┘
                              │
 core/project  core/timeline  core/analysis  core/mapping
 core/template core/scene     core/scope     core/base
```

核心只表达领域状态、算法和端口；Qt、具体 GPU API、音频设备 API、编码器对象和操作系统句柄不得进入核心数据模型。

### 5.2 工程文档

`ProjectDocument` 至少需要表达以下逻辑字段；具体序列化格式待技术评审确认：

```text
schemaVersion
projectId / createdAt / modifiedAt
projectSampleRate
assets[]
analysisRefs[]
templateInstances[]
mappings[]
timeline { tracks[], events[], keyframes[], loopRange }
transportPreferences
exportPresets[]
randomSeeds
extensionData
```

工程契约必须满足：

- 保存前完成全量结构验证；
- 使用同目录临时文件、落盘和原子替换，失败时保留上一个完整版本；
- 自动恢复写入独立副本，不覆盖用户显式保存文件；
- 迁移按 Schema 版本逐级执行，并保留迁移诊断；
- 可安全保留的未知字段应往返保留；无法安全解释的版本必须拒绝打开并说明原因；
- 工程引用不得隐式执行脚本、加载网络资源或写入工程目录外的位置。

### 5.3 素材引用与缓存键

`AssetRef` 至少包含稳定 ID、原始/相对定位信息、内容摘要、字节大小、媒体类型和已验证的媒体元数据。重新定位必须先核对内容摘要或显示差异并由用户确认，不能只按同名文件静默替换。

分析缓存键至少由以下信息组成：

```text
assetContentDigest
analyzerId + analyzerVersion
analysisParameters
channelMapping
analysisSampleRate
determinismProfile
```

缓存内容必须自带版本、键摘要、长度和完整性校验。校验失败时缓存只可被隔离或删除重建，不得修改素材、事件编辑、映射或工程文件。

### 5.4 特征、事件与节拍

连续特征记录必须包含中心样本位置、分析窗口/步长版本和数值；离散事件必须至少包含：

```text
eventId
samplePosition
eventType
strength
confidence
origin = automatic | user
locked
sourceAnalyzerId + sourceRevision
```

用户移动、增加或锁定事件后必须产生新的工程 revision。重新分析只可替换与目标分析 revision 关联且未锁定的自动事件；用户事件和锁定事件不得被覆盖。

### 5.5 映射与模板

映射记录至少包含源、目标、启用状态、范围、方向、强度、曲线、attack/release、延迟、门限、量化、采样保持、合成方式、顺序和 seed。M 级字段必须可在不支持 S 级高级字段时使用确定默认值打开。

模板清单至少包含模板 ID、版本、类别、显示元数据、能力要求、性能档位、资产清单及摘要、公开宏参数、默认映射和授权记录引用。模板实例必须保存自己的参数与映射状态；模板切换不能删除其他实例状态。

## 6. 接口、作业与错误契约

### 6.1 核心端口

| 端口 | 输入 | 输出 | 失败与取消语义 |
|---|---|---|---|
| `IMediaProbe` | 受限文件句柄/路径令牌 | 格式、时长、声道、采样率、能力 | 不支持、损坏、权限、资源上限；无工程副作用 |
| `IAudioDecoder` | 素材引用、目标采样率、区间 | 带起始样本位置的 PCM 块 | 失败块不提交；取消后可释放全部临时资源 |
| `IAudioAnalyzer` | PCM 块、分析配置、取消令牌 | 特征帧、事件候选、进度 | 输出先写暂存结果，成功后按 revision 提交 |
| `IBeatEditor` | 节拍网格、BPM/拍号/第一拍、锁定事件 | 新网格与受影响项清单 | 校验失败不改变旧网格 |
| `IMappingEngine` | 时间上下文、特征/事件视图、映射快照 | 参数写批次 | 实时求值不得抛异常或阻塞 |
| `ISceneEvaluator` | 场景快照、参数批次、样本时间 | 渲染器无关帧 | 资源缺失返回可诊断占位/失败状态，不修改工程 |
| `IRenderBackend` | 渲染帧、目标和质量配置 | 帧或 GPU 结果 | 设备丢失可重建或明确失败；不影响音频状态 |
| `IMediaEncoder` | 有理 PTS 的视频帧、原音频流、输出配置 | 临时输出与进度 | 成功后原子完成；取消/失败不得伪装为完整文件 |
| `IProjectStore` | 工程快照、目标、保存选项 | 保存/恢复/迁移结果 | 任一阶段失败保留上一个完整工程 |

接口实现不得跨边界传递所有权不明的指针、具体 GPU/Qt 对象或未版本化的二进制结构。若使用跨 DLL C ABI，不得暴露 STL 容器、C++ 异常或 RTTI 对象。

### 6.2 作业状态

分析和导出作业必须遵循：

```text
Queued → Running → Succeeded
                 ↘ CancelRequested → Cancelled
                 ↘ Failed
```

- 取消请求必须幂等；重复取消不得造成额外副作用。
- `Succeeded` 前结果不可替换当前有效缓存或目标文件。
- `Cancelled` 和 `Failed` 必须终止进度更新并释放文件句柄、队列和临时资源。
- 作业结果必须关联输入工程 revision；旧 revision 的完成结果不得静默覆盖新编辑。

### 6.3 统一错误模型

错误对象至少包含稳定错误码、类别、用户影响、可操作建议、是否可重试、技术原因链和关联作业/素材。最低错误类别为：

```text
UnsupportedFormat, CorruptInput, PermissionDenied, MissingAsset,
CapabilityUnavailable, VersionUnsupported, Cancelled, ResourceLimit,
DeviceLost, CodecFailure, PersistenceFailure, InternalFailure
```

UI 可以本地化说明，但不得只显示第三方库错误码。日志可记录规范化路径令牌或散列，不得默认记录完整私人路径和媒体内容。

### 11.2 分层验证

- 单元：时间换算、Schema 校验/迁移、缓存键、映射函数、命令撤销、颜色有效性。
- 属性测试：任意合法有理帧率换算、事件区间判定、工程往返、资源上限。
- 黄金音频/事件：固定输入、配置、seed 和版本的特征/事件摘要。
- 黄金图像：示波器圆形、颜色、余辉与三类模板关键帧；GPU 差异按预定感知阈值。
- 集成：解码→分析→映射→场景→帧；工程→恢复；导出→常见播放器。
- 端到端：SC-01 至 SC-05 及三类模板导出。
- 异常：取消、磁盘满、权限不足、素材移动、缓存损坏、设备丢失、编码失败、进程崩溃。
- 稳定性：长音频、长时间循环、重复跳转/撤销、并发分析与导出、GPU 重建。
- 安全：损坏输入、fuzz、目录穿越、超限资源、未验证依赖、外部进程参数。

### 11.3 发布候选技术证据

进入发布候选前必须具备：

1. 每条 M 级产品需求到技术需求、实现项和测试结果的三向追溯；
2. 示波器、粒子和基础 3D 模板各至少一个端到端通过记录；
3. 60 秒首预览、3 秒缓存打开和 10 分钟首次导出的产品测试证据；
4. 10 分钟音画同步误差不超过一帧的机器可读报告；
5. 工程原子保存、异常恢复、迁移和素材重新定位测试；
