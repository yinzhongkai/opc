## 1. 结论摘要

本项目当前及后续只提供 Windows 桌面客户端，不建设 Web 客户端。客户端与服务端分工：客户端使用 C++、Qt 和 SQLite，负责用户交互、结构化明细人工编辑与确认、本地确定性计价、报价留存和追溯，并负责版本检查、升级包验证、安装及失败恢复；服务端以 Linux/glibc 为运行基线，使用 C++17/20、Drogon、libcurl 和 PostgreSQL，负责账号与年度订阅授权、PDF 临时分析、平台标准目录匹配、原材料价格快照、计价规则包发布、客户端版本与升级管理和平台管理。生产环境在 Drogon 前部署 Nginx，开发环境可以由客户端直连 Drogon。

PDF 不在客户端解析。客户端上传 PDF 后，服务端异步完成文本提取、必要时 OCR、大模型结构化和目录匹配，返回候选 JSON；客户端只展示结构化明细并要求用户确认，不显示原始 PDF，也不实现字段原文定位或高亮。服务端仅临时保存 PDF 和分析中间结果，到期清理；生产商的客户资料、询价单、报价单和本地计价参数只在客户端长期保存，服务端不保存这些业务数据。

服务端不返回固定销售价，而是发布带签名和版本信息的价格与公式包。客户端以已确认的结构化数据、本地业务参数和目标毛利率完成计算，并保存完整计算凭证。目标毛利率以不含税、不含运费的出厂价计算：

```text
不含税不含运费出厂价 = 单位成本 / (1 - 目标毛利率)
```

税费与运费单独计算和展示。目标毛利率必须小于 100%，支持本地默认值和逐项覆盖。

## 2. 设计依据与约束

### 2.1 已确认约束

- Windows 桌面客户端是项目当前及后续唯一客户端形态，Web 客户端属于明确非目标。
- 客户端不实现 PDF 解析、OCR 或大模型接入，不展示原始 PDF，也不做原文位置高亮。
- 结构化明细必须支持人工编辑和确认；未确认或无法处理的明细不得进入自动计价。
- 服务端维护全局标准管件目录、别名、计价公式模板、原材料价格及其来源，不保存生产商的客户资料、询价单、报价单和本地计价参数。
- 不建设企业业务数据或多租户业务域，不为此预埋无实际语义的 `organizationId`；商业授权仍需区分平台订阅主体、账号和已激活客户端，这些授权数据不构成生产商业务数据。
- 生产商只能通过受控业务接口取得其账号或设备已获授权的平台数据，不能修改服务端平台目录、公式或价格源，也不能访问其他账号或设备的授权数据。
- 同一 Windows 客户端可按服务端签发的平台管理员角色显示管理入口；管理接口与普通业务接口逻辑隔离。
- 原材料行情使用可插拔数据源适配器；没有正式行情网站时先实现人工维护和文件导入。
- PostgreSQL 用于服务端持久化；SQLite 和受管本地文件用于客户端持久化。
- 当前按客户端实例总量预计不超过 10,000 个进行容量设计；该数值不是并发在线数、峰值请求量、性能验收指标或商业授权上限。
- Windows 客户端必须具备可安全升级能力，服务端必须提供版本、发布通道、策略、升级包元数据、发布范围、下载授权和升级审计等管理能力；升级包必须经过完整性及发布者签名校验。

### 2.2 当前未知项

- 不同来源 PDF 的真实版式、扫描质量、字段名称、单位和异常样例。
- 管件目录的最终分类、规格属性、别名和匹配优先级。
- 实际成本公式、损耗、工艺费和本地参数的定义与取值边界。
- 正式行情网站或 API、授权方式、刷新频率、税口径和区域口径。
- 账号、客户端数量档位、离线宽限期、数据保留期和恢复目标。
- 日活和峰值在线客户端数、登录及令牌刷新峰值、同时上传 PDF 数、异步分析任务到达率和队列长度。
- PDF 大小分布、单任务处理时间、外部大模型并发或限流、价格与公式包集中更新时的下载峰值。
- 升级提示与交互、自动安装时机、增量包或全量包、最低支持版本取值、离线升级方式、失败回滚保留策略。
- 升级包采用对象存储还是受控静态下载入口，以及发布通道、灰度比例、分批节奏、下载并发和带宽目标。

这些未知项不阻止架构拆分，但会阻止识别准确率、报价正确性和生产可用性的最终验收。

### 2.3 容量设计假设

D-007 给出的设计基线是客户端实例总量预计不超过 10,000 个。这里的“总量”用于约束账号与设备授权表规模、索引和部署复杂度，不表示 10,000 个客户端会同时在线，也不表示系统已经承诺支持 10,000 个并发请求。

当前按中小规模集中式部署设计：授权和设备查询使用 PostgreSQL 索引；Drogon API 尽量保持无会话状态；PDF 分析通过异步 Worker 与 HTTP 请求解耦；API 与 Worker 保留按实测结果增加实例的能力。现阶段不为未确认的更大规模提前引入数据库分片、多区域写入或复杂分布式协调。

进入性能验收前仍须定义并验证以下指标：峰值在线客户端数，登录、令牌刷新和授权检查的持续及突发请求率，同时上传 PDF 数及带宽，分析任务到达率、并行 Worker 数和允许队列长度，价格、公式或客户端版本发布后的集中下载峰值，以及各接口响应时间、任务完成时间和错误率目标。

## 3. 系统上下文与边界

```text
生产商用户
   |
   v
Windows 客户端（Qt / SQLite / 本地受管文件）
   | HTTPS
   v
Nginx（生产环境 TLS、反向代理、限流、上传限制、访问日志）
   |
   v
Drogon API（Linux/glibc） ───── PostgreSQL（平台数据、授权、任务元数据、审计）
   |
   +──── 分析 Worker（PDF 提取 / OCR / 大模型 / 目录匹配）
   |          |
   |          +──── 临时对象或文件存储（TTL 清理）
   |
   +──── 数据源适配器 ──── 人工录入 / 文件导入 / 未来 HTTP API 或网页源
   |
   +──── 大模型供应商接口
   |
   +──── 客户端升级管理 ──── 对象存储或受控静态下载入口（候选）

平台管理员 ── 同一客户端的管理入口 ── 独立管理 API ── 平台资源与客户端版本发布
```

边界原则：生产商的客户资料、询价单、报价单、毛利设置、本地计价参数和计算凭证只在客户端长期保存。服务端只持久化平台公共数据、商业授权数据，以及完成异步处理和审计所必需的最小元数据；临时分析内容按 TTL 清理，不演变成企业业务数据或多租户业务域。

## 4. Windows 客户端候选结构

建议模块如下：

| 模块 | 主要职责 |
|---|---|
| 登录与授权 | 登录、令牌刷新、订阅状态和设备激活状态展示 |
| 采购清单导入 | 选择 PDF、计算文件哈希、上传、轮询分析任务 |
| 结构化明细工作台 | 展示候选字段、校验告警、人工编辑、批量确认、无法处理标记 |
| 目录与规则缓存 | 缓存服务端发布的目录摘要、价格快照和带签名公式包 |
| 本地计价引擎 | 根据固定版本输入执行确定性公式，输出中间值和结果 |
| 报价管理 | 管理客户、报价单、版本、导出状态和手工销售价覆盖 |
| 凭证与追溯 | 保存输入哈希、结构化版本、价格和公式版本、参数、过程和结果 |
| 本地存储与备份 | SQLite 在线备份、文件引用、加密备份包和恢复校验 |
| 版本与升级 | 检查当前版本和服务端策略、取得下载授权、下载升级包、校验哈希与发布者签名、执行安装并在失败时回滚或进入恢复流程、上报升级事件 |
| 平台管理入口 | 仅平台管理员可见，调用独立管理 API，不提供远程 Shell、任意文件或直接数据库访问 |

建议将 UI、领域模型、网络访问、本地持久化和计价引擎分层。计价引擎不依赖 Qt 界面组件，以便使用固定测试向量进行单元测试和未来复用。

### 4.1 人工确认状态

每条结构化明细至少包含以下状态：

- `unreviewed`：尚未人工检查；
- `questionable`：系统识别或匹配存在歧义；
- `modified`：用户已编辑但尚未再次确认；
- `confirmed`：允许进入查询和计价；
- `unprocessable`：本轮不能自动处理，需人工报价。

只有 `confirmed` 明细可以自动计价。已确认字段发生修改后，目录匹配和计算结果立即失效，状态回到 `modified`。

## 5. 服务端候选结构

### 5.1 接入层

- Nginx 在生产环境终止 TLS、反向代理、设置上传大小和超时、限流并记录访问日志。
- Nginx 为升级元数据 API 和受控下载入口实施独立的缓存、限流、文件类型与大小策略；若升级包由对象存储承载，可由服务端签发短期下载授权并经 Nginx 返回或重定向，具体承载方式待确认。
- Drogon 提供 HTTPS 后的业务 API，负责认证、参数校验、任务创建、数据查询和管理操作。
- PDF 分析不得在 HTTP 请求线程中等待大模型完成。创建任务后返回 `202 Accepted` 和 `jobId`，由 Worker 异步处理。

### 5.2 核心服务

- 授权服务：账号、年度订阅、席位、Windows 设备激活、短期令牌和权限校验。
- 分析任务服务：任务状态、临时文件引用、重试、超时、失败原因和 TTL 清理。
- 文档分析 Worker：原生 PDF 文本提取、OCR 降级、大模型结构化、字段规范化和置信度输出。
- 标准目录服务：标准管件、别名、核心关系字段与可扩展属性、候选匹配和歧义说明。
- 行情服务：数据源适配器、单位与币种归一、人工修正、不可变价格快照和过期策略。
- 公式服务：安全声明式公式、参数定义与边界、版本和生效期、签名发布包。
- 客户端升级管理服务：客户端版本、发布通道、升级策略、最低支持版本、升级包哈希与签名元数据、灰度或分批范围、下载授权和升级审计。
- 管理服务：平台配置、全局目录、公式、价格源、账号订阅、设备、任务队列、审计、备份恢复和版本信息。
- 审计服务：记录高权限及关键平台数据变更，不把密钥明文写入数据库或日志。

服务端内部访问外部大模型和行情接口使用 libcurl 等出站 HTTP 客户端；Drogon 是链接进应用的 C++ Web 框架，最终运行的是项目自己的 API 与 Worker 程序。

## 6. 关键业务数据流

### 6.1 PDF 到可确认明细

1. 客户端计算 PDF 哈希并调用分析任务接口上传文件。
2. 服务端校验授权、类型和大小，将文件放入临时存储，登记任务并返回 `jobId`。
3. Worker 优先尝试文本提取；文本不可用或质量不足时调用 OCR。
4. Worker 将受约束的字段模型交给大模型，取得候选 JSON；大模型输出必须经过模式、类型、枚举和范围校验。
5. 标准目录服务按规范化字段和别名给出唯一匹配、多个候选或未匹配结果，不自动猜测歧义项。
6. 客户端取得结构化结果，在明细工作台中编辑并逐项或批量确认。
7. 服务端按 TTL 删除 PDF、OCR 文本和大模型中间结果，仅保留完成任务和审计所需的最小元数据。

### 6.2 价格与公式包到本地计价

1. 数据源适配器获取原始行情，行情服务完成单位、币种、税口径、区域和时间归一。
2. 服务端生成不可变价格快照；人工修正生成新快照，不覆盖旧快照。
3. 服务端发布已签名计价包，包含价格快照、公式版本、参数定义与边界、生效和过期时间、最低客户端引擎版本。
4. 客户端校验授权、签名、有效期和引擎兼容性，将服务端平台参数与生产商本地参数组合。
5. 本地计价引擎只处理已确认明细，并保存过程值和计算凭证。
6. 用户可覆盖逐项目标毛利率或最终销售价；若覆盖销售价，客户端反算并显示实际毛利率，且记录操作者、时间和覆盖原因。

### 6.3 客户端安全升级

1. 客户端携带当前版本、系统架构、发布通道、账号和设备授权上下文请求升级策略；服务端按已发布版本、适用范围和策略返回“无更新、可选更新、强制更新或当前版本不受支持”等语义。具体检查频率、提示交互和自动安装时机待确认。
2. 需要升级时，客户端请求短期下载授权。服务端只返回已发布制品的受控下载地址、大小、内容哈希、发布者签名、签名和哈希算法标识、目标版本及兼容约束；升级包本体不写入 PostgreSQL。
3. 客户端通过对象存储或受控静态入口下载，支持中断后的安全重试。仅有 HTTPS 不足以证明升级包来自发布者；客户端必须先校验包大小和内容哈希，再使用内置信任根校验发布者签名，任一步失败都丢弃制品并停止安装。
4. 安装前检查操作系统、架构、当前版本、目标版本、磁盘空间和正在运行的业务任务。客户端保存足以执行失败回滚或恢复的状态；具体采用原版本保留、安装器修复还是重新下载，以及保留版本数量，待原型验证和用户确认。
5. 客户端记录检查、下载、验证、安装和恢复结果，并向服务端上报不含生产商客户业务数据的升级事件。失败上报不得阻止本地恢复。
6. 服务端支持按发布通道及账号或设备范围进行灰度或分批发布，并允许暂停后续投放；具体通道、批次、比例、强制窗口和回滚策略尚未确认。分组只用于平台授权与发布控制，不引入企业业务租户。

## 7. 数据与存储设计

### 7.1 服务端长期数据

- `subscription_accounts`、`subscriptions`、`accounts`、`device_activations`、`roles`；其中 `subscription_accounts` 表示平台商业订阅主体，不表示报价业务中的客户；
- `catalog_items`、`catalog_aliases`、`catalog_versions`；
- `materials`、`price_sources`、`price_observations`、`price_snapshots`；
- `formula_templates`、`formula_versions`、`parameter_definitions`、`pricing_packages`；
- `client_releases`、`release_channels`、`upgrade_policies`、`release_artifacts`、`rollout_assignments`、`upgrade_events`；其中升级包本体存放在对象存储或受控静态下载目录，数据库只保存定位、大小、哈希、签名和发布状态等元数据；
- `analysis_jobs` 的最小任务元数据和清理状态，不持久化采购清单正文或完整结构化业务内容；
- `admin_audit_events`、运行配置的非敏感引用。

目录采用“关系型核心列 + JSON 扩展属性”：用于标识、筛选、关联和约束的稳定属性进入关系列；品类差异较大的附加属性进入受模式约束的 JSON。敏感密钥由专用密钥管理或部署环境提供，数据库只保存引用或加密材料。

### 7.2 客户端长期数据

- 客户、报价单、报价版本和明细；
- 原始 PDF 的本地受管副本及哈希；
- 结构化候选、人工修订、确认状态和目录匹配结果；
- 本地默认毛利率、逐项覆盖、生产商参数和用户偏好；
- 价格及公式包缓存、计算凭证、导出记录和本地审计信息。
- 当前客户端版本、最近检查结果、适用升级策略、下载与验证状态，以及完成失败恢复所需的受控状态；不在业务数据库中保存未受保护的升级包副本。

PDF 等大文件保存在受管文件目录，SQLite 保存相对引用、哈希、大小和状态，不将大文件作为数据库 BLOB。客户端备份使用 SQLite 在线备份机制取得一致快照，再与受管文件和清单打包、校验并加密。

### 7.3 服务端临时数据

- 上传 PDF、提取文本、OCR 结果、大模型原始响应和规范化中间结果；
- 任务租约、重试上下文和短期诊断信息。

每类临时数据都要定义保留时长、成功与失败清理路径、清理失败告警以及人工清理入口。日志不得写入完整 PDF 内容或无脱敏的大模型请求。

## 8. 接口草案

接口版本统一放在 `/api/v1`，管理接口使用独立的 `/admin/v1` 路径、权限和审计策略。候选接口如下：

| 方法与路径 | 用途 | 关键结果 |
|---|---|---|
| `POST /api/v1/auth/login` | 登录 | 短期访问令牌、刷新令牌、角色和订阅摘要 |
| `POST /api/v1/devices/activate` | 激活 Windows 安装 | 设备激活状态与占用名额 |
| `POST /api/v1/analysis-jobs` | 上传 PDF 并创建分析任务 | `202`、`jobId`、清理期限 |
| `GET /api/v1/analysis-jobs/{id}` | 查询任务 | 状态、进度阶段、错误码 |
| `GET /api/v1/analysis-jobs/{id}/result` | 取得候选结构化明细 | 结构化版本、字段、置信度、匹配候选 |
| `POST /api/v1/catalog/match` | 对已编辑字段重新匹配 | 唯一、歧义或未匹配结果 |
| `GET /api/v1/pricing-packages/latest` | 获取适用计价包 | 签名包、版本、有效期和兼容要求 |
| `GET /api/v1/subscription/status` | 检查授权 | 订阅、席位、设备、宽限状态 |
| `POST /api/v1/client-updates/check` | 按客户端版本、平台、架构、通道和设备上下文检查升级 | 更新状态、目标版本、可选或强制策略、兼容约束和发布说明摘要 |
| `POST /api/v1/client-updates/{releaseId}/download-authorizations` | 取得升级包短期下载授权 | 受控地址、过期时间、大小、哈希、发布者签名和算法标识 |
| `POST /api/v1/client-updates/{releaseId}/events` | 上报升级阶段结果 | 接收状态、事件 ID；事件不得包含生产商客户业务数据 |
| `/admin/v1/...` | 平台管理 | 目录、公式、价格源、授权、任务、审计与运维操作 |

管理 API 还需覆盖客户端版本草稿、制品元数据、发布通道、升级策略、最低支持版本、灰度或分批范围、暂停发布和升级审计。发布动作必须与普通配置写入区分权限并支持再次认证；只有完成哈希和发布者签名校验的制品才能从草稿进入可发布状态。

所有写接口使用请求 ID 或幂等键；错误响应包含稳定错误码、可展示信息和可追踪请求 ID。下载授权与账号、设备、版本和发布范围绑定且短期有效，不能把对象存储或静态目录变成匿名文件列表。管理接口不暴露远程 Shell、任意文件访问或直接 SQL。

## 9. 计价规则与追溯

### 9.1 规则表达

公式使用受白名单约束的声明式表达，允许算术、条件、查表和明确的单位转换，不允许任意脚本、动态库调用或文件/网络访问。每个公式版本必须声明：

- 适用品类和版本号；
- 所需输入、单位、精度、舍入规则；
- 平台参数、本地参数及取值边界；
- 中间结果与最终成本字段；
- 生效时间、失效时间和兼容的最低计价引擎版本；
- 内容哈希、服务端签名和替代关系。

### 9.2 目标毛利率

设单位成本为 `C`，目标毛利率为 `G`，不含税不含运费出厂价为 `P`：

```text
P = C / (1 - G)
实际毛利率 = (P - C) / P
```

客户端必须校验 `0 <= G < 1`；默认毛利率由生产商在本地设置，可逐项覆盖。税与运费是出厂价之外的独立项目，不能混入目标毛利率分母。若用户手工修改销售价，应显示反算后的实际毛利率，避免将“成本加价率”误当成“毛利率”。

### 9.3 计算凭证

每次计算至少保存：

- PDF 或输入数据哈希、结构化数据版本和确认状态摘要；
- 标准目录项及目录版本；
- 价格快照 ID、来源、采集时间、单位、币种、税和区域口径；
- 公式版本、计价引擎版本、计价包哈希和服务端签名；
- 平台参数、本地参数、目标毛利率及其默认或覆盖来源；
- 中间结果、舍入过程、最终结果和手工覆盖记录；
- 操作者、计算时间与客户端实例标识。

历史报价重放默认使用原凭证中的固定版本，不静默切换到最新行情或公式。

## 10. 价格数据源适配器

统一适配器输出候选字段包括：材料编码、原始名称、价格、币种、计量单位、税口径、区域、报价或采集时间、来源引用、原始内容哈希和质量标记。初始实现：

- `ManualPriceAdapter`：平台管理员人工录入，保留录入人与依据；
- `FileImportAdapter`：从约定模板导入并生成校验报告；
- `MockPriceAdapter`：只用于开发和测试，不得用于生产报价。

未来的 HTTP API 或网页适配器实现同一接口。每次导入先形成原始观测，再经归一化和审核生成不可变快照。价格过期阈值按材料或来源配置；过期、缺失或口径不匹配时禁止静默使用，客户端显示明确告警或停止自动计价。

## 11. 认证、订阅与平台管理

年度商业授权按“平台订阅主体 + 账号席位 + 已激活 Windows 客户端数量”建模。这里的订阅主体只承担计费与授权语义，不承载生产商的客户、询价或报价业务数据。访问令牌短期有效，敏感管理操作要求更强认证，可启用 MFA 和再次认证。订阅到期后至少阻止新 PDF 分析、最新价格和公式包下载及重新计价；是否提供只读和导出宽限期由商业规则另行决定。升级检查和下载授权必须结合账号与设备状态，但不能因业务订阅异常阻止安全修复的方式仍待授权策略确认。

平台管理员是服务运维和平台数据维护角色，不是生产商企业管理员。管理能力包括运行健康、分析任务和队列、模型与数据源非敏感配置、全局目录与公式、订阅账号与设备、审计、备份恢复，以及客户端版本、发布通道、升级策略、最低支持版本、制品签名元数据、发布范围和升级状态。版本发布、强制升级、最低支持版本变更及发布暂停属于高影响操作，必须再次认证、完整审计并支持职责分离的候选控制。密钥输入只写不回显，代码签名私钥不得存入业务数据库或普通应用配置，列表和日志只显示掩码。

普通生产商账号不能调用管理 API，只能取得其账号或设备已获授权的平台数据；不能更改服务端目录、公式、行情源或授权数据，也不能访问其他账号或设备的授权数据。企业业务数据和多租户业务域属于项目非目标，现有数据模型和接口不得预埋无实际语义的 `organizationId` 或租户隔离逻辑；若项目边界未来发生变化，必须通过新的产品与架构决定重新设计，不能把该变化视为当前方案的兼容扩展。

## 12. 备份与恢复候选方案

### 12.1 服务端

- 每日 `pg_dump` 逻辑备份业务数据库，并备份角色和全局对象；
- 备份加密后复制到服务器之外，按日、周、月设置保留策略；
- 定期执行自动完整性检查和人工恢复演练，记录恢复时间与结果；
- 当数据量和恢复目标要求提高时，引入 `pg_basebackup`、WAL 归档和时间点恢复；
- 临时 PDF 默认不进入长期数据库备份，避免与 TTL 清理策略冲突。
- 已发布升级包、哈希和签名元数据纳入发布资产备份与可恢复性设计；代码签名私钥单独按密钥管理制度备份，不进入普通数据库或文件备份包。

### 12.2 客户端

- 使用 SQLite 在线备份 API 生成一致数据库快照；
- 将数据库快照、受管 PDF/导出文件和清单打包，校验哈希并加密；
- 恢复前验证版本、完整性和可用空间，恢复后校验数据库与文件引用；
- 明确本地备份位置、保留数量和用户责任，避免只备份单个 `.db` 文件。

具体 RPO、RTO、保留天数和异地介质待生产部署需求确认。

## 13. 关键质量属性

| 属性 | 候选要求与设计响应 |
|---|---|
| 正确性 | 未确认明细不计价；目录歧义不猜测；固定版本公式、价格和舍入；测试向量校验 |
| 可追溯性 | 输入、人工修订、目录、行情、公式、参数、中间值和结果均带版本或哈希 |
| 安全性 | HTTPS、短期令牌、最小权限、管理面隔离、密钥不回显、审计、临时数据 TTL；升级包哈希与发布者签名双重校验，签名私钥隔离 |
| 隐私 | 生产商客户资料、询价、报价和本地计价参数只在客户端长期保存；服务端临时分析内容按 TTL 清理；日志脱敏 |
| 可用性 | 异步任务、可重试、幂等、超时和错误码；本地历史报价在服务暂不可用时仍可读取 |
| 可维护性 | Qt 客户端分层；Drogon API 与 Worker 共享领域库；价格源适配器和声明式公式版本化 |
| 可恢复性 | PostgreSQL 异机备份与恢复演练；SQLite 一致快照和文件清单；客户端升级失败可回滚或进入可操作的恢复路径 |
| 可观测性 | 请求 ID、任务阶段、升级阶段与结果、指标、结构化日志和平台审计，不记录敏感正文或生产商客户业务数据 |
| 容量与扩展 | 按客户端总量不超过 10,000 个设计索引和部署复杂度；API 与 Worker 可按实测扩容；客户端集中升级的下载峰值纳入验证，并发与峰值验收指标另行定义 |

客户端总量不超过 10,000 个是设计假设，不是并发承诺。峰值在线数、请求率、同时上传数、分析任务吞吐与队列长度、响应时间、识别准确率、清理时限、RPO 和 RTO 仍需在取得使用模式、样例及部署环境后量化。

## 14. 候选方案权衡

| 选择 | 采用理由 | 代价与控制 |
|---|---|---|
| 服务端 PDF 分析 | 集中管理 OCR/大模型能力和提示词，客户端更轻 | 上传涉及隐私和网络依赖；采用 HTTPS、最小留存、TTL 与日志脱敏 |
| 客户端本地计价 | 保护本地参数和报价数据，可离线重放，降低服务端业务数据责任 | 必须保证引擎一致和规则可信；使用签名版本包、测试向量和最低引擎版本 |
| PostgreSQL 服务端 + SQLite 客户端 | 分别适合并发平台数据与单机业务数据 | 形成双端备份责任；分别定义恢复流程，不做隐式双向同步 |
| Drogon + Nginx | Drogon 适合 C++ 业务 API，Nginx 承担生产入口通用能力 | 增加部署组件；开发环境可直连，生产以配置和监控降低复杂度 |
| 关系列 + JSON 扩展属性 | 兼顾标准查询与品类差异 | JSON 仍需模式和版本管理，禁止成为无约束字段仓库 |
| 不建设企业业务数据或多租户业务域 | 服务端不保存生产商客户、询价、报价和本地计价参数，减少隐私与隔离复杂度 | 这是明确的产品非目标；若边界改变，必须新增决定并重新设计数据模型和接口 |
| 按客户端总量不超过 10,000 个设计 | 满足当前规模假设，避免提前引入分片、多区域写入等复杂度 | 并发和峰值负载尚未确定；通过参数化负载测试验证并保留 API、Worker 横向扩展能力 |
| 服务端管理策略、客户端执行升级 | 集中控制版本、授权、灰度和审计，同时由客户端在本机完成可信校验与恢复 | 双端状态机和兼容性更复杂；接口幂等、签名信任根、阶段事件和恢复演练必须先验证 |
| 升级包本体不存 PostgreSQL | 避免大文件膨胀数据库和备份，便于独立扩展下载带宽 | 对象存储与受控静态入口尚未选定；两者都必须实施受控下载、防篡改和发布资产备份 |

## 15. 主要风险与验证计划

| 编号 | 风险或假设 | 验证实验 | 通过标准候选 | 所需输入 |
|---|---|---|---|---|
| V-01 | 非固定 PDF 的抽取质量未知 | 建立脱敏样例集，分别测试文本 PDF、扫描 PDF、复杂表格和异常页 | 关键字段准确率、漏项率和人工修订耗时达到与用户共同设定的阈值 | 真实脱敏 PDF 与正确答案 |
| V-02 | 大模型输出可能不稳定或越界 | 对固定样例重复运行，执行 JSON Schema、枚举、范围和提示注入测试 | 非法输出全部被拒绝或转人工；同样例关键字段稳定 | 模型候选与字段模型 |
| V-03 | 标准目录匹配可能误报 | 用已标注目录项测试唯一、歧义、未匹配和别名场景 | 不把歧义项自动判为唯一；误匹配率达到商定阈值 | 目录、别名和历史描述 |
| V-04 | 本地与服务端规则版本可能不兼容 | 使用签名包、最低引擎版本和黄金测试向量做兼容测试 | 篡改包被拒绝；不兼容版本被阻止；黄金结果一致 | 真实公式和舍入规则 |
| V-05 | 行情口径不同导致成本错误 | 对单位、币种、税、区域和时间做归一化与过期测试 | 口径不完整或过期时明确阻断或告警，不静默换算 | 行情样例或导入模板 |
| V-06 | 临时 PDF 未按承诺清理 | 覆盖成功、失败、超时、重试和进程中断场景的清理测试 | 到期文件和中间结果可证明清除，失败触发告警 | 确认 TTL 与部署存储 |
| V-07 | 订阅与设备计数可被绕过 | 测试并发激活、令牌撤销、过期、时钟偏差和离线场景 | 超额和到期策略一致，审计可追踪，不破坏历史只读数据 | 商业授权细则 |
| V-08 | 备份存在但无法恢复 | 在隔离环境执行 PostgreSQL 与客户端备份恢复演练 | 数据、文件引用和凭证抽样一致，达到约定 RPO/RTO | 部署规模和恢复目标 |
| V-09 | Nginx 与异步任务配置不当 | 测试大文件、慢上传、超时、限流、任务积压和 Worker 重启 | API 在上传及任务提交后返回任务 ID；平台操作幂等、任务可恢复；供应商重试计费语义另验；可观测 | 目标文件大小和并发量、供应商幂等或查询能力 |
| V-10 | 客户端总量已知但并发和峰值使用模式未知 | 以 10,000 个客户端及账号/设备授权记录为数据基线，按商定的在线、登录、上传、任务到达和集中升级下载曲线进行分级负载测试 | 授权查询、API、队列、Worker 和升级下载入口在约定响应时间、任务时限、带宽和错误率内运行，且扩容前后结果一致 | 峰值在线数、请求率、上传并发、任务到达率、升级并发、包大小、PDF 大小和模型限流 |
| V-11 | 客户端升级可能被篡改、错误投放或安装失败 | 覆盖哈希不符、签名无效或过期、错误平台或版本、授权过期、断点续传、断电或进程中止、磁盘不足、强制升级、灰度暂停和服务端不可用场景 | 未签名或被篡改制品不能安装；不兼容投放被阻止；重复请求和事件幂等；失败后原版本可用或进入明确恢复路径；发布与结果可审计 | 签名与信任根方案、安装器原型、发布策略、恢复目标、升级包大小与承载方式 |

## 16. 首轮原型技术契约与实施方案（0.3 候选补充）

本节将 0.2 的拆分细化为可交给实现人员的候选约定；不改变 D-001 至 D-008。当前交付是文档，下面的接口、状态、数据结构、测试和演示均尚未实现或运行。工作包是建议分解，不是向其他成员分配任务。`WORKSPACE.yaml` 仍为 `none`，源码、构建文件、样例文件和验证性代码须在声明及授权落实后进入产品仓库。

### 16.1 原型目标与两条验证路径

首轮先验证端到端交互和失败处理：登录及设备授权 → 上传文件 → 异步结果 → 明细编辑和人工确认 → 取得固定版本计价包 → 本地计算 → 报价保存、重开、导出；同时验证升级检查、制品验证和恢复的技术边界。报价类型在本地明确区分 `manufacturer_reply` 与 `sales_estimate`，不据此增加平台账号角色。销售估价输出必须标识“估价结果”。导出是生成本地文件，由用户自行发送；本轮不实现客户或销售的服务端协作、订单流转或自动发送。

| 路径 | 可使用的输入 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| 模拟流程演示 | 人工编写的候选分析响应、虚构目录、测试价格、测试公式和测试授权；用无真实业务内容的 PDF 作为上传载体 | 契约兼容、状态门禁、重复请求、计算可重复、保存重开和错误提示流程 | 非固定 PDF 识别质量、真实目录匹配率、真实成本或报价准确性、商业授权正确性 |
| 真实资料验证 | 脱敏真实 PDF、逐项人工答案、目录和别名、公式例算、价格口径及授权规则 | V-01 至 V-11 各自声明范围内的验证，达到另行约定的标准后形成证据 | 在样例以外自动推断全行业正确性，或把 10,000 个客户端总量当成并发承诺 |

模拟服务适配器由测试环境配置显式启用，不能在真实分析失败时自动降级为模拟成功。分析结果的 `analysisMode`、价格及规则包的 `dataMode`、报价凭证的 `evidenceMode` 必须保留 `demo` 标记；任一输入为 demo，整份报价和每页导出均显示“演示数据，不可用于真实报价”。原型中人工价格也须带来源、录入时间和口径；缺少实际业务验证时仍不得据此移除演示标记。

### 16.2 双端职责及调用边界

| 操作 | Windows 客户端 | Linux 服务端 |
|---|---|---|
| 文件导入 | 选择、复制到受管目录、校验可读性和哈希、上传原始字节；不解析、不渲染 PDF | 校验大小、类型和授权，临时存储并交给 Worker 分析；不信任文件名和 MIME 声明 |

### 16.3 通用协议和最小 API

以下是 `/api/v1` 与 `/admin/v1` 的候选规范，优先形成产品仓库中的 OpenAPI、JSON Schema 和固定测试样例。JSON 使用 UTF-8、camelCase 字段；时间采用带 `Z` 的 UTC 字符串；本地显示可转换时区。ID 是不含业务内容的不透明字符串。数量、金额、比例和可计算规格用十进制字符串及明确单位，禁止用二进制浮点 JSON number 作为计价依据；计数和页号可用整数。未知值用 `null` 并附问题，不能用零、空字符串或“默认规格”冒充识别结果。模型版本和包版本使用独立标识，不按字符串字典序判断客户端兼容性。

业务请求携带访问令牌及 `X-Request-Id`；服务端从已校验的令牌和设备凭据推导账号与设备，不信任请求体伪造的身份。写操作携带 `Idempotency-Key`。幂等域为已认证账号、设备、操作类型和键，绑定规范化参数摘要或文件摘要；同键同输入返回同一结果，同键不同输入返回 `409 IDEMPOTENCY_CONFLICT`。请求 ID 只用于追踪，不能代替幂等键。同文件的新主动分析可用新键，不能按哈希全局跨账号去重。幂等记录保留期、任务元数据保留期和临时内容期限分别配置；内容到期后不能由重试重建旧结果，须明确创建新任务。

创建操作声明 `operationExpiresAt`，服务端校验并以自己的时间固定接受窗口；同键窗口不得延长。幂等记录至少覆盖任务期限及接受的网络恢复窗口，窗口过期的旧创建操作返回 `410 OPERATION_EXPIRED`，即使幂等记录已清除也不得当作新操作受理。要重新分析，用户明确发起并生成新键和新窗口。ID/哈希和签名在正式 Schema 中规定格式；下面的示意 JSON 不是可直接提交的测试样例。

| 方法与路径 | 最小输入 | 结果及限制 |
|---|---|---|

成功 JSON 响应统一包含 `requestId`、`serverTime`、`schemaVersion` 和 `data`；错误响应采用下例。HTTP 状态与错误码均须检查，代理返回 HTML、响应截断或模式不合法统一显示协议错误，不当作空成功。

```json
{

  "serverTime": "2026-10-11T00:00:00Z",
  "schemaVersion": "1.0",
  "error": {
    "code": "RESULT_EXPIRED",
    "message": "分析结果已到期，请重新创建任务",
    "retryable": false,

  }

```

| 状态/错误 | 客户端动作 | 服务端约束 |
|---|---|---|
| `400/422 INVALID_REQUEST`、`FILE_HASH_MISMATCH`、`UNSUPPORTED_SCHEMA` | 修正输入，不能自动重试原参数 | 校验失败不投递任务，失败上传临时文件也清理 |
| `401 AUTH_EXPIRED`、`403 DEVICE_NOT_AUTHORIZED`、`SUBSCRIPTION_DENIED` | 访问令牌可刷新一次；其余显示允许动作，不伪造宽限 | 每次读写和下载授权都核对当前身份；商业策略未知项保留 |
| `404 RESOURCE_NOT_FOUND` | 不猜 ID、不改用其他设备 | 对不存在或无权查看的任务统一外部语义，避免泄漏授权关系 |
| `409 IDEMPOTENCY_CONFLICT`、`RESULT_NOT_READY`、`VERSION_CONFLICT` | 分别更换主动操作键、继续轮询、刷新并人工决定 | 不覆盖原输入、结果或发布状态 |
| `410 RESULT_EXPIRED/OPERATION_EXPIRED`、`413 FILE_TOO_LARGE`、`415 UNSUPPORTED_FILE` | 显示重新分析或更换文件提示 | 不以过期元数据返回采购明细；明确大小及支持类型配置 |
| `429 RATE_LIMITED`、`503 TEMPORARILY_UNAVAILABLE` | 按 Retry-After 或退避策略有限重试同幂等操作 | 不把请求拒绝写成分析成功，重试期间仍受绝对期限约束 |
| 网络超时、`502/504`、响应不可解析 | 创建任务结果未知时用同键重试确认，不能立即生成新键 | 提供可恢复的幂等结果；外部模型调用计费是否重复取决于供应商能力，不能承诺 exactly-once |

退避、轮询上限、上传限制和绝对任务期限由测试环境配置并记录；未经容量实验不在正文虚构生产数值。错误详情采用允许字段列表，不能回传堆栈、SQL、令牌、服务器路径或分析正文。

### 16.4 数据草案与版本关系

第 8.1 节是概念模型；0.3 已将其 quantity 示例同步为十进制字符串，实现候选按本节补充版本、来源及覆盖问题。最终字段字典仍需真实样例校准。文件来源用本地文件哈希及逻辑来源标记关联：例如页号、服务端提取行号和稳定 sourceRef，不增加 PDF 渲染、坐标高亮或客户端解析。缺失或无法识别内容生成 documentIssues/显式待处理记录；模型声称“无遗漏”不能替代人工答案比对。

```json
{
  "schemaVersion": "1.0",
  "resultVersion": "result-demo-001",
  "sourceFileHash": "sha256:example",
  "analysisMode": "demo",
  "catalogVersion": "catalog-demo-001",
  "documentIssues": [],
  "items": [{
    "lineId": "line-demo-001",
    "sourceRef": {"page": 1, "extractedRow": "row-demo-001"},
    "rawDescription": "虚构管件演示条目",
    "productType": "demo-fitting",
    "quantity": "2",
    "unit": "piece",
    "material": null,
    "extensions": {},
    "fieldIssues": [{"field": "material", "code": "MISSING_FIELD"}],
    "fieldConfidence": {},
    "catalogMatch": {"status": "unmatched", "catalogItemId": null, "candidateIds": []}
  }]
}
```

服务端不能将 `reviewStatus=confirmed` 当作模型可信输出；客户端首次导入强制置为 unreviewed/questionable。置信度只是校对线索，不是允许计价的门槛替代品；未知置信度可以缺省，不能编造精确概率。

| 存放位置 | 最小实体/键 | 不变量及生命周期 |
|---|---|---|
| PostgreSQL 长期平台表 | accountId、deviceActivationId、subscriptionId；catalogVersion；packageId/hash；releaseId/artifactId；平台审计 eventId | 唯一设备绑定、不可变发布版本；不引入 organizationId、客户表、报价表或本地参数表 |
| PostgreSQL 有期限任务表 | jobId、accountId/deviceId、status/stage、attempt、leaseGeneration/leaseUntil、临时对象 opaqueRef、expiresAt、cleanupStatus、幂等摘要 | 不存 PDF、提取文本或完整结构化明细；文件哈希、临时引用及诊断也按明确期限删除/脱敏，不把可识别业务的指纹长期留在审计 |
| 临时存储 | jobId + attempt 的 PDF、OCR、模型原响应、结果文件 | 不进入长期备份；每一层副本受清理清单约束，账号授权检查后才可读，外部模型保留策略另验 |
| SQLite 本地业务表 | documentId/fileHash；lineId + revision；confirmationRevision；quoteId + quoteVersion；receiptId；operationId | 业务内容仅本地；修订与确认对应精确版本，quoteVersion 和计算凭证一经保存不可原位改写，后续形成新版本 |
| 本地受管文件/缓存 | 相对 opaqueRef、hash、size、fileState；packageId/hash；exportId/version | 原始 PDF 可保存但不显示；文件路径防越界；历史凭证依赖的目录与计价包保留到其引用解除，不被“最新包”缓存清理覆盖 |

本地明细增加 `revision`、`reviewStatus`、`confirmedRevision`、`matchRevision`、`issueDisposition`、`confirmedBy/At`。计算输入哈希覆盖确认版本、目录项及版本、价格/公式包、参数、毛利率和舍入规则；售价覆盖及其原因在保存版本的完整内容哈希与凭证中另行固化，不冒充公式计算结果。凭证包含 engineVersion 和完整固定输入。本地匹配请求携带 revision 关联标记；返回旧 revision 时丢弃，不把后台结果覆盖新输入。包签名针对规范化 manifest 或固定原始字节定义，明确算法、keyId 和信任根；禁止验签后对内容重新拼接再使用。

本地报价还记录 quoteKind、inquiryReceivedAt（收到已分配询价）、replyConfirmedAt（生产商确认回价）、exportedAt 及时间来源；导出不等于发送，不能将 exportedAt 当作客户收到报价时间。未取得实际发送证据时只报告本地处理耗时；时钟回拨或来源不明须标记，不能作为效率改善实测。约 30 分钟继续是参考值。

内部模块也使用明确的输入输出，避免 UI 与 Worker 直接操作彼此存储：

| 边界/候选端口 | 输入 | 输出及禁止行为 |
|---|---|---|
| 分析适配器 | 受管临时 fileRef、jobId/attempt/generation、schemaVersion、catalogVersion、绝对期限 | CandidateResult 或稳定失败；MockAnalyzer 只返回固定 demo 样例，真实适配器通过受控 PDF/OCR/模型链路，不读取任意本机路径 |
| 行情适配器 | 来源版本、授权引用、人工/文件/API 观测 | 带单位/币种/税/区域/时间和质量标记的观测及校验报告；不直接生成销售价，不覆盖已发布快照 |
| 本地计价引擎 | 已确认固定版本明细、已验签包、精确十进制参数及毛利率 | 中间值、金额、舍入及凭证或结构化错误；无 UI、网络、文件执行或任意脚本能力 |
| 本地保存服务 | expectedRevision、operationId、quoteVersion 快照、文件引用 | 已提交版本或明确失败/待恢复状态；协调 SQLite 与文件 journal，不上传业务内容，不由 UI 绕过保存门禁 |

演示数据、解析器及规则引擎的具体 Schema、声明式公式操作符白名单、最大表达式深度/运算预算、十进制实现与舍入模式在 WP-01/WP-05 锁定；收到未知操作符、越界参数或不支持的 schema/engineVersion 必须拒绝，不能执行包内任意代码。

### 16.5 人工确认、计算和报价状态机

| 当前明细状态 | 事件及门禁 | 下一状态/影响 |
|---|---|---|
| 无记录 | 导入候选，模式合法 | unreviewed；存在缺字段、歧义或文档问题则 questionable |
| unreviewed/questionable/confirmed/unprocessable | 用户修改字段、目录选择或纳入范围 | modified，revision 递增；旧确认、匹配和该条计算失效；历史保存版本保留 |
| unreviewed/questionable/modified | 用户确认；必需字段完整、单位合法、唯一目录项/人工选择已记录、全部阻断问题有明确解决结果 | confirmed，confirmedRevision=revision；记录实际操作人，禁止模型代确认 |
| unreviewed/questionable/modified | 本轮无法处理并填写原因 | unprocessable；不进入自动计价，保留在整单统计及待人工处理清单 |
| confirmed | 当前目录/包不适配、或确认后修改输入 | 阻止计算；输入变化进入 modified，包变化要求重新计算，不覆盖旧凭证 |

批量确认必须逐条检查同一门禁，展示成功数量、失败条目和原因；不能“一键确认”吞掉歧义、缺字段或未覆盖页。documentIssues 与行级状态分别处理，行都 confirmed 不代表清单识别完整。客户端仅有结构化内容，发现漏项疑虑时支持手工补行并记录来源；原文件由用户在客户端之外核对，真实漏项质量依赖 V-01，不新增内嵌 PDF 查看器。

报价草案状态为 `editing → ready_to_calculate → calculated → saved`。进入 ready_to_calculate 前检查所有纳入条目 confirmed、目录和参数合法、包验签及兼容、授权允许本操作；计算完成后记录输入哈希。任何编辑使当前计算回到 editing 并失效；保存前再次比对哈希和 revision，过时结果不能保存为当前有效报价。人工售价覆盖独立记录价格、原因、操作人和反算毛利率；`P = 0` 时反算无定义，`P < 0` 超出原型自动计价范围，必须拒绝或转有原因的人工处理，不能输出伪造毛利率。

未处理条目不得悄悄删除以使整单通过。首轮允许保存包含这些条目的工作草案，但不能生成声称“完整报价”的正式输出。手工报价或排除条目的业务准入未确认前仅演示草案处理；草案导出明确显示未报价清单和“未完成，不可作为正式报价”。完整流程演示先使用全部可确认的虚构数据，另用异常样例演示阻断。生产商回价还须有本地操作人的明确最终确认；销售估价不得借同一按钮变成生产商正式确认价。

### 16.6 异步任务状态、重试与清理

服务端状态是 `queued → running → succeeded/failed`，可增加 `retry_wait`、`cancel_requested`、`cancelled`、`expired`。running 的 stage 单独为 extracting、ocr、structuring、matching，不按阶段数伪造耗时百分比。

| 事件 | 转换及处理 |
|---|---|
| 上传与任务提交完成 | queued；临时文件失败不得留下可执行任务，数据库提交失败的孤立文件进入清理清单 |
| Worker 领取 | queued/retry_wait → running；事务领取并写租约和递增 generation，外部调用期间不持有数据库行锁 |
| 可重试故障 | running → retry_wait；受 attempt 上限、供应商限流和绝对 expiresAt 限制；输入不合法、模式不合法不盲重试 |
| 成功 | 仅当前 generation、租约有效、仍为 running 且未到期的 Worker 可条件提交不可变结果；结果文件完整落地且元信息提交后才 succeeded；取消或新租约已提交时旧成功写入必须失败并清理孤立结果 |
| 永久错误/次数用尽 | failed，稳定错误码；绝不返回虚构空结果或测试结果作为成功 |
| 用户取消 | queued/retry_wait 可直接 cancelled；running → cancel_requested → cancelled，协作取消或丢弃迟到结果；完成已提交时返回终态冲突 |
| Worker 崩溃/租约失效 | 可在期限内重新领取并递增 generation；旧 Worker 不能回写；过期则 expired，不自动延长内容保留期限 |
| 绝对期限到达 | 未领取任务停止执行；任何结果接口返回到期语义，进行中的结果不能再发布；清理所有任务内容副本 |

候选队列先用 PostgreSQL 任务表及租约，多个 Worker 使用短事务领取；无需先引入 Redis 或专用消息中间件。`FOR UPDATE SKIP LOCKED` 可用于队列消费，不能据此宣称一般查询一致性；依据见 [PostgreSQL SELECT 官方文档](https://www.postgresql.org/docs/current/sql-select.html)。任务按至少一次执行设计，以 generation 和结果提交门禁保证平台只发布一个有效结果；外部模型请求是否能幂等须另验，重试不承诺供应商只收一次费用。

客户端等待状态单独为 uploading、waiting、downloaded、interrupted、abandoned。网络断开只表示 interrupted，不表示任务 failed；保存 jobId 和创建幂等键后可恢复查询。只有候选结果已成功提交到本地 SQLite 才显示 downloaded；重复获取同一 resultVersion 不重复插入明细。迟到结果不自动替换用户正在修改或已经保存的文档，重新分析产生另一个本地候选版本并由用户选择。

cleanupStatus 与业务终态分开为 pending/cleaning/cleaned/cleanup_failed。清理覆盖 API 上传目录、Worker 文件、OCR/模型中间件、结果存储以及代理缓存/临时文件；仅删 PostgreSQL 引用不算清理成功。Nginx 上传缓冲和失败重试需纳入审查，[官方 proxy_request_buffering 文档](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_request_buffering)说明缓冲开启时会先读取整个请求体。分析响应不缓存，代理错误日志、访问日志、应用日志和监控标签禁止记录正文或原始文件名；到期删除失败立即不可读取、告警并重复清理，不把失败写成 cleaned。TTL 数值及清理失败恢复目标仍待用户和部署需求确认。

### 16.7 本地保存、追溯及导出语义

原始 PDF 导入先在受管目录以临时文件写入、校验 hash/size，再以不可变文件引用登记 SQLite；崩溃后的未引用文件扫描为孤立文件，缺失文件的文档显示 unavailable，不假装可重新分析。文件与数据库不是一个事务，需 operation journal 和启动恢复协调，不靠两次普通写入假设原子性。

报价保存以本地 `operationId` 去重，事务中同时提交 quoteVersion、所有行、凭证、确认摘要、未处理条目和审计；成功以 SQLite 提交成功为准。失败必须回滚或确认事务状态，显示未保存并保留内存草案。建议单写入服务处理 SQLite，有限 busy 重试，不能在 UI 线程长时间等待。SQLite 的 COMMIT 可能返回 SQLITE_BUSY 且事务仍在进行，见 [SQLite 事务文档](https://www.sqlite.org/lang_transaction.html)；必须区分提交失败、明确回滚及结果未知，不提前显示“已保存”。

历史报价重开默认只读固定版本；修订生成新 quoteVersion。历史重放使用原目录快照、签名包、参数、确认版本、engineVersion 与舍入规则；缺失依赖明确显示“不可重放”，不能静默取最新版本。服务端离线不影响读取已经存在的本地历史；新计算和历史导出的商业准入仍由第 11 节待确认策略决定，不在原型中暗自授予永久离线许可。

原包有效期到期不改变已保存报价的历史事实；原型可在“历史重放”只读模式解释旧凭证并标记原计算时间，不能将旧包作为新报价有效输入。签名已被撤销或依赖完整性不符时提示历史可信性问题，不静默忽略验签。断电后的文件与 SQLite 持久性必须在选定文件系统、journal/synchronous 配置和安装环境实测，文件原子替换本身不等于整机断电恢复保证。

首轮推荐只先实现本地 CSV 表格导出和可重放凭证归档，输出 PDF/Excel 排版作为后续候选，须产品确认具体格式。CSV 含报价类型、报价版本、目录/价格/公式版本、生成时间、币种/单位/税/运费口径，以及逐行状态；缺失的税运费不得填零冒充已确认。销售估价、演示或未完成草案在首行及文件内显著标记；对外估价必备有效期/风险提示尚未确认，真实使用继续等待规则补齐。导出不能被记为已经发送给客户或销售。

导出 operation 状态为 `pending → writing → written → completed`，错误为 failed；状态与报价 saved 分离。先固定 quoteVersion 和模板版本，在目标同目录临时写入、flush/校验后提交文件，再写导出记录（hash/size/quoteVersion/模板版本/时间）。Qt 候选使用默认禁止 directWriteFallback 的 QSaveFile，成功 commit 后才认为文件写成；它不能让文件写入与 SQLite 共同原子，参见 [Qt QSaveFile 官方文档](https://doc.qt.io/qt-6/qsavefile.html)。写入中断保留原目标文件；文件已提交而数据库记录失败时由 journal 和 hash 在重启后补记或提示结果未知，不重复覆盖其他文件。目标已存在时由用户明确选择覆盖或另存。

CSV 对可能被表格软件解释为公式的用户文本作安全编码，并正确处理逗号、换行和引号；合法数值与文本按列类型区分，不改变计价凭证中的原始十进制值。归档包含完整输入快照、包原字节及签名、版本和哈希清单；不能只归档可过期下载 URL。导出路径仅用户选择或受管路径，不接收服务端提供的任意本机路径。

### 16.8 安全升级原型的接口和依赖

首轮推荐优先评估全量签名安装包及独立升级执行器，先验证沙箱中的安装/恢复；这只是候选，安装器类型、自动安装时机、包承载和恢复保留数仍待确认。升级业务数据不上传服务端。访问令牌与签名信任不是同一机制，不能凭“登录成功”认定下载包可信。

升级 manifest 至少覆盖 releaseId、artifactId、目标版本、platform/architecture、允许来源版本、minClientVersion/minEngineVersion、DB schema 兼容范围、大小、哈希、签名算法/keyId、通道、policyVersion 与有效期。manifest 与包都须按已锁定信任根验证；恶意 metadata 指向有效但不适用的旧包也须拒绝。Windows 安装包可评估 Authenticode/WinVerifyTrust，返回值只有零才是验证成功；还须绑定本项目允许的发布者，不能接受任意受信任发布者，依据见 [Microsoft WinVerifyTrust 文档](https://learn.microsoft.com/en-us/windows/win32/api/wintrust/nf-wintrust-winverifytrust)。撤销检查、离线验签、信任根轮换与受控降级的具体策略须在 V-11 定稿，测试密钥不能进入生产信任列表。

客户端候选状态：`idle → checking → offered/required → downloading → verifying → staged → installing → verifying_install → completed`；任一失败进入 failed，安装已变更时进入 restoring/recovery_required。重复检查不能触发重复安装。断点续传绑定 artifactId/hash/size，目标变化丢弃旧片段；短期 URL 过期可重新取授权，不降低校验。下载、校验和事件上报在后台运行，安装前须保存业务草案、停止写数据库并确认无进行中计算。

安装前做 SQLite 一致快照与受管文件清单，检查磁盘空间、运行进程、平台及权限。版本切换和数据库迁移必须用恢复 journal 记录；迁移失败不得启动旧程序读取不兼容的新数据库。只有已验证可逆迁移或兼容性时才支持自动回滚；否则保留备份并进入明确恢复路径，禁止声称保留旧 EXE 就能恢复。演示环境验证升级及恢复不等于在生产系统执行升级。

服务端发布状态候选为 draft → validated → published，可暂停后续投放；签名/哈希/兼容性不符不能 validated。已发布的包内容不可修改，撤回只改变投放状态并留审计；客户端安装前重新取得策略，暂停对已安装版本的处理仍须策略决定。最低支持版本限制不得破坏本地业务数据，安全修复如何允许过期订阅设备下载仍是授权规则缺口。升级 eventId 幂等保存，本地待上报事件可重试，上报失败不阻止恢复。升级包本体由受控文件入口或对象存储承载，暂未选定。

### 16.10 可演示脚本与证据

演示环境应固定客户端/服务端提交、编译工具、目录/包版本、测试授权与 TTL 配置。推荐使用三个虚构条目：一个完整、一个目录歧义、一个缺数量，并准备字段修正后的已知测试成本。仅作黄金测试向量示例：单位成本 80.00、目标毛利率 0.20，按本测试包两位小数得到出厂价 100.00；真实成本组成、舍入及税费仍未确认。演示标记一直保留。

1. 测试账号登录并激活设备；用普通角色调用管理发布接口应被拒绝，展示测试授权状态而非虚构正式套餐。
2. 上传合成 PDF，超时后以同幂等键恢复同一任务；UI 显示异步阶段，接收标为 demo 的固定结果，原始 PDF 不显示。
3. 尝试直接计价应被阻止；修正歧义和缺字段，模拟迟到 match 响应不得覆盖新 revision；再人工确认全部条目。
4. 取得测试计价包并验证，篡改包及不兼容引擎分别失败；正确包固定输入计算并核对黄金向量、毛利率与独立税运费栏位。
5. 修改 confirmed 字段使旧计算失效；重新确认及计算后保存报价版本。模拟磁盘满或事务失败不能显示保存成功；重启读取原成功版本。
6. 分别导出演示生产商回价和“估价结果”，核对演示/估价标记、输入追溯及无发送记录；含 unprocessable 条目时只能展示未完成草案，不能输出完整报价。
7. 断开网络读取历史；丢失原依赖时显示不可重放。注入导出文件提交后 DB 失败，重启核对 journal 和文件 hash，不产生假成功或损坏原文件。
8. 另建任务演示取消、Worker 重启、租约失效和结果到期；保留清理清单及实际文件检查，不能只凭 API 显示 cleaned。
9. 使用两个测试安装版本演示升级策略、短期授权、篡改拒绝、发布暂停与失败恢复；安装/DB 迁移失败后验证旧数据完整。该步骤须隔离环境和明确安装授权，不在用户工作电脑自动执行。

每一步留存输入 ID/版本、预期状态、实测结果及失败差异；截图和日志不包含真实客户内容、凭据或私钥。两类报价展示和 80.00 测试向量只能证明流程/算术约定，不能证明真实行业报价规则。
