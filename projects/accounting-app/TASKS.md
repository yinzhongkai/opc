# 任务

以下是初始示例任务，均未启动。每项任务由具体成员 ID 负责；完成条件需结合实际项目澄清后确认。

- [ ] `ACC-000` 建立研发里程碑与依赖计划；负责人：`project-manager-01`
  - 完成条件：形成覆盖需求、设计、实现、联调和验证的初始计划并列出待确认项。

- [ ] `ACC-001` 澄清产品需求与验收标准；负责人：`product-manager-01`
  - 完成条件：目标用户、核心流程、非目标与验收条件得到确认。

- [ ] `ACC-002` 设计架构、数据模型与接口契约；负责人：`architect-01`；依赖：`ACC-001`
  - 完成条件：前后端可据同一契约实现，关键技术选择和未知项有记录。

- [ ] `ACC-003` 实现前端页面与前端单元测试；负责人：`frontend-dev-01`；依赖：`ACC-001`、`ACC-002`
  - 完成条件：界面覆盖约定行为与异常状态，单元测试结果和实现说明可查。

- [ ] `ACC-004` 实现后端接口、存储与后端单元测试；负责人：`backend-dev-01`；依赖：`ACC-001`、`ACC-002`
  - 完成条件：接口行为符合契约，数据规则有验证记录。

- [ ] `ACC-005` 完成前后端联调与集成运行；负责人：`backend-dev-01`；依赖：`ACC-003`、`ACC-004`
  - 完成条件：与 frontend-dev-01 共同验证主路径，提交可复现运行说明及接口差异处理记录。

- [ ] `ACC-006` 执行验收测试并提交缺陷与结果；负责人：`tester-01`；依赖：`ACC-001`、`ACC-005`
  - 完成条件：验收条件有对应结果，未通过和未验证部分被明确标出。

- [ ] `ACC-007` 独立评审交付物与验证证据；负责人：`reviewer-01`；依赖：`ACC-006`
  - 完成条件：报告提供有依据的 pass、revise 或 blocked 结论。

成员直接在自己负责的任务下更新状态、进展、产物链接和阻塞；需要独立验收的任务区分自报完成与已验收。项目经理维护任务增删、负责人、依赖、优先级、范围和完成条件，并汇总项目状态。普通进展无需重复写交接；需要其他成员行动或接手时再记录 HANDOFFS.md。

发现问题后由对应成员修订并复测，不将依赖任务完成等同于后续验收通过。负责人停用时，保留已完成任务历史和未完成工作，注明待重新分配；项目经理随后安排接收者并记录接收确认。任务转交不阻碍成员直接停用，停用也不会自动完成任务。
